# X43 — ΔΙΆΣΤΗΜΑ DIASTEMA: the interval over a shape, not the value

## The hole, measured

A `find -printf`, a `stat`, an `ls --full-iso`, a `tar -tv`, any log with a clock in it, any CSV with
a date and a price — the widest token on most lines is a **number**, and the number is almost the
same as the line before it:

```
2026-09-30T07:59:52.6403938810       7193 node_modules/@babel/code-frame/lib/index.js
2026-09-30T07:59:52.6923941430        132 node_modules/@babel/compat-data/corejs2-built-ins.js
```

Twenty-four digits and six separators per line. The residual census on the real captured
`bench/holdout-ops/find-listing.txt` (`bench/x43/residual.ts`) shows the frontier wire is **40 %
digit tokens**: after OURA has done everything it knows how to do, the numbers are what is left.

They are also nearly free in principle, and that part was measured before anything was built: the
same column in place costs **2 159** o200k tokens; carried as signed **decimal** intervals it costs
**505** — 4.3× less (`bench/x43/enc.ts`). The same stream in base-36 costs 626 and in base-62 563:
BPE packs digit runs densely and letters sparsely, so the "obvious" wide alphabet *loses*. The
envelope is decimal because it was measured, not because it is conventional.

## What was built

`src/lib/omega/diastema.ts`, registry key `diastema` (206 entries, family `exact`), gate-checked.

| export | role |
|---|---|
| `diastemaPlan(text, enc)` | over token ordinals 0…7, group shaped tokens by digit mask, chain BigInts, score every candidate on **rendered tokens**, keep the best-paying column; `null` when no column pays |
| `diastemaWire(plan, text)` | one self-describing header line + the transform; the header delimiter is chosen from characters absent from the source |
| `diastemaDecode(wire)` | the header is the program; total on encoder output, identity on anything that fails to parse |
| `diastemaEncode(text, enc)` | G1 → G2 → G3 → G4; on any failure it returns the parent's own wire and a note with both numbers |
| `diastemaTokens/Mask/Value/Render/Runs/Pattern` | the shape algebra |

Wire:

```
Δ <d> <mask> <d> <j> <d> <eol> <d> <pattern>        one line, the contract
<body: every source line, in order, the j-th space-token of a RECORD line
       replaced by its signed decimal interval>
```

- `<mask>` — every digit run replaced by `#` of the same length, literals verbatim:
  `####-##-##T##:##:##.##########`. Sent **once**.
- `<j>` — the 0-based ordinal of the shaped token among the line's non-space runs.
- `<eol>` — `s` = LF, `S` = CRLF. CRLF is settled once, globally; **mixed** EOLs are refused, not
  normalised.
- `<pattern>` — RLE of the line pattern, `R120L1` = 120 interval lines then 1 literal. A marker
  glyph would cost one token per line (that is the shape of HORA); a run costs six characters once.

Decoding is calendar-free and exact by construction: keep a running BigInt, add the interval, write
the decimal expansion **left-padded with `0` to the mask's total digit count**, then fill the `#`
runs left to right. Ten-digit nanosecond fractions, four-digit years, one-digit counters and
nineteen-digit epoch stamps are the same case. A wide alphabet would have been a rounding hazard;
decimal digits are not.

## The four gates

| gate | test | on failure |
|---|---|---|
| G1 | `diastemaDecode(wire) === text`, **before** any measurement | identity arm |
| G2 | the parent (OURA) round-trips the transform through the stack's own decoder | identity arm |
| G3 | `\|parent(transform)\| + \|clause\| < \|parent(source)\|` on rendered o200k tokens | identity arm + note with both numbers |
| G4 | the emitted wire decodes to the source through the reader's path | identity arm |

`proxyGain` (the column's own token cost, `colTok - dTok - |mask| - 4`) is a cheap predictor used
only to *pick* a plan and to skip the parent encode when nothing can pay. It is never the decision.

## Measurements — the real gate, same clock

`bench/x43/verify.ts`: one process, one clock, contract and clause in band. `parent` is OURA, the
direct parent the codec gates against; `chain` is the **shipped frontier's** one-chat total
(`apographeEncode`), which is the number a gain has to beat.

| `holdout-x40/prices.csv` (synthetic holdout, 30 rows) | 582 | 226 | 209 | **133** | **−76 (−36.4 %)** | **yes** | EXACT |
| `holdout-tab/aapl-2014.csv` (real market data, 163 rows) | 3 108 | 1 450 | 1 151 | 1 336 | **+185** | yes, but **loses** | EXACT |
| `holdout-x40/metrics.tsv` (synthetic holdout) | 811 | 237 | 237 | 237 | 0 | no — wire+clause 247 ≥ 237 | EXACT |

| `holdout-ops/openstack-loghub-26.log` (real, 26 lines) | 4 028 | 898 | 898 | 898 | 0 | no — wire+clause 982 ≥ 898 | EXACT |

Gate lane time on 2 cores: 107 s parent + 96 s DIASTEMA on the 4 k-token listing. The log lane is the
outlier: 616 s for the parent and 1 265 s for the DIASTEMA arm (three parent encodes of a 4 k-token
log inside one process), which is the honest cost of measuring that lane at all.

**The aapl row is the boundary, and it is reported as a loss.** APOGRAPHE already reads that CSV's
comma grid and models the date column, so the shipped chain reaches 1 151 while DIASTEMA's interval
codec reaches 1 336. Firing is not winning: the codec fired on its own parent and lost to the chain,
and both numbers are here.

**And the cheap predictor is wrong where it matters, which is why it is never the decision.** On the
OpenStack log the column-level `proxyGain` is **+271 in favour** (the clock column really is cheaper
as intervals), yet the measured message is **982 against a 898-token parent**: the parent already
models the repeated request-line text, and replacing a clock in the middle of the line breaks the
alignments it was exploiting. The gate caught it; a proxy-based codec would have shipped a
regression.

**Refused with a reason, not silently** (no column of ≥6 shaped values with ≥6 digits sharing one
mask): `git-numstat`, `git-log-stat`, `git-log-fuller`, `node-stacktraces`, `ps-real`, `ls-l-real`,
`du-real`, `tsc-diag`, `node-versions`. Those refusals are correct: `git numstat` carries three
independent counters per line, none of them shaped; `ls -l` and `ps` carry sizes and PIDs in
different columns on different lines.

`apt-real` plans (10 rows, `##.#.#-##+deb##u#`, column gain 60 tokens) and was **not gated**: a single
parent encode of its transform took **289 s** on this box, and a 60-token column cannot pay a
46-token clause after that. It is reported as unmeasured, not as a win or a refusal.

One measured consequence of widening the mask grammar: on the OpenStack log the chosen plan changed
from the clock mask (`##:##:##.######`) to the wider hex-and-letters mask
(`###d#a##c#da###fbd##cc#caa#b##d#`), because that mask covers more lines at the same ordinal. Both
are refused at the gate; the point is that the grammar change is visible in the plan, not only in the
red team.

## Red team — `bench/x43/rt.ts`, 50/50

- **A1–A18 — refusals.** Every header field is attacked: missing/extra delimiter, an empty mask, a
  mask with no `#`, a mask over 64 characters, an ordinal out of range, a non-integer interval, an
  eol flag other than `s`/`S`, a pattern letter that is not R/L, a pattern that does not match the
  body length, an interval that would overflow the mask. Each returns the input **unchanged**.
- **B1–B10 — boundaries.** 30-line listing; CRLF; no final newline; negative steps; a listing one
  row below the minimum; mixed EOLs (refused); a blank line; a mask that ends in a literal
  (`id-###.bak`); strictly decreasing values.
- **C1–C6 — adversarial shapes.** Source that itself starts with `Δ`; a source containing every
  candidate delimiter; a body line shaped like a header; a column whose values widen mid-run; a
  delta of 30 digits; a shaped token at the very end of a line.
- **D2 — fuzz.** 200 seeded random listings, 199 produced a plan, **0 bad round trips**.
- **E1–E14 — algebra.** Token offsets, mask, value, render padding / overflow / negative / interior
  zeros, pattern round trip, the clause's ordinal wording, `proxyGain > 0`, decode idempotence, and
  the clause itself **under 50 tokens**.

Two real bugs the red team found and the fix for each:

1. **CRLF is a token.** On `openstack-loghub-26.log` the ordinal pointed at the `\r` instead of the
   value, and the chain diverged. Fixed by settling EOL once, globally, and re-adding exactly one
   `\r\n`; mixed EOLs now refuse.
2. **A mask may start or end with a literal.** The first grammar (`^#+([^#]+#+)*$`) refused
   `id-###.bak` and `out-########`. The rule is now: any mask containing at least one `#`, length
   ≤ 64. Twenty-eight of the fifty cases exist to keep that widened grammar honest.

The clause length is a **measured** quantity, not a guessed one: five phrasings of the same rule
were tokenised (`bench/x43/cl.ts`, `cl2.ts`, `cl3.ts`) and differed by up to 2× — 99, 78, 67, 60,
45 — with no change in meaning. The shipped clause is 46 o200k tokens:

```
Δ: mask = value shape with # per digit. R: add the first space-token (signed int) to a sum
from 0 and print it into the #s, zero-padded; L: verbatim. Print.
```

(for `j ≠ 0` it reads `space-token <j> (0-based)`, which costs more and is only paid when the shaped
token is not the leading one).

## The frontier did not move

The 31-lane repeat (`bench/x40/frontier.ts`) was re-run on this build: **29/31 lanes bit-identical,
3 223 s wall**. The two differences are the two X40 and X42 already reported and could not reproduce,
both in the **parent's** number and neither on an X43 lane: `npm-ls.txt` 901 → 904 and
`markdown-table.md` 182 → 176, with `oura.ts` unchanged. X43 adds one module and one registry entry;
`git diff --stat` over `src/` is the new file plus 11 lines of `registry.ts`.

Registry check: `bench/x43/reg.ts` reaches the codec exactly the way a reader does — 206 entries,
`oneChat` 1 140 on `find-listing`, `decoded === source`.

## Honest ancestry

HORA (`hora.ts`, X13) is the ancestor and is cited as such. HORA replaces a
`YYYY-MM-DD HH:MM:SS.mmm` that falls on the *same date* as its predecessor with a millisecond
offset, and its own boundary list states what it cannot do: date changes stay literal, 6- and
9-digit fractions are unmatched, timezone suffixes are untouched, and it requires the DAEDALUS
parent.

DIASTEMA is that idea generalised until the format stops mattering: any mask, any number of digit
runs, any widths, any separators, any position in the line, any digit count (BigInt, not millisecond
integers), no same-date or magnitude restriction, no field-validity test — the value is never
interpreted, only differenced — plus the run-length pattern instead of a per-line marker, a decimal
envelope chosen by measurement, and gating against the **current** parent.

Adjacent and **not** substituted: arithmetic-progression generation (METRON `lin`, KANNABOS `t:`)
needs a law that holds; here the interval only has to be cheaper than the value. Run-length coding
of equal values (KANNABOS `r`) does not apply — every value is distinct. A dictionary costs an index
letter per line. Timeline sorting is not performed: source order is preserved exactly. Nothing is
bucketed: every digit is recovered.

## Time / CPU

Planning is one pass per candidate ordinal (≤ 8) with BigInt chaining — milliseconds on every lane
in this corpus. The cost is the gate, exactly as for every codec in this stack: one parent encode of
the source plus one of the transform (107 s + 96 s on the 4 k-token listing, 2 cores, deterministic
tokenizer).

## What is still open

`ls-full-iso` (28 rows, 6-digit microseconds) does not fit under its parent: the interval stream
costs 447 against a 367-token parent. `metrics.tsv` is 247 against 237 — the mask spans five
columns, so the header eats what the intervals save. Both are reported as refusals **with both
numbers**, which is the behaviour the gate is supposed to have; neither is hidden.
