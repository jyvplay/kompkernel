# X137 A–J review

## A. Model, access and resources

Finite valid UTF-8 text; full one-chat message charged with installed o200k_base.
Decoder receives message only, no original source, hidden dictionary, skills.md,
external tool or extra instruction. Encoder may inspect source and tokenize.
Verifier compares original bytes afterward. Program inverse and native model
response are distinct decoders and must not be conflated. Same deterministic
TAGSTACK flags as X136, recorded in harnesses. Source-size ceiling 50,000 UTF-16
units, no CR/tilde; transformed words printable ASCII, single internal spaces.
Other lines remain literal. No universal Unicode-layout support claimed.

## B. Quantifiers and boundaries

Desired: one fixed encoder/decoder for every source in a predeclared corpus,
exact byte equality, token non-regression on every lane, >10-token improvement
on real everyday material, plus honest whole-stack speed gain and native
single-message behavior. One winning Node source proves only an existential
compression example. It does not quantify over all prose, all LLMs or all inputs.
By elementary finite counting, an injective code cannot shorten every finite
string over the same alphabet. That does not forbid finite-corpus gains.

## C. H+, H− and H∂ evidence thresholds

H+: hanging-layout prediction can pay its complete contract on some actual
source. Supported by 846→831 and independent byte reconstruction. H−: no such
candidate within the tested bounded family wins on specified sources. Finite
losses on Git/Python/LLM-answer/code/JSON support only that local negative, not
impossibility. H∂: native behavior, generalization, all-codec novelty and speed
remain boundary questions. Native evidence threshold is a retained blind model
response; speed threshold is controlled full-cost A/B; novelty threshold is
semantic comparison, not a new filename. None is waived to satisfy the request.

Marked and overflow KREMA are two invocation policies of the same layout
mechanism, not counted as independent approaches. Fast parent is a search/quality
trade-off, not a second new representation.

## E. Candidate adversaries and repaired gates

First marked design lost because each run paid a marker. Overflow removes those
markers, but must escape untouched long lines; omitting escapes changes source.
Unit test intentionally strips one and detects corruption. Width/margin bounds,
missing gaps, stray/repeated markers, CR, unsupported Unicode words, final LF
multiplicity and real corpus inverses are exercised. Strict admission compares
source reconstruction, not just candidate's token count. Planning verifies
its own inverse; independent Python reader reads parameters from emitted header.
Remaining attack: human/native interpretation of terse recursive macro syntax,
not settled by either program. Another: runtime unfairness from cheaper parent
quality loss. Separate fast-arm receipts expose it rather than calling it Pareto.

mode, resource boundary**. A change in any coordinate blocks promotion.

2. Bytes instead of BPE tokens → installed reference tokenizer.
3. Encoder `decoded` field instead of emitted-wire proof → independent reader.
