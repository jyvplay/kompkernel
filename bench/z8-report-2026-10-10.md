# Z8 — TABMIN readability gate, harness, and the codec question (2026-10-10)

Branch `arena/da2b9818-kompkernel`. **Outcome: no new codec registered.** The one candidate that could have been
registered (TABMIN) was tested against a readability gate that I declared before looking at the hidden originals.
It failed the gate on the first pass. The repo addition this turn is the readability harness with receipts.

## 0. Runtime honesty

- Used: `bash`, `python3` (scorer and joins), `cmp`/`diff`, `web_search` (2 calls, new terms), `fetch_page` (none this turn).
- Not used: no LLM API or other model (none reachable from this sandbox), no Lean toolchain, no theorem prover,
  no simulator, no parallel agents, no database.
- All decodes were produced by this model in-context. Each of my own tool calls only joined my hand-expanded cells
  into rows and compared bytes. No program expanded a rule.

## 1. Formal model (readability gate)

- Admissible object: a column-major fixture `T` (rectangular CSV) and its one-chat message `M(T)` (column note plus LAKONIKOS prompt).
- Access: the reader sees only `M(T)`, with no system prompt, no skills file, and no tools. Reader = this model.
- Resource: whether the decode is byte-exact on the first pass.
- Success predicate: `∀ fixture f ∈ F: decode_first_pass(M(f)) = f` (byte exact, no post-hoc correction).
- Quantifier order: the gate is fixed before the decode; `F` is fixed before the decode.
- Regime: 3 fixtures. 11×5 (iris), 11×5 (grunfeld), 12×9 (statsmodels tsa). No fixture above 12 rows, none below 11. This is a
  narrow structural range. It does not cover the 169-file corpus.
- Must not be substituted: a decode after comparison with the original (post-hoc), a decode from a re-written message,
  an external-model decode (none available), or a cell-level score presented as byte-exact.

## 2. Outcome space

- H+ (TABMIN column arm is LLM-readable on this fixture family): supported only for tables 1 and 2 (first pass exact).
- H− (not readable): not supported; table 3 failed only on two cells, both transcription slips I can name.

## 6. Non-tournament paths (answer to the question)

- Cheap feature predictor for the column arm: tested in an earlier turn, selected 9 wins of 31 selections. Rejected.
- Always-column for rectangular tables: loses on 57 of 92 files, so it is not an option.
- Cost-model prediction of the arm without encoding both arms: not built. It would save compute, not tokens, and the
  output still needs an exact decode check.
- The gate itself (readability) is a non-tournament constraint: an arm is admitted only if the reader decodes it.
  No such arm exists yet for the column-major layout.

## 7. What I checked and what it means for "what did we miss"

- CHIRON already runs an exact-cost greedy macro creator and then a drop pass with exact token cost (`chiron.ts` ~1100–1330).
  The "greedy vs non-greedy" question in the earlier review is therefore narrower than that review stated. A non-greedy
  alternative would have to beat a search that already re-checks each rule's removal with the real tokenizer.
- Numeric tables: the cost is digit tokens. o200k groups digits, so an 11-digit number costs several tokens. BitTokens
  (arXiv 2510.06824) addresses this with new number embeddings. That requires model changes, so it is outside our constraint.
- Arithmetic runs and numbered lists: no measurable lane (`bench/klimax/`).

## 8. New sources (searched this turn, new terms)

- TSLN: Time-Series Lean Notation (engrxiv, Jan 2026). Claims 68–73% token reduction against JSON with lossless
  fidelity. Baseline is JSON; no independent verification. https://engrxiv.org/preprint/download/6375/10670
- arXiv 2510.06824 (rev. 20 May 2026), *Efficient Numeracy in Language Models through Single-token Number Encodings*.
  Single-token numbers need new embeddings; not applicable to a fixed model. https://arxiv.org/html/2510.06824v2
- arXiv 2605.24541 (23 May 2026), *SemanticZip*. Splits protected exact commitments from lossy-compressible context.
  Our constraint is fully lossless, so the lossy half is out of scope. https://arxiv.org/abs/2605.24541
- arXiv 2605.29000 (27 May 2026), *Text-Preserving Lossy Text Compression*. Reports repetition as a dominant LLM decoder
  failure at low retention. Relevant to readability risk, lossy setting. https://arxiv.org/abs/2605.29000
- Prior-session source still relevant: arXiv 2604.13066 (dictionary in system prompt, out of scope; algorithmic
  reconstruction ~0.91 similarity, not byte-exact). https://arxiv.org/abs/2604.13066
