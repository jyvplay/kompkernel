## 2. ATX-RELEASE mechanism and admissible inputs

A target source line is exactly `## TITLE (YYYY-MM-DD)`, where `TITLE` is nonempty and the date has the digit shape `4-2-2`; the transform does not validate calendar dates. The encoded line is `TITLE YYYY-MM-DD`. The in-band rule, applied **after the parent decoder**, restores each line matching `^(.+) ([0-9]{4}-[0-9]{2}-[0-9]{2})$` to `## $1 ($2)`. The regex takes the final space before the date. No per-line marker or hidden side channel is used.

The inverse would be ambiguous if an untouched line already had the collapsed form, so the encoder rejects the entire transform if any non-target line matches it. It also refuses fewer than three target headings, empty or over-cap input, lone-CR line endings, or ill-formed Unicode. The transform preserves every other code unit and every LF/CRLF boundary, including the final-newline state. The accepted domain is therefore: valid UTF-8 text representable as well-formed JavaScript Unicode, at most 100,000 UTF-16 code units, LF or CRLF line endings, at least three exact level-two dated headings, and zero non-target collision lines. All other inputs use the exact AKOLOUTHIA-2 fallback.

### Cost gate and fallback

The emitted candidate is the short ATX contract plus a complete DAEDALUS message for the transformed body. First the encoder measures that candidate against complete-message AKOLOUTHIA-2 on the original source. AKOLOUTHIA-2 is one of the named TAGSTACK runtime parents. If the candidate is not strictly below that measured member, it cannot be below the minimum of a set that includes the member, so the expensive full tournament is safely skipped and the exact AKOLOUTHIA-2 message is returned. Only candidates below AKOLOUTHIA-2 are sent through the full same-source TAGSTACK runtime-parent set plus SIBLING-TEMPLATE; they are emitted only if exact and strictly below that measured minimum. A completed rejection returns its measured best parent; if the full gate throws or does not complete, the encoder fails closed to the exact AKOLOUTHIA-2 fallback. This is a two-stage, explicitly scoped gate—not a registry-wide Pareto claim.

The corpus covers LF/CRLF, final EOL, multiple spaces, Unicode titles, malformed/near-match shapes, collision refusals, lone CR, over-cap input, and an unpaired surrogate refusal. - `npx tsc --noEmit -p .` passed after the X50 implementation and registry entry.
- `npm run build` passed for the production Vite build (309 modules transformed; 32.41 s in the final run).
- The contract and parent decoder are intended to be in the same chat message, with no system prompt, skills file, tool, or side channel. **No external LLM was asked to decode the candidate or fallback**, so native LLM readability is unverified. No independent human/model decode is claimed.
- This transform does not normalize or semantically rewrite prose. It restores the exact source spelling or refuses/falls back. Exactness here is a local software/UTF-8-byte result, not a proof that an LLM will follow the contract.

## 6. Fresh research and honest prior art

I searched for format-aware/lossless Markdown compression and fetched the relevant repository pages rather than treating snippets as evidence.

- [`mdziper`](https://github.com/shenyizg/mdziper) documents whitespace and punctuation removal for Markdown while preserving rendered appearance; its README includes heading-spacing transformations. This is close practical prior art for syntax-aware Markdown preprocessing, but its README does not establish this exact byte-preserving, one-chat contract.
- [`ContextCompressionEngine`](https://github.com/SimplyLiz/ContextCompressionEngine) describes byte-identical restoration but requires persisting a separate `verbatim` map alongside the compressed messages. That external state is outside this task's one-message/no-tools admissibility rule.
- Search snippets for `compress.new` and `llm-transpile` were not fetched or reviewed, so they remain leads and are not used to support a claim.

ATX-RELEASE's contribution is only the repository implementation of this narrow inferred-line-shape transform, its collision refusal, and its measured gate. Markdown syntax removal, structure-aware preprocessing, and template/dictionary compression are established neighboring ideas. **No compression-theory novelty claim is made.**
