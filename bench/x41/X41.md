# X41 — τύπος TYPOS: a self-inferred record mask, and its measured refusal

## The idea, in one paragraph

Encode a record set by what it does *not* contain. Infer a small alphabet of separator-free literal
strings that reappear in the same order on most lines, emit that alphabet once as the header, then
send only the values. The mask is the skeleton; the payload is the holes.

## What was built

`src/lib/omega/typos.ts`

| export | role |
|---|---|
| `typosPlan(text, enc)` | infer the mask, separator, delimiter and row/literal pattern; return `null` when no exact mask exists |
| `typosEncode(text, enc)` | plan → transform → **self-decode equality check** → parent encode → real one-message gate |
| `typosTransform(text, plan)` | render the wire |
| `typosDecode(wire)` | parse, re-interleave, refuse the wire untouched on any inconsistency |
| `typosSplit`, `cellSignature` | the mask algebra (split a line by its literals; cluster by exact skeleton) |

Wire grammar:

```
⟨ lit0 <d> lit1 <d> … <d> litk ⟩ <d> s<sep> <d> p<runs>        RLE of the row/literal pattern
<col0 values, joined by sep>                                    one line per unlifted slot
<col1 values, joined by sep>
…
<literal line 1>                                                every non-row line, in source order
```

Invariants held by construction and by test:

* the separator occurs in **no** source line, so a column split can never be ambiguous;
* the delimiter is read from position `close + 1`, never guessed from the mask body (a mask literal
  may itself contain a delimiter candidate);
* each column's value count is checked against the row count from the run pattern — arity is not
  inferred, it is proven per column;
* `\r`, the presence/absence of a final newline and every literal line pass through byte-exactly;
* decode refuses (returns the input) rather than guessing.

## The measurement that decides it

One process, `OMEGA_DET=1`, o200k, parent and child in the same run, every wire decoded **EXACT**.

| real slice | raw | wire | M_src | M_typ | Δ |
|---|---|---|---|---|---|
| `apt list --installed`, 30 rows | 608 | 574 | **275** | 315 | +40 |
| `find` listing, 30 rows | 1 005 | 741 | **367** | 387 | +20 |
| `ls -l` + npm tree, 87 rows | 2 136 | 1 489 | **408** | 474 | +66 |
| openstack/nginx log, 15 lines | 2 511 | 1 286 | **605** | 619 | +14 |
| `ps aux`, 24 rows | 688 | 569 | **316** | 352 | +36 |

Add the ~28-token clause: **+42 … +94 in favour of the incumbent parent, five lanes of five**. The transform genuinely
shrinks the text (−6 %, −26 %, −30 %, −49 %) and the parent still prefers the original, because it
compresses the original 2.2–4.2× and the wire only 1.4–2.1×. The mask cannot beat a repetition model
that already charges a repeated skeleton once.

Earlier row-major-body measurements, same conclusion with a different body layout: find-files
635 → 730 (+95), ls-l-nm 466 → 539 (+73).

The full-lane `apt-real` run (119 rows, 2 739 tokens) was **killed at 14.5 min** without finishing a
single lane of `verify.ts` — the parent's matcher is expensive on a 119-value single line. That is a
second honest reason not to ship the transform: it changes the parent's cost profile, not just its
output size.

## What the mask *is* good for

As a standalone wire with no repetition-coding parent it is 6 % (apt) to 26 % (find) below raw
tokens, with no model, no dictionary and no schema. That is the niche, and it is not the shipped
configuration.

## Files

* `bench/x41/rt.ts` — 49 tests, all passing: 9 grammar refusals, 10 boundary deformations, 7
  adversarial sources, 200-shape seeded fuzz, idempotence, 8 split/signature tests.
* `bench/x41/proto.ts` — plan census. 9 of 14 `bench/holdout-x41` lanes produce a mask; all decode
  EXACT; `du-ak`, `df-real`, `git-log-stat`, `node-help`, `node-versions`, `tsc-diag`, `find-json`
  have no repeated skeleton and are refused.
* `bench/x41/verify.ts` — real encode runner (parent vs TYPOS, same process).
* `bench/x41/mini.ts` — the slice runner used for the table above (`F=… N=…`), because full lanes
  do not fit in a turn's wall clock.

## Remaining gap and next test

The success predicate — a lane where the shipped message is smaller — was **not met**. The exact
gap: the parent is ~2.4× better than the mask on the same bytes. The next highest-information test
is therefore not another mask shape but a *different parent interaction*: feed the parent a wire in
which the mask header is itself tokenised as a **dictionary the parent can reference** (i.e. let the
parent see the mask as a repeated literal rather than as a new string), or measure TYPOS against a
deliberately repetition-blind parent to bound where it can ever pay.
