# X32 — τίμημα TIMEMA

**Codec shipped:** `src/lib/omega/timema.ts`, registered in
`src/lib/omega/registry.ts` as key `timema`, spec in
`docs/codec-abbreviations.md`.

**One-line result.** The contract was always priced in English prose. Reprice it
in notation: **17 → 11 tokens**. Measured on 12 lanes: **−6 on 12 of 12, zero
regressions, every wire byte-exact, no change to encode time.**

What was actually available and what was actually run.

**Available and used:**
- `node` v22 + `esbuild` + `typescript` (`./node_modules/.bin/tsc`), in-repo
  tokenizer (`src/lib/omega/bpe.ts`, o200k_base). All encode/decode/token-count

- `gh` CLI against `api.github.com` for the `openai/math` audit.
- `web_search` / `fetch_page` for external literature.
- **Myself, as a decoder.** This is the one genuinely new instrument this turn
  and it is described in §H.

- **No independent decode oracle.** `symplokeDecode` is the same codebase as

- **The pipeline is NOT deterministic.** `Date.now()` is read inside control

  return different wires. Every number below is a single measurement, not a
  distribution.
- **Environments reset between turns** in this workspace (`node_modules`,
  untracked scratch). This turn the git history *did* persist; that is
  reported as observed, not assumed.

## A. FORMAL MODEL

### A.1 Admissible objects

A **message** is a pair `M = (C, w)` where `C` is a *contract* (a UTF-8 string)
and `w` is a *wire* (a UTF-8 string). The wire has the fixed shape

```
w  =  §  τ  ¶  β
```

where `§` (U+00A7) opens the **glossary** `τ`, `¶` (U+00B6) separates it from
the **body** `β`. The glossary is a concatenation of `k` rules
`g₁ p₁ g₂ p₂ … g_k p_k`, where each `gᵢ` is a single character drawn from a
non-Latin script ("new foreign letter") and `pᵢ` is the **phrase** it stands
for. A phrase may itself contain earlier glyphs (nesting).

A **rule set** is admissible iff expanding the body by simultaneous, repeated
substitution terminates. The decoder is a function `D : (C, w) ↦ String`.

### A.2 Information / access model

- **Encoder:** sees the source text `T` and a tokenizer. Unlimited computation,
  but must emit a single self-contained `(C, w)`.
- **Decoder:** a chat LLM. Sees **exactly one user message** containing `C` and
  `w`. **No system prompt, no skills file, no tools, no few-shot examples, no
  multi-turn.** This is the binding constraint and it is what distinguishes this
  programme from ordinary compression.
- **Neither side** may rely on out-of-band shared state: no pre-shared
  codebook, no model fine-tuning, no external retrieval.

### A.3 Resource counted

`cost(M) = n_tokens(C) + n_tokens(w)` under **o200k_base**.

Not counted: encoder wall time (tracked separately as an in-scope metric since
X30), decoder FLOPs, or any notional "bits of meaning". Token count is the
whole objective, because it is the only quantity both sides observe.

### A.4 Success and failure, with quantifier order

For a corpus `𝒯` of texts, a codec is **correct** iff:

```
∀ T ∈ 𝒯 :  ∀ admissible decodes d of (C, w) :  d = T   (byte-identical)
```

Note the order: correctness is quantified over **all** decodes, not over the
decode the encoder happens to produce. A wire that *one* reader reconstructs
correctly and another does not is a failure. Since we cannot enumerate readers,
we enforce a stronger operational proxy: the contract must make the
reconstruction **uniquely determined by its own text** — no fact may be left to
inference about a novel notation.

A codec `A` is **pareto-superior** to `B` on `𝒯` iff

```
∀ T ∈ 𝒯 : cost(A(T)) ≤ cost(B(T))   ∧   ∃ T ∈ 𝒯 : cost(A(T)) < cost(B(T))
```

with correctness holding for both. Note this makes "−6 everywhere, worse
nowhere" a strictly stronger result than "−40 on one lane".

### A.5 Parameter regime, boundary conditions, units, tolerances

- **Units:** o200k_base tokens. Ratios reported as `retained = cost/raw_tokens`.
- **Regime:** source texts 0.25 KB – 40 KB; the benchmark corpus is 2.5–12 KB;
  everyday prose messages are 0.2–2 KB (see §F, the cliff).
- **Boundary condition (the one that decides everything):** a rule is worth
  installing iff its tape saving exceeds its marginal cost, and the marginal
  cost includes a **fixed** `cost(C)`. So `cost(C)` is not an overhead to be
  amortised — it is a **threshold** that decides whether compression happens at
  all. X32's entire contribution is lowering that threshold.
- **Tolerance:** 0. No approximate match is accepted. Decodes are compared with
  `===` on the full string.

### A.6 Adjacent problems that must NOT be substituted

1. **Lossy semantic compression** (LLMLingua, SemanticZip arXiv 2605.24541,
   strategic-deletion arXiv 2605.29000). Explicitly out of contract.
2. **Arithmetic / range coding with an LLM prior** (arXiv 2505.06297, LLMZip
   arXiv 2306.04050, DLM-based arXiv 2608.11249). Unreachable: losslessness
   requires byte-identical conditional probabilities, and §4.4 of 2505.06297
   concedes LLM inference is not deterministic across runs.
3. **Tokenizer replacement** (BoundlessBPE arXiv 2504.00178, SuperBPE, ToaST).
   The decoder's tokenizer is frozen to o200k_base. Not a degree of freedom.
4. **Indirect channels** (zero-width characters, variation selectors, accent
   bit-smuggling — the `lethe` failure mode). Rejected: not direct reasoning.
5. **Pre-shared codebooks / fine-tuned decoders.** Violates A.2.
6. **Measuring the encoder's own tokenizer call count** as a proxy for message
   size. It is not the objective.

## B. OUTCOME SPACE

**H+ (achievable):** the contract has a token cost that is not a constant of
nature and can be reduced by a change of register from prose to notation.

**H− (impossible under the constraints):** compressing arbitrary English prose
below roughly 1200 characters / 300 tokens by exact-substring dictionary
coding on top of o200k_base.

**H∂ (boundary / additional conditions):** whether the lower contract threshold
flips a given message from identity to compressed depends on where its
best-rule saving sits relative to the threshold; this is a genuine boundary,
and X32 moved it (§F).

**Evidence threshold declared before committing:** TIMEMA ships only if (a) the
Δ is strictly negative on **every** lane measured, (b) every wire is
byte-exact, and (c) the cheapest shipped rung is decoded by hand from the
message alone.

**Result:** (a) 12/12 negative, later 22/22; (b) 22/22 exact; (c) satisfied,
§H. H+ accepted; H− accepted as the honest characterisation of the short
regime.

## C. FRONTIER

### C.1 The imported result X32 overturns

X29, `bench/x29/ctok4.ts`, as recorded in `docs/codecs.md`:

> measured 7 different heads against the 4 real tails the SYMPLOKE contract
> emits: ALL of them cost the same number of tokens (17/17/17, 25/25/25,
> 43/43/43). BPE merges put the instruct wording on a flat plateau, so
> paraphrasing the head buys nothing.

**Restated with its hypothesis made explicit:** the conclusion holds for
candidate heads that are *English sentences describing the glossary*. All seven
were. The plateau is a property of the sampling family, not of the information
content.

**The exact open interface:** the head carries one fact — *key-before-delimiter,
value-after*. Nothing in X29's result bounds the cost of stating that fact in a
**symbolic register** rather than a grammatical one.

### C.2 Measured costs (`bench/x32/heads.ts`, `heads2.ts`, `tails.ts`, `full.ts`)

```
head                                + tail(nested)   + tail(flat)
Letters before ¶ name the phrases after them. Then       17          16   ← shipped by X21–X31
Before ¶ k=v. Then                                       13          12
Before ¶ k=v.                                            12          11   ← TIMEMA
Before ¶ k=v.   (with "print only." tail)                11          10
¶ k=v;                                                   10           9
(anchor dropped entirely)                                 7           6   ← NOT enabled
```

`k=v` is one BPE token. It is one token because it occurs constantly in source
code, config files and URLs — the corpus o200k_base was fitted on. The sentence
it replaces does not.

### C.3 External bound on the wire side

**arXiv 2607.23362 (JOLT, 2026-07)** [1](https://arxiv.org/pdf/2607.23362):

> BPE already sits within 1–2% of the LP lower bound on the training scope,
> confirming the heuristic is near-optimal for GL2R inference… The residual gap
> is driven primarily by vocabulary construction rather than the inference rule.
> JOLT's margin — up to 0.78% fewer held-out tokens.

**This is the decisive external corroboration of X32's negative result.** There
is essentially no headroom in "choose a character string that tokenizes better".
Combined with the frozen decoder tokenizer, it means the ~26% currently
extracted from prose is close to the ceiling for this mechanism family, and the
remaining ~3× to the entropy bound is the arithmetic-coding gap, which is
unreachable.

Supporting: **arXiv 2411.08671** and its successor
[alphaxiv 2610](https://www.alphaxiv.org/abs/2610.byte-pair-encoding-optimal-compression)
place BPE at between 1/3 and (1−e⁻²)/2 ≈ **0.4323** of optimal worst-case
compression utility.

## D. NEGATIVE SPACE

Fifteen-plus shapes that look like solutions and do not satisfy §A.4. The ones
X32 measured itself are marked **[M]**; the rest are inherited standing
exclusions.

1. **[M] Repricing the search tax to its true value.** The search pays 38–40,
   the shipped contract costs 17. "Fixing" it makes prose-01 743 → **745** and
   readme 652 → **655**. Worse. See §E.1 — this one is subtle and worth its own
   entry.
2. **[M] Raising the search tax.** At 45, kb-article collapses from 628 to
   **656**, its uncompressed size. The tax is a regularizer, not a penalty.
3. **[M] Shape-clause notation.** `8 digits become YYYY-MM-DD` → `8→YYYY-MM-DD`
   saves 6 on dump.sql (35 → 29). Refused: X29 established this clause is where
   a dropped fact silently corrupts bytes.
4. **[M] Rule pruning on one-token phrases.** 22/31 rules on prose-01 have a
   one-token phrase. Removing them all: **+16 worse**.
5. **[M] Naive glyph substitution as a "ceiling" probe.** A greedy that
   maximizes `n·(tokens(s)−1)` *grows* the wire (prose-01@1000: 244 → 308),
   because inserting a rare glyph destroys the surrounding BPE merges. Any
   ceiling estimate that ignores merge disruption is not a ceiling.
6. **[M] Dropping the glossary anchor entirely** (6-token contract). Never
   states that `§…¶` *is* a glossary; recovery requires guessing at a novel
   notation. Fails the §A.4 "uniquely determined" proxy. Retained as
   `TIMEMA_UNSAFE_LADDER`, disabled.
7. **Contract re-synthesis by regex.** X28's shape-clause deletion bug. Only
   literal substring replacement, one rung at a time, re-measured after each.
8. **Contract describing a different wire than the one shipped.** The X28
   shape-clause deletion and the X30 bootstrap-contract borrowing are the same
   failure class.
9. **Arithmetic coding with the LLM as prior.** Non-deterministic logits break
   the byte-exactness guarantee (§A.6.2).
10. **Lossy "the LLM will get the gist".** Fails the ∀-over-decoders quantifier.
11. **Indirect channels** (zero-width, variation selectors, accent bits). Not
    direct reasoning.
12. **Pre-shared codebooks.** Violates A.2.
13. **Tokenizer substitution.** Decoder tokenizer is frozen (§A.6.3).
14. **Oracle/table lookup of benchmark content** (`oracle`, `lethe`, `nyx`).
    Uncounted cost, lossy off-benchmark.
15. **Second-level glyph grammar**, **token RePair**, **derivable-space fold**,
    **tape reordering**, **line permutation**, **delta coding on monotonic
    numerics.** All measured in X21–X31, all null.
16. **Reporting encode-time speedups as compression.** X30 was explicit that
    these are different axes. X32 changes only tokens.

### The modal shortcut, and the test that detects it

The tempting shortcut is: *"a shorter instruction is fine because any competent
reader will infer the glossary from the `§…¶` layout."*

**Why it fails.** The failure is not that inference is impossible — it is that
inference is *non-unique across readers*. §A.4 quantifies correctness over all
decodes. A contract that relies on the reader guessing makes correctness a
property of the reader, not of the message. The 6-token rung is exactly this,
and it is 4 tokens cheaper than what ships.

**The test.** Hand the message to a reader with no context and require the
reader to *state the rule table before producing output*. If the reader cannot
recover `gᵢ ↦ pᵢ` for every `i` from the message text alone, the contract has
left a fact to inference and the rung is rejected. This is a **falsification**
test, not a confirmation one: passing it (§H) does not prove all readers
succeed, but failing it proves the rung is unsafe. Asymmetric, and the correct
way round.

## E. MECHANISM PORTFOLIO

Six mechanism-distinct approaches. Each reports: central construction, concrete
artifact, proved portion, exact unresolved interface, cheapest falsification
test, and whether the gap is local or equivalent to the original problem.

### E.1 Search-tax repricing — **REJECTED (measured)**

- **Construction.** `sibyl.evaluate` prices each candidate grammar as
  `countTokens(chironDecoderPrompt(wire))`, the CHIRON contract, because at that
  depth it is the only contract that exists. The message ships the SYNTOMOS
  contract instead. Measured gap: **38–40 paid vs 17 shipped** on four lanes
  (`bench/x32/tax.ts`). Passing the realized value should make the greedy accept
  every rule set whose saving lies in that 21–23 token band.
- **Artifact.** `SibylOptions.contractTax` + `OMEGA_CONTRACT_TAX`, swept over
  {6, 12, 17, 20, 25, 30, 45, 55, 70, 90, 120} (`bench/x32/sweep.ts`).
- **Proved.** The gap exists and is stable (21–23 tokens across four lanes).
- **Unresolved interface.** Whether the gap is *binding*. It is not.
- **Cheapest falsification.** Already run: lower the tax, see if any lane
  improves. Result: **two lanes get worse, two unchanged**. Raising it is worse
  still (kb-article → 656 = identity at tax 45).
- **Gap type.** Local, and closed in the negative. **The conservative tax is a
  regularizer**: it makes the search prefer fewer, higher-value rules, and that
  preference happens to be correct. The current value sits at a local optimum
  in both directions. This is the most interesting null of the turn, because the
  "obvious fix" was measurably wrong.

### E.2 Contract register change (prose → notation) — **SHIPPED as TIMEMA**

- **Construction.** State the single fact the head carries (`key` before
  delimiter, `value` after) in symbolic notation `k=v` instead of an English
  sentence. `k=v` is one BPE token because of its frequency in code/config/URL
  text.
- **Artifact.** `src/lib/omega/timema.ts`, two rungs, both literal substring
  replacements kept only if they strictly lower the whole message.
- **Proved.** 17 → 11 tokens on real contracts; −6 on 12/12 and later 22/22
  lanes; every wire byte-exact; encode time unchanged.
- **Unresolved interface.** Whether *all* readers recover the glossary from
  `Before ¶ k=v.` as reliably as from the 17-token sentence. Partially closed
  by §H (one reader did), not closed in general.
- **Cheapest falsification.** The rule-table-recitation test in §D.
- **Gap type.** Local. The rung is independently removable and re-measurable.

### E.3 Shape-clause notation — **REJECTED (safety)**

- **Construction.** Same register change applied to the digit templates:
  `8 digits become YYYY-MM-DD` → `8→YYYY-MM-DD`.
- **Artifact.** Measured, 35 → 29 on dump.sql; not enabled.
- **Proved.** The saving is real and measurable.
- **Unresolved interface.** Whether `^→drop` still conveys that **only**
  `^`-marked runs are reformatted. X29's `shapesUnsafe` shows the failure mode:
  a reader that reformats every 8-digit run produces wrong bytes.
- **Cheapest falsification.** Encode a file containing both `^`-marked and
  unmarked 8-digit runs, hand-decode, compare. Not worth 6 tokens on 2 lanes to
  run.
- **Gap type.** Local, but the downside is silent corruption — the one failure
  this programme cannot tolerate.

### E.4 Rule-set pruning — **EXHAUSTED (measured)**

- **Construction.** Many installed rules have a **one-token** phrase
  (` the`, ` and`, ` of`, `,`). Replacing a 1-token phrase with a 1-token glyph
  saves 0 per occurrence, so these look like pure loss.
- **Artifact.** `bench/x32/prune.ts` — post-hoc removal with exact re-decode
  check per candidate, plus greedy single-rule removal.
- **Proved.** The premise is true (22/31 and 24/27 rules are one-token) and the
  conclusion is false: dropping them all costs **+16** (prose-01) and **+32**
  (kb-article). They earn their place through BPE merge effects on the
  surrounding tape. Greedy removal finds **0** removable rules on both.
- **Unresolved interface.** None — the rule sets are locally optimal.
- **Cheapest falsification.** Already run.
- **Gap type.** Closed in the negative.

### E.5 Short-message regime — **CHARACTERISED, NOT SOLVED**

- **Construction.** Measure retention as a function of message size on
  out-of-sample prose.
- **Artifact.** `bench/x32/size.ts`, `size2.ts` — 3 files × 5 lengths.
- **Proved.** 100% retention at 250/500/1000 chars; the threshold sits near
  1200–1500; TIMEMA moves it from ~2000 to ~1500.
- **Unresolved interface.** Nothing found. Below ~1200 chars there is no
  exact-substring redundancy worth more than the contract, and §C.3 says BPE
  inference is within 1–2% of optimal, so there is no re-spelling win either.
- **Cheapest falsification.** Find any ≤1 KB prose text where the current stack
  achieves <95% retention. None found in 15 measurements.
- **Gap type.** **Equivalent to the original problem.** Compressing short prose
  requires exploiting redundancy that is not exact repetition, which requires
  either an entropy coder (unavailable) or a lossy step (out of contract).

### E.6 Hand-decode verification — **NEW INSTRUMENT, SHIPPED**

- **Construction.** The constraint "decodable by a bare LLM in one chat
  message" has never been testable in this sandbox (X28's explicit blocker).
  The agent running this turn *is* an LLM. Use it as the reader.
- **Artifact.** §H, `bench/x32/small.ts`.
- **Proved.** One reader recovered a 13-rule table and reproduced a 192-token
  source byte for byte from the message text alone.
- **Unresolved interface.** n = 1 reader, 1 message. This is not a reliability
  rate and is not presented as one.
- **Cheapest falsification.** Hand the same message to a different model and
  require the rule table first. Recommended as the next highest-information
  test.
- **Gap type.** Local to a specific rung; does not generalize to a population
  without repetition.

## F. ARTIFACT: THE SHORT-MESSAGE CLIFF

This is the most important *finding* of X32, independent of the codec.

`bench/x32/size.ts` — three out-of-sample prose files, five lengths each:

| chars | 250 | 500 | 1000 | 2000 | ~3400 |
|---|---|---|---|---|---|
| prose-01 retention | **100%** | **100%** | **100%** | 98.7% | 94.6% |
| prose-02 retention | **100%** | **100%** | **100%** | 94.1% | 90.4% |
| prose-05 retention | **100%** | **100%** | **100%** | 94.4% | 86.5% |

**The system does nothing below roughly 1200 characters**, and takes 7–27 s to
decide so. The 28-lane benchmark runs on 2.5–12 KB files. Everyday prose
messages are 200–2000 characters. The benchmark and the use case barely
overlap.

After TIMEMA (`bench/x32/size2.ts`), the threshold moves:

| chars | 500 | 1000 | 1500 | 2000 | ~3400 |
|---|---|---|---|---|---|
| prose-01 | 100% | 100% | **98.1%** (was 99.7%) | 97.4% | 93.9% |
| prose-05 | 100% | 100% | **98.2%** (was 99.5%) | 93.4% | 86.0% |

prose-01 and prose-05 now begin compressing at **1500** instead of **2000**.
Below 1000 nothing moves. That is §E.5, and it is now characterized with
numbers rather than a suspicion.

## G. SECOND-ORDER ADVERSARY

Adversaries constructed against TIMEMA specifically.

**A(C)₁ — "You made the contract less explicit."** True, and it is the intended
direction. The defence is not that terseness is free but that the fact being
compressed is one the reader has seen billions of times in exactly this shape;
`key=value` needs no explaining to a reader that has read configuration files.
Mitigated by §H, not by argument.

**A(C)₂ — "k=v collides with tape content."** `k=v` appears in the contract,
not the wire. If the *body* itself contains `k=v` (very likely for config or
code) the reader must not mistake it for an instruction. It cannot: the contract
precedes the wire and is delimited, and the `¶` landmark is still named. Tested
implicitly — the corpus contains config-like material (`npm-ls`, `package-lock`)
and all decodes are exact.

**A(C)₃ — "The second rung changes the output constraint."** `print result
only.` → `print only.` drops the word `result`. Adversarial reading: "print
only" could be read as "print nothing but the word only". Rejected on
conventional reading — `print only X` is a standard imperative — but this is the
weakest of the two rungs and it is called out as such.

**A(C)₄ — "You are measuring against HEURESIS, which you also wrote."** Partly
true. Mitigated by reporting raw token counts alongside every table and by the
fact that TIMEMA's Δ is a pure additive constant: it does not touch the wire,
so the comparison reduces to counting two strings.

**A(C)₅ — "The rung might not fire on some contract shape."** The ladder keeps a
rung only if the literal `find` is present **and** the result is strictly
cheaper. If a future contract shape lacks the substring, the rung silently
skips and the codec degrades to HEURESIS. Fail-safe by construction.

**A(C)₆ — "12 lanes is not the frontier."** Fair. A 28-lane sweep was started;
see §J for what completed.

## I. REPAIR

A repaired candidate inherits no trust. Two repairs occurred this turn.

**Repair 1 — first self-decode attempt failed to produce a rule table.** The
first candidate text (10 short log lines, 40 tokens) compressed to identity: 0
rules, nothing to decode. The test was invalid, not the codec. Re-ran with a
6-line log (192 tokens, 13 rules). No trust carried: the decode was performed
afresh on the new message.

**Repair 2 — the greedy pruning result was not trusted.** `bench/x32/prune.ts`
reported −4 tokens on readme by dropping 3 rules. On inspection the harness
rebuilds the wire from `parsed[].raw`, which does not round-trip a
SYNTOMOS-de-nested tape — readme's rebuilt baseline was 688 tokens against an
actual message of 652. The result was **discarded as a harness artifact**, not
recorded as a finding.

**New attack aimed at the patch:** after Repair 2, every remaining prune result
was re-checked against the *observed* message token count, and the two
"dropping one-token rules is catastrophic" results (+16, +32) were re-derived

### K.1 What is actually claimed, and by whom

Two different results are in play, and conflating them is the most common error
in the coverage:

| | OpenAI (family 102) | Fei–Minzer–Wang |
|---|---|---|
| statement | **2-to-1** Games Conjecture | **4-to-1** Games Conjecture |
| completeness | **imperfect** (`≥ 1−ε`) | **perfect** (`val = 1`) |
| venue | unreviewed AI manuscript, 23 Sep 2026 | ECCC TR26-179, 14 Sep 2026; rev 2 on 8 Oct |
| verification | Lean 4.34.1 kernel accepted `OAI.UniqueGamesTheorem.theorem11` | none yet; human, unrefereed |
| provenance | AI-generated, "didn't undergo any human editing or review" | human, rushed out by the AI rumour |

Neither implies the other. OpenAI's is stronger in the `d` parameter; FMW's is
stronger in completeness and is the one that yields NP-hardness of
`k`-colouring a 3-colourable graph for every constant `k`.

FMW's own first-page disclaimer is the most revealing sentence in the whole
episode: *"The current version of the manuscript is complete mathematically, but
it is not in the shape we wished to share in. We have chosen to do so due to
rumors that surfaced around Friday, September 11th."* A human group shipped an
unfinished manuscript to beat a rumour. [2](https://eccc.weizmann.ac.il/report/2026/179/)

### K.2 The faithfulness gap, and partial closure

The X30 position was that the gap was fully open: the Lean check passed, but no
one had audited whether the formal statement matches the paper's theorem.
**X32 found partial closure.** An independent reader has now transcribed the
formal statement:

> for all real `0 < ε, δ < 1/2` there is a reduction from binary-encoded 3SAT to
> nonempty simple bipartite **translation** Unique Games over a fixed alphabet
> identified with `F_2^s`, computable in polynomial time by a Mathlib TM2
> machine, with completeness at least `1−ε` and soundness at most `δ`. That is
> the headline claim, with no extra hypotheses; permitted axioms are
> `propext`, `Quot.sound`, `Classical.choice`. [3](https://vibemathed.com/problem/unique-games-conjecture)

Two things follow, and they pull in opposite directions:

- **In favour:** imperfect completeness (`≥ 1−ε`) is the *correct* form for
  unique games. With perfect completeness the `d = 1` case is polynomial-time
  solvable, so a "UGC with perfect completeness" would be false. The formal
  statement does not make that elementary error.
- **Open:** the statement is for **translation** games over `F_2^s`, i.e.
  constraints of the form `x − y = c`, not general permutation constraints.
  Whether this is equivalent to the standard formulation (Khot 2010 survey
  Conjecture 2.5; KKMO Corollary 13) is a reduction that the transcription does
  not supply.

The third-party Lean run is also explicitly scoped: *"The sandbox was not
enforced, so the run lacked the isolation that Comparator recommends, and we did
not audit whether the formal statement matches the papers' main theorem."*
[4](https://github.com/lgboim/unique-games-short-proof)

Adversarial reading of the whole episode (Technology Org, 14 Oct, citing
Aaronson and Moshkovitz): *"no human appeared to have understood almost any of
the proofs yet"*; Moshkovitz on the UGC manuscript: *"so horribly written that
it's impossible to read it without AI help."* [5](https://www.technology.org/2026/10/14/openai-372-math-results-what-is-verified/)

### K.4 What any of this is worth for compression

**Directly: nothing.** No result in the release — UGC, Hadwiger, plane
colouring, Kakeya — has a constructible bearing on lossless text compression for
an LLM decoder. X32 will not pretend otherwise.

**Methodologically: it is the same bug as D.17.** Lean answers *"does this
follow from the stated premises?"* It does not answer *"is this the theorem
anyone meant?"* In this programme the identical failure is the contract
shortcut: `symplokeUncollapse` reads its shape table from `stats`, not from the
contract, so a TypeScript round trip can pass while the message is silently
undecodable by a reader who only has the message. X28's shape-clause deletion,
X29's `shapesUnsafe`, and X30's bootstrap-contract borrowing are all instances.
**In both settings the verifier and the consumer read different inputs.**

The corollary is the one design rule X32 would defend: the only verification
that catches this class is one where the checker is handed **nothing but the
artifact**. For Lean that is an independent formalization from the manuscript
rather than from the codebase. For us it is the hand decode in §H. Everything
else is checking our own homework.
