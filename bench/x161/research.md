# X161 fresh research and imported-result boundaries

This is a bounded source audit, NOT an audit of ALL results from all labs. No
Lean/lake or external model endpoint was available. GitHub files, revisions and
hashes are in research/provenance.json. Downloaded code is inspected, not trusted
as executable instructions. Numbers below are either explicit publisher claims
or bound to local verification receipts.

## Compression sources and exact open interface

Fresh searches used reversible morphology, log-length prediction, finite
differences/time-series forecasting, and attractor verification (rather than
X160's Git-header/grammar queries).

- Blalock, Madden, Guttag, **Sprintz: Time Series Compression for the Internet
  of Things**, IMWUT2(3),article93,2018, DOI10.1145/3264903.
  https://dl.acm.org/doi/10.1145/3264903 . Publisher abstract fetched. It describes
  lossless sensor time-series compression with online forecasting, limited
  memory and binary coding. Its speed/ratio claims are not reproduced here.
  Transfer: predictive representations can help the subsequent coder. Not
  transferred: lossy polynomial approximations, binary bitpacking ratios, or
  a native-language-model inverse. KAMPYLI uses classical Newton differences
  and accepts ONLY exact finite tables; it is not an implementation of Sprintz.
- Tang et al., **LogLite**, arXiv2507.10337v1,2025:
  https://arxiv.org/html/2507.10337v1 . First HTML chunk fetched, publisher
  artifact link https://github.com/benzhaotang/LogLite . Abstract claims a
  streaming lossless log system; search exposes length windows, XOR-P and RLE.
  The conjectured transfer is cheap length-indexed candidate discovery, not
  shipping XOR bytes to a chat reader. No numerical claim imported.
- Kempa/Prezza, **At the roots of dictionary compression: string attractors**,
  STOC2018, DOI10.1145/3188745.3188814 (search abstract only): for finite strings,
  a position set intersects an occurrence of every distinct substring. The
  smallest k-attractor decision problem is stated NP-complete for k>=3. This
  is NOT a lower bound for complete BPE messages with arithmetic instructions,
  and does not justify declaring our search impossible.
- Search-only RejuvenateFormer arXiv2412.15250 reports neural restoration;
  trained reconstruction/semantic quality is not byte equality without training.

The open interface is exact representation → full parent price → native
one-chat reconstruction → total runtime. Solving one arrow does not solve all.
Unconditional finite-alphabet counting rules out injectively strictly shortening
ALL finite strings in the same alphabet. It does not rule out these selected
polynomial tables. No unverified ETH assumption is used as an impossibility.

## OpenAI — one dependency deeper

Pinned SchedulerMachine.lean imports and defines scheduler machinery beneath
X160's WalkOutput. Its `poly_tour` assumes a polynomial comparison function on
the coded alphabet; `tour_spec` requires substring closure and empty-word
membership, with scheduler coverage obligations. This is a symbol-list/encoded
machine statement, not an o200k message objective. Source inspected, no imported
closure build and no kernel replay. The repository HEAD still matches the
previous pinned revision. No new proof is inferred merely from a fresh fetch.

## Anthropic — Frey boundary and newly found ETH claim

The newly fetched `Thm_FreyPackage_frey_no_cofixed_small` delegates to its P2M
solution for prime cases5,7,13 under FreyPackage hypotheses; it is not an
independent verification of the exclusion proof.

Fresh search led to public anthropics/formal-math/eth. Its MainResults.lean
explicitly says **definitions only, no theorem, no proof**. The documented main
claim quantifies one finite-stack deterministic machine and a constant C
independent of k, for k>=1, m>=2, n>=4, no duplicate clauses and every variable
occurring; it bounds counting time by an exponential with the minimum of two
expressions involving km and k²n. README claims a subexponential3-SAT algorithm
and describes Lean/nanoda verification; NONE of those builds ran here. The
source itself separates simulation/encoding alignment from its formal claims.
We therefore report an inspected public claim, not an established refutation
of ETH, not P=NP, and not a practical compression speedup. No instruction in its
README about prompting a model was executed as a verification substitute.

## Google — different construction, independent verifier

Fetched the pinned cap_sets verification notebook as joined cell sources,
retaining license text. It supplies1084 vectors of dimension9. Its prose says
F_2^n while specifying mod3 arithmetic; the data contain2, so we test the
well-defined claim over **F3^9**, not silently repeat the typo.
`verify-capset.py` parses literal data only and checks all distinct pairs x,y:
-(x+y) mod3 is absent. This is equivalent to absence of three DISTINCT points
summing to zero in characteristic3. Also verify cardinality, coordinates, and
reject the mutation adjoining the forced third point. This certifies this
finite construction only, not optimality, the historical1082→1084 record,
notebook execution or any codec bound. Receipt: capset.json.

## DoubleAI — expose the SAT trust interface

Pinned All63/Trust.lean defines `UnsatFacts = UnsatFamily 7224 G63`.
`routeA_case` derives UNSAT from `lratBytesOk bytes = true`; `routeA_facts`
packages such a family. The contents API returned encoding=none for the2,019,004-byte
All63/Axioms.lean; this initially looked empty but was a retrieval limitation,
not source-file emptiness. Re-fetching its git blob recovered the actual file:
7,224 explicit UNSAT axioms, followed by a decision tree packaging `routeB_facts`.
The final wrapper references that family. Full-blob hash and an explicitly marked
first/last18-line excerpt are saved. This exposes the conditional trust boundary;
it is neither proof that the theorem is false nor a successful certificate replay.
The per-instance LRAT acceptance and formula/hash alignment remain the next gates.
No SAT certificates or25GB Lean build ran here. Earlier girth-paper access gap
is not disguised by this different chess artifact.
