## 2. Measured findings this turn (receipts in brackets)

1. **CHIRON is wall-clock budget-limited on documents ≳ 5 KB.** `filelock__changelog.rst`:
   budget 4 s → 9756 tokens, budget 26 s → **9019 (−7.5 %)**; `nose__CHANGELOG` 7272 → 7135;
   `greenlet__CHANGES.rst` 6136 → 6069. On readme/email-thread the budget makes no difference
   (converged). [`bench/tmp/chiron-determinism.ts`, `bench/tmp/chiron-budget.ts`]
   - Consequence: CHIRON's output depends on machine load (`gpl-3.0`: 6709 vs 6706 quiet, 6728 vs 6684
     under two-process load). Any tournament that uses CHIRON with a wall-clock budget is not
     reproducible across machines. **This is the largest missed item found.**
2. **Macro search is at a local optimum for its move set on short documents.** Widening the prefilter
   (1600 → 100000) and phrase length (26 → 40) changed nothing on readme or email-thread.
   [`bench/tmp/chiron-exp-run.ts`]
3. **STICHOS assumed one width per document.** PERIODOS removes that limit: long tool-wrapped
   licence texts gain 3–6 % over CHIRON alone (GPL-3.0 −298, CECILL-2.1 −280, AGPL-3.0 −274 tokens,
   contract included), while the broader wrapped subset gains 0.30 % in aggregate.
   [`bench/periodos-report.md`]
4. **Contract overhead dominates below ~1–2 k tokens.** The reflow contract is 43 tokens; its savings
   are 18–26 newlines on a 650-token document. Only long documents pay.
5. **Markup is already covered.** `page.html` compresses 81 % (`akribeia-report.md`); closing-tag
   elision was killed there (#6). Not re-opened.

## 4. What we have missed (ranked by measured evidence)

1. CHIRON wall-clock truncation (above). Fix: deterministic work budget (candidate evaluations) and
   incremental token counting in the greedy macro pass. Expected to be the largest single lever on
   documents of 5 KB and up. **Unmeasured as a fix; the 26 s result is the measured ceiling.**
2. Reproducibility: any codec using a wall-clock deadline gives load-dependent output. The same issue
   affects `stichosEncode`, which calls CHIRON with `budgetMs: 4000`.
3. Readability of counting-based codecs (STICHOS, PERIODOS) is **unverified**. No model is available
   in the sandbox. This is the single biggest open risk to the readability requirement.
4. Prose substitution headroom is effectively exhausted at chat scale (kb-article bound above).
5. Contract tax: ~40 tokens per codec makes every codec lose below ~1–2 k tokens. Shorter, shared or
   named-algorithm contracts are the only lever on short documents (see §5).
6. Non-English prose remains at 0 % (pl-kb, ru-kb).

## 5. AI-native ideas (none of these is measured unless marked)

- **Named-algorithm contracts.** Replace a 40-token rule with a pointer to a standard algorithm the
  reader already knows (e.g., Python `textwrap.fill` with fixed flags). Measured: no. Verifiable
  oracle: the Python standard library itself, which is available in this sandbox.
- **Oracle-checked decoders.** Use an independent implementation (Python textwrap, a second decoder)
  as the verification receipt for any reflow or grammar layer, not just our own decoder. Measured: no.
- **Work-budgeted search.** Make CHIRON's search deterministic (fixed candidate budget) so tournament
  results are reproducible and can be cached. Measured: no (see §2 item 1 for the ceiling).
- **Reader-side counting checks.** Give the reader a self-check (for example, "the longest line must
  be ≤ W"), which costs tokens but converts a silent failure into a detectable one. Measured: no.
