# X35 — συγκοπή SYNCOPE

**Date:** 2026-10-21. **Branch:** `arena/f9c95c13-kompkernel`.
**What shipped:** one new codec, `syncope`, registered at position 25 of
`src/lib/omega/registry.ts` immediately after `pyknosis`, byte-exact through the
registry `run` path. It takes `openstack-loghub-26.log` from 945 (OIKONOMIA) and
928 (PYKNOSIS) to **898** — **−47** against the pre-X34 frontier and **−30**
against PYKNOSIS itself.

---

## A. Executive summary

Every codec before PYKNOSIS compressed the same resource: some span of the text
occurs more than once. PYKNOSIS compressed a second resource: the decoder's
tokenizer charges different prices for different characters, and that price list
can be arbitraged by re-spelling.

**SYNCOPE compresses a third resource, and it is not repetition and not
alphabet pricing. It is FORMAT.** A dash inside a hexadecimal identifier carries
no information — the 8-4-4-4-12 grouping is fixed by convention, so the payload
determines the dash positions exactly. PYKNOSIS preserves those dashes out of
caution. SYNCOPE measures the cost of that caution (117 tokens on the 36 UUIDs
of openstack) and reclaims it.

The turn is also, and perhaps more usefully, a **negative-space map**. Nine
mechanisms were built and measured this turn; eight are refuted with receipts.
Section C records all nine. Several of the refutations are more valuable than
the win, because they close off directions that will otherwise be re-tried.

## C. The hunt — nine mechanisms built and measured, eight refuted

This is the core of the turn. Each entry states the mechanism, the
instrument, and the number that killed it.

### C.1 REFUTED — cross-script / glyph alphabet search
*Instrument:* `bench/x35/xscript.ts`, using a new `forceScript?` option added to
`MetathesisOptions` in `src/lib/omega/metathesis.ts` (pool-only: the parse keeps
`scriptOfChar(tape[0])`, only the glyph pool is redirected).
*Result:* all 8 `CHIRON_SCRIPTS` give **identical** token counts to the parent on
all 7 lanes (kb-article 622, prose-01 737, readme 646, bibliography 671,
git-numstat 1992, find-listing 1279, vix 1195). Metathesis already runs inside
`oikonomiaEncode`, so re-running it finds nothing new. **The glyph alphabet is
already optimal.**

### C.2 REFUTED — CHIRON block/template pass
*Instrument:* `bench/x35/blocks.ts`, `ab.ts`, `bob.ts`, `blocks2.ts`, `tapeblk.ts`.
*Result:* the raw opportunity is large — `chironFindBlocks` finds 1125 tokens
(24.3%) on git-numstat, 344 (12.5%) on npm-ls, 170 (9.5%) on dump.sql. But:
- `ab.ts`: blocks-ON **ties** blocks-OFF, delta 0 on all 5 lanes.
- `bob.ts`: blocks *are* constructed (git-numstat: 8 blocks, 19 lists) but only
  8 sequencing rules survive, versus the far richer rule set of the pure
  dictionary path — **the structural pass starves the dictionary.**
- `blocks2.ts`: the 126-unit block's anchors are `["","\t0\tsrc/lib/omega/",".ts\n"]`
  — the same constant the dictionary already captures.
- `tapeblk.ts`: mining blocks on the **post-dictionary** tape finds **zero**
  blocks on all 7 lanes, because the dictionary has already collapsed the
  anchors.

**Conclusion: block templates and the dictionary capture the *same* redundancy.
Templates are strictly redundant with the dictionary.** This is the cleanest
negative result of the turn.

### C.3 REFUTED — optimal (minimum-token) segmentation
*Motivation:* arXiv 2412.06926 reports greedy BPE is 3–5% suboptimal against
Viterbi min-cost segmentation.
*Instrument:* `bench/x35/seg.ts` (Viterbi over the encoder as an oracle).
*Result:* **zero** of the top-60 words on four prose lanes improve. Greedy is
already optimal for ordinary English words; the paper's gains live in rare and
cross-lingual vocabulary, which is not where this corpus's cost is.

### C.4 REFUTED — search is budget-limited
*Instrument:* `bench/x35/budget.ts`, 2000 ms vs 30000 ms (15×).
*Result:* **identical** output on kb-article (622), prose-01 (737), git-numstat
(1992), find-listing (1279). The search is **mechanism**-limited, not
budget-limited. No faster or longer search helps.

### C.5 REFUTED — digit-run re-spelling
*Instrument:* `bench/x35/price.ts` (alphabet price list), `dig.ts`, `syn2.ts`.
*Result:* measured chars/token for random 32-char payloads:

| alphabet | chars/token |
|---|---|
| `pyr` (PYKNOSIS, 16 letters) | **2.21** |
| `a16` (a–p) | 2.03 |
| hex | 1.71 |
| digits | **1.49** |

Letters beat hex, which beats digits — PYKNOSIS's direction is right. But
remapping **pure digit** runs loses: find-listing **+227** end-to-end,
vix-daily +164. The o200k pretokenizer caps digits at `\p{N}{1,3}`, and real
digit payloads are mostly 2–3-digit groups that already cost one token, so there
is nothing to arbitrage.

### C.6 REFUTED — post-grammar (residual-tape) alphabet arbitrage
*Hypothesis:* PYKNOSIS re-spells *before* the grammar, so the search re-optimises
against it and claws part of the saving back. Re-spelling the **tape** instead
would keep the rule set fixed.
*Instrument:* `bench/x35/hyst.ts`.
*Result:* net +3 (openstack), −3 (dump.sql), +2 (git-numstat), **+227**
(find-listing), 0 (vix). Worse or flat everywhere. The reason is diagnostic:
openstack's source has 124 hex runs / 2408 chars but its **tape** has only 8 runs
/ 74 chars — **shape collapse splits hex into letters and digits long before the
tape is built**, so there is almost nothing left to arbitrage there.

### C.7 REFUTED — extending PYKNOSIS to new lanes
*Instrument:* `bench/x35/hexscan.ts` (lowercase/uppercase/mixed/UUID patterns).
*Result:* only dump.sql (832 ch) and openstack (2408 ch) carry meaningful hex.
`ls-full-iso` has 252 chars but remapping **loses 50**. No third lane exists.

### C.8 REFUTED — prefix / LCP inheritance and glossary delta-coding
`prefix.ts` strictly worse on every structured lane (find-listing 2481 vs 1279;
git-numstat 4067 vs 1992). `gloss.ts`: `estDeltaSave` = 0 on all 7 lanes.

### C.9 **CONFIRMED — separator elision in grouped hex identifiers**
*Instrument:* `bench/x35/syn.ts` → `syn2.ts` → `syn3.ts`.
*Result:* **117 tokens** on openstack's 36 UUIDs. This is SYNCOPE; section D.

## D. SYNCOPE in detail

### D.1 The measurement

`bench/x35/syn3.ts` prices the same 32 hex digits two ways, over all 36 UUIDs:

| pattern | n | PYKNOSIS style (dashes kept) | dashes elided | saving |
|---|---|---|---|---|
| 8-4-4-4-12 | 36 | 663 | **546** | **117** |

### D.2 Why the dashes cost twice

1. **Directly.** Under the o200k pretokenizer, a dash is its own pretoken
   (` ?[^\s\p{L}\p{N}]+`). Four dashes, four tokens per identifier.
2. **Indirectly, and worse.** They fragment the re-spelled run. `\p{L}+` is one
   pretoken, so 32 contiguous letters are one mergeable unit; splitting them
   into 8/4/4/4/12 gives five units, and short units merge badly.

### D.3 Why dropping them is safe

The dash is recoverable **by position**. "Payloads after `^` take dashes after
8,12,16,20" asks the reader to count to 32 and insert four characters. No base
conversion, no carries, no large-number manipulation — the same discipline that
makes TIMEMA safe.

### D.4 The `hexish` guard (the anti-benchmaxxing clause)

`bench/x35/syn2.ts` scans every lane and counts matches containing ≥1 `a-f`:

| lane | shape | n | hexish |
|---|---|---|---|
| openstack-loghub-26.log | 8-4-4-4-12 | 36 | **36** |
| openstack-loghub-26.log | 4-2-2-2 | 26 | 0 |
| dump.sql | 4-2-2 | 26 | 0 |
| find-listing.txt | 4-2 | 120 | 0 |
| vix-daily-1990.csv | 4-2-2 | 126 | 0 |
| bibliography.txt | 3-3 | 12 | 0 |

Every date and page range scores zero. Those separators are **not** elidable —
TIMEMA and the shape system already compress dates far better, and deleting
their dashes would destroy that. The rule is therefore not "dashes are free here"
but "**dashes inside a hexadecimal identifier carry no information**", which
holds for UUIDs, trace ids and content hashes in text this encoder has never
seen.

### D.5 Disambiguation by marker, not by length

A length rule was tried first and **fails in practice**: openstack carries
32-character request UUIDs alongside 32-character **un-separated** tenant ids
(`113d3a99c3da401fbd62cc2caa5b96d2`). A reader could not tell them apart, so the
first implementation correctly refused to fire. The fix is a dedicated second
marker — elided payloads get their own, and the reader never counts to decide.

### D.6 Result

| stage | openstack wire | Δ |
|---|---|---|
| OIKONOMIA | 945 | — |
| PYKNOSIS | 928 | −17 |
| **SYNCOPE** | **898** | **−30** |

`syncope=true, syncopeRuns=36, syncopeSeps=144`, `DECODED-EXACT` through the
registry. The isolated estimate (117) exceeds the delivered gain (−30) for the
reason PYKNOSIS's own doc records: the grammar search reacts to the changed text
and reclaims part of the arbitrage. Reported honestly.

## E. Decodability — one chat input box, nothing else

The contract is one sentence appended to the existing wire:

> Then ~: etaoinsrhldcumyp mean 0123456789abcdef. Payloads after ^ use the same
> letters and take dashes after 8,12,16,20.

The reader's job, in full: expand the glossary (already required by every codec
in the stack), then for each `~` or `^` run map 16 letters back to hex, and where
the marker is `^`, insert dashes after the 8th, 12th, 16th and 20th characters.

**No system prompt. No skills.md. No tools. No arithmetic.** The regrouping is
positional; the alphabet is a fixed 16-entry table stated in the wire itself.
Verified byte-exact by `syncopeRoundTrip` and independently through the registry
`run` path (`bench/x35/reg.ts`), which reports `DECODED-EXACT` on openstack,
dump.sql and kb-article.

## F. Generality, and why this is not benchmaxxed

- The transform is **content-shaped, not corpus-shaped**: it keys on
  "hexadecimal identifier with ≥2 internal separators, ≥1 hex letter". It never
  sees a filename, a lane or a threshold tuned to this benchmark's filenames.
- The `hexish` guard **rejects** 4 of the 5 shapes it encounters, including the
  120-match and 126-match cases. A benchmaxxed codec would have taken them.
- The gate is **measured end-to-end**, so any document where the grammar reacts
  badly is returned byte-identical to the parent.
- It composes **under** the dictionary, like PYKNOSIS: the wire expands first and
  the regrouping is undone last, over text in which every payload still appears
  in its original surroundings.

**Honest scope:** it fires on documents carrying grouped hex identifiers and is
a no-op on prose, dates and digit-only tables. One lane of this corpus moved.

## G. Speed

Encode time is in scope (X30: "attack speed as well"). SYNCOPE adds one regex
scan and, on firing lanes, one extra full encode. It reuses PYKNOSIS's ≥150
re-spellable-character gate, so on the 29 non-firing lanes the added cost is a
single scan behind a gate already paid for. On openstack it costs the second
encode that PYKNOSIS already pays, plus one scan — no third encode.

### The generalisation boundary, stated without softening

**Zero of the ten prose-representative lanes moved under any codec in this
stack**, across X33, X34 and X35. The reason is now measured rather than
asserted (`bench/x35/ttok.ts`): the prose tape is

| lane | tape tokens | words | glyph runs | punct | digits |
|---|---|---|---|---|---|
| kb-article | 655 | **473 (72%)** | 165 (25%) | 13 | 2 |
| prose-01 | 799 | **568 (71%)** | 135 (17%) | 64 | 19 |
| readme | 626 | **472 (75%)** | 66 (11%) | 66 | 8 |

at roughly 5 characters per token, which **is** the natural o200k rate for
English. Every mechanism in this stack attacks repetition, alphabet pricing or
format — and ordinary English prose has no exploitable surplus of any of the
three at that rate. Beating it needs a semantic (lossy) mechanism.

The corresponding split on ops lanes is what makes them winnable:

| lane | tape tokens | glyph runs | words | **digits** |
|---|---|---|---|---|
| vix-daily-1990.csv | 989 | 625 (63%) | 10 | **352 (36%)** |
| find-listing.txt | 1173 | 374 (32%) | 322 | **473 (40%)** |
| git-numstat.txt | 1579 | 661 (42%) | 502 | **378 (24%)** |

Ops lanes are 24–40% digits and 32–63% glyph runs; prose lanes are 71–75% plain
words. **That is the whole difference between the categories that move and the
categories that do not.**

## J. Negative space — what is now known unreachable

Ranked by how firmly the turn closed them:

1. **Block/template structure** — provably redundant with the dictionary
   (C.2, four independent instruments).
2. **Glyph alphabet choice** — already optimal (C.1).
3. **Search effort** — mechanism-limited, not budget-limited (C.4).
4. **Segmentation** — greedy already optimal on this vocabulary (C.3).
5. **Digit re-spelling** — wrong direction on the price list (C.5).
6. **Residual/tape arbitrage** — shape collapse removes the payload first (C.6).
7. **Arithmetic / base conversion** — LLM-infeasible; regrouping is the
   positional-only subset that *is* feasible, and SYNCOPE takes it.
8. **Entropy coding** — arithmetic coding is inaccessible: LLM inference is not
   byte-deterministic (arXiv 2505.06297, 2601.10678 PMATIC).
9. **Brotli/gzip floor** — LZ77 + Huffman back-references are not executable by a
   bare LLM in one chat message. Measured floor: 9.4–41.9% of raw
   (`bench/x35/ceiling.ts`). Documented bound, not a target.

**What remains genuinely open:** prose. `bench/x35/ttok.ts` shows the prose tape
is 72–75% ordinary word tokens at ~5 chars/token, which is the natural o200k
rate for English. Beating it requires a semantic (lossy) mechanism, which is out
of scope for an exact codec. **Prose is the honest generalisation boundary of
this entire stack, and has been since X34: 0 of 10 prose lanes moved.**

### K.5 The fractal pattern, stated plainly

Across all four labs the same three-layer structure repeats:

| layer | status |
|---|---|
| results *claimed* | growing superlinearly (722 manuscripts in one drop) |
| results *Lean-formalised* | ~42% of the above |
