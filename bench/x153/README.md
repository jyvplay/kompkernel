# X153 — KENOMA: measured token wins, incomplete conjunctive target

## A. Model and admissibility

Source is an exact UTF-8 byte string, not a JSON value. Cost is o200k_base tokens
in the **entire** final message, including all decoder instructions and parent
representation. Incumbent is the current TAGSTACK frontier plus the X152 HOMOSEMA
ordinary-parent tournament, not raw text. Access is local code and source files;
no independent basic-chat endpoint was run. Experimental modules are unwired.
A selector accepts only a strict token improvement with a verified source inverse.
This establishes a local token-only nonregression property, not runtime Pareto
superiority. Unsupported parent readers retain the incumbent, not a fake pass.

## B. Hypotheses and evidence thresholds

- H+: some structured JSON closing lines are redundant given retained indentation
  and the stack, even after parent compression and complete instruction cost.
  Supported on two manifests by independent exact reads and reference pricing.
- H−: this mechanism gives broad everyday prose/ops wins and significant total
  acceleration. No supporting evidence: prose has no eligible JSON events; speed
  gate failed. This is not a universal impossibility result.
- H∂: restricted canonical layouts admit erasure while arbitrary JSON formatting
  does not. Exact reconstruct-and-compare admission defines the boundary.

Full requested success needs native one-chat exact reading, significant whole-stack
acceleration and broad useful frontier advancement together. Those conditions are
**not met**. No merge is authorized by these results.

## C. New implementation

`kenoma.ts` adds a hole arm (retains whitespace/comma-only close-event lines) and
an indentation arm (removes entire close lines). The latter reconstructs closing
bracket types, commas and line indentation from lexical stack and next retained
line, flushing at EOF. Widths 1/2/4 are tried; source reconstruction must match.
UTF-8 instability, excess depth, noncanonical layout and cap violations are rejected.
`kenoma-frontier.ts` exposes an optional complete API over the stronger X152
incumbent. No production wiring or benchmark manifests changed.

## H. Speed

An esbuild-only A/B patch uses TextEncoder.encodeInto in the existing scratch buffer
when the non-ASCII chunk's worst-case UTF-8 length fits. Production is unchanged.
14909 reference comparisons per build pass. After other benchmark jobs exited,
12 cold whole-stack calls ran in ABBA order on three fixed lanes. All wires match
fresh canonical results. Aggregate B/A CPU **0.963323**, wall **0.962005** (about
3.7%/3.8% lower), but the >=10% significant improvement/nonregression gate **fails**;
prose CPU ratio is 1.002482. No significant acceleration claimed or deployed.

## I. Cost and quantifiers

Lexical reconstruction is linear in traversed source plus emitted output, bounded
by 50000 UTF-16 source units and stack depth128; repeated whole-string validation
and three width trials are constant passes. Parent compression cost is additional
and inherited, not bounded by that linear decoder analysis. The wrapper reuses
identical folded inputs within its width tournament, but adds real parent calls.
Whole-source minimum across eligible alternatives is non-greedy; parent internals
retain their own heuristic searches. There is no global optimum or universal token
lower bound. Concurrent trial times must not be used as acceleration evidence.
