## §A Formal Model

A delimited table with header + R data rows, arity C, delimiter
`,`/`;`/TAB, plain or German number style, one scale per eligible
column. KEPHALAION searches for **aggregate entailments**:

- **rowsum**: a column `t` and a subset S (|S| ≥ 2) of other columns
  with `x_{i,t} = Σ_{c∈S} x_{i,c}` for all rows i except ≤3
  exceptions (empty term = 0). The target column is dropped.
- **headsum**: columns `h`, `t`, subset S with
  `x_{i,t} = x_{i,h} − Σ_{c∈S} x_{i,c}` (h ∉ S, |S| ≥ 1). Target dropped.
- **colsum**: one aggregate row a (first data row, last data row, or
  a row whose field-1 matches a Total/Sum/Overall/Gesamt/Summe label)
  with, for ≥2 numeric columns c, `x_{a,c} = Σ_{i≠a} x_{i,c}`
  (empty = 0). Verifying cells are blanked in the reduced text.
- **composition**: a rowsum drop together with a colsum blanking
  (≤3 combined exceptions).

All in exact BigInt decimal arithmetic; a target printed at a
coarser scale than its terms is accepted only when every row is an
exact multiple of the scale factor. Caps: 400k chars, 20k rows,
40 cols, ≥6 data rows, 80M planner work units. **Reader protocol**:
independent sums, no carried state — a slip damages one cell
(structural contrast with ATHROISMOS' integrating chain).

**Order-safety of the composition (proved)**: if both identities
hold in the original table, restoring the rowsum column first and
then column sums is safe. Let f(r) be any row-computable value
(function of row r alone, the dropped column's values included).
Restoration phase 1 inserts f exactly, because the rowsum identity
holds row-wise by encoder verification (exceptions shipped
literally). Phase 2 sums column c over the restored rows; those
rows are now byte-equal to the original non-aggregate rows, so the
sum equals the original aggregate cell by the colsum identity,
which the encoder verified on the original table. ∎ The encoder
re-verifies composition on the reduced table before pricing
(correctness proof + mechanical check, belt and braces).

## §E Six mechanism-distinct approaches considered

1. **n-ary row aggregates (chosen)**. Construction above.
   Artifact: `src/lib/omega/kephalaion.ts` (registered `kephalaion`).
   Proved: exactness by construction + whole-input restore; proved
   portion also covers order-safety. Unresolved: subset recall
   beyond 16 term columns (ranges-only fallback). Cheapest
   falsification: §F.
2. **Weighted sums `Σ k_c x_c` (rejected v1)**: real tables print
   weighted scores; but generic integer weights explode the search
   and the contract ("multiply {Mid} by 4 and …") and reader error.
   SYLLOGISMOS `A·K` covers single-term weights only. Deferred as
   v2 candidate with small-coefficient Diophantine fitting.
3. **Windowed/subtotal rows (rejected v1)**: report sections with
   `Subtotal` after each group. Teaches fine, but group-boundary
   detection + per-group sums multiply contract clauses; deferred.
4. **Row-count-driven totals / averages (rejected)**: an Average
   column = sum/count needs rounding-mode fitting with many ties;
   TAXIS' fitted-ceil semantics would need re-derivation in CSV
   land; sum stays exact, average is lossy-prone. Dead unless a
   round-trip-perfect printed-average lane is found.
5. **Checksum-style redundancy (rejected)**: ISBN/IBAN/Luhn digits
   are entailments but tiny per-row mass (~1 digit) and bacterial
   contract cost; dead by economics.
6. **Row-wise min/max/majority aggregates (rejected)**: real, but
   "the largest of fields…" per-cell reader cost and tie rules make
   byte-exactness fragile for human-grade readers; no evidence the
   o200k parents price such columns expensively. Deferred.

## §G Second-order adversary (per candidate)

- **Spurious subsets**: with k columns and few rows, some random
  subset can coincide on probe rows — countered by full-table
  verification + ≤3 exceptions; a coincidental subset surviving
  hundreds of rows still restores byte-exactly (restore is the
  arbiter), so the failure mode is at most "unintuitive contract",
  never corruption. Randomized sweep + refuse-or-exact invariant
  cover this.
- **Empty-cell semantics**: empty=0 is a *fitted* convention here —
  a table where empty means "unknown" and total = sum of *present*
  values would fit identically (they coincide numerically); a table
  where empty ≠ 0 in the total fails verification and is refused.
  Hazard: none beyond refusal.
- **Aggregate row masquerades**: a real data row whose values
  coincidentally equal column sums gets blanked and refilled —
  still byte-exact by verification. A `Total`-labelled entity row
  (e.g. a company literally named Total) is only *candidate*; cells
  that don't verify stay shipped.
- **Reader burden**: independent sums of up to 13 terms are the
  protocol; blind-decoded 3/3 (incl. German decimals and a colsum
  over 7 rows). No carried state is the engineered answer to
  ATHROISMOS' propagation risk. Long sums (hundreds of terms)
  would degrade readers; terms are capped implicitly by arity
  (40 cols).
- **Cost-model adversary**: plan ranking uses raw o200k counts of
  contract+reduced, not post-parent costs; on the zero-heavy early
  slice the planner picked a 4-term col13 plan instead of the true
  13-term one — still exact, still lost, gate falls back.
  Disclosed v1 limitation (repair: rank top-2 plans post-cheapest-
  parent; §I).
