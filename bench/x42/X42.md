# X42 — κάνναβος KANNABOS: the grid is the schema

## The hole, in the stack's own words

X39's report said it first: for space-aligned tables — `df -h`, `ps aux`, `kubectl get pods`,
`docker ps`, `ls -l`, `netstat` — "APOGRAPHE **refuses** (no single-character field separator).
The most common shape of CLI output is exactly the shape it cannot parse." Every codec in the chain
splits a record on a separator character, and every one of the commands an ops agent actually runs
prints fixed-width columns padded with space runs.

X42 is the codec for that shape. It reads the source as **character offsets**, infers the grid, and
transmits the **geometry** — the padding is never sent, it is regenerated.

## What was built

`src/lib/omega/kannabos.ts`, registry key `kannabos` (inserted before `chronos` in
`src/lib/omega/registry.ts`), exact, gate-checked.

| export | role |
|---|---|
| `kannabosPlan(text, enc)` | infer the grid (columns, anchors, per-column codecs, row pattern), then pick the cheapest plan on rendered tokens; `null` when no grid exists |
| `kannabosEncode(text, enc)` | plan → byte-exactness check → parent encode of the transform → **decode through the stack's own decoder** → one-message gate, `wire + clause < parent`; otherwise passthrough with the reason |
| `kannabosClause(plan)` | the contract, generated **from the plan** (only the anchors and codec kinds the wire uses) |
| `kannabosDecode(wire)` | the header is the program; any inconsistency returns the input untouched |
| `kannabosLines/Cells/Runs/RunBlock` | the geometry algebra |

Wire grammar:

```
⟨ k ¦ Ln<cellcodec> ¦ Rn<cellcodec> ¦ Tn<cellcodec> … ¦ pR12L1 ⟩ ¦ s
<one block per column, in column order>
<one line per literal row, in source order>
```

`p` is the row pattern (R = a row rebuilt from cells, L = a literal line, RLE'd); `¦s` = LF,
`¦S` = CRLF; the header delimiter and the run marker are chosen **by measurement** from characters
absent from the source.

Cell codecs, each chosen by measured token count on the rendered column: `x` one value per line,
`rN` run list, `dN` dictionary + index, `wW` fixed-width concatenation, `l:`/`k:` a METRON number or
clock law, and `t:` a **compound law** (text plus several integer fields, each with an affine step
and an optional period).

## The three patches that made it work

**Patch 10 — header ejection.** In a CLI table the header row is usually a **conforming** row:
`NAME READY STATUS …` sits on the same anchors as the data, so it enters every column's value list
and poisons every generator (the AGE column's first value becomes the literal string `AGE`). The
planner now tries ejecting the first 0, 1 or 2 lines into the literal set and keeps the cheapest
plan. `kubectl get pods`: 737 → 414 wire tokens, same 22 rows.

**Patch 11 — per-field periodicity.** `10.244.0.0 … 10.244.0.88` then `10.244.1.99`: the last two
numeric fields of a pod IP step at different rates and no single affine step list can fit them (the
fit fails exactly at row 8). `fitCompound` now searches a period list per field and writes `s%M`,
meaning `(V + s·row) mod M`. That one change is what made the `kubectl` lane buildable at all: all
seven columns become `t:` laws.

**Patch 12 — the clause is plan-filtered.** Only the anchors and codec kinds actually present are
explained. `df -h` clause: 53 tokens. `kubectl`: 72 (it pays 9 more for the `%M` sentence, and only
when a period is really used — earlier this was keyed off a `%` in the header text, which a `30%`
cell triggers falsely; now the plan records `periodic` explicitly).

## Red team — 91/91

`bench/x42/rt.ts`. A 15 grammar refusals · B 10 boundary deformations (CRLF, no final newline,
trailing spaces, tabs, mixed EOL) · C 8 adversarial sources (a `*` inside a value, the header glyphs
`⟨⟩¦` inside values, a `%` inside a modelled cell, ragged arity, unicode, an 8 kB line) · D 300-case
seeded fuzz · E 7 algebra checks · **F 12 checks for the three patches** (conforming header
ejection, `%M` periodicity, periodicity with one outlier, constant field, dangling/zero/one modulus
refusal, plan-filtered clause).

Re-running the suite after patches 10–12 found **two real soundness bugs that no gate run would have
caught**, because both produced a wire that decoded to *itself*:

1. **The empty trailing line.** A file ending in `\n` has a final empty line, carried as an `L` row
   (that is how the final newline is represented). When every column is a generator, that empty line
   is the *only* body line, so `header + "\n"` meant both "one empty literal line" and "no body";
   the decoder read it as no body, refused, and `kannabosDecode` returned the input. Silent identity.
   Fixed in the decoder: one `L` row plus an empty body ⇒ one empty literal line.
2. **The close glyph inside a sample.** `L0t:⟨x⟩0/1` is a legal column, and the header terminator is
   the first `⟩` — which was then found inside the sample. The decoder now takes the last `⟩`
   followed by a delimiter and an EOL flag; no sample can contain that, because the delimiter is
   chosen absent from the source.

## Honest citation

Fixed-width framing is old (Hollerith cards, COBOL `PICTURE`, Fortran FORMAT). Inferring a fixed-width
layout from alignment alone is **tooling, not literature**: pandas `read_fwf(colspecs='infer')`,
readr `read_fwf`, Alteryx "Parse Fixed-Width File and Infer Columns", and the published "sieve"
heuristic (positions no row fills are boundaries — the same idea as KANNABOS's anchor histogram).
All of them infer a *parse*. None treats the inferred grid as a **transmitted, token-costed
message**, which is the only claim made here.

Adjacent and real: the column store (Abadi, Madden, Ferreira, SIGMOD 2006) is the same
de-interleaving for storage; SuperBPE (Liu et al., arXiv:2503.13423, 2025) shows that BPE's
whitespace pretokenisation makes a space run a token **boundary**, which is why a gap's *width* is
nearly free and its *occurrence* is not; "Getting the most out of your tokenizer" (arXiv:2402.01035,
2024) treats pretokenisation as a compression lever; Afroozeh, Kuffó, Boncz (SIGMOD 2024,
`doi:10.1145/3626717`) compress text/logs against grammars. Recent table work (TEAR,
arXiv:2609.15205; "Table Serialization Determines Which Relations Language Models Preserve",
arXiv:2610.24798) studies how layout affects what a model recovers — read here as search snippets
only, and cited for that reason.

## Limits, stated plainly

1. A grid needs ≥ 4 rows and ≥ 3 columns. Seven-line `df -h` output and `dpkg -l` produce no plan.
2. `findmnt` plans and gains 65 tokens, which the ~60-token clause eats; it would lose the gate.
3. Periodicity is per field over a fixed period list; a larger prime period, or a column whose step
   changes, falls back to `x`/`r`.
4. The clause is 53–72 tokens. That is the entire reason `ss -tan` and `ls -l /usr/bin` refuse — not
   the wire, the contract.

## Next highest-information test

The refusals are all "good table, strong parent". The next measurement that would move this is a
**worksheet-style ops lane** with ragged multi-line records (`docker ps` with a wrapped command,
`iostat -x`, `ip -br addr`, `journalctl`), where the grid's per-column law can cover a *changing*
step; and a clause ladder that drops to the anchors alone when the parent is already close, since
the 53–72 tokens are the deciding term on three of five lanes.
