## 1. What was built, in one paragraph

ARCHETYPON is a byte-exact, single-chat, tool-free codec with two line-patch
folds behind one gate. The **parametric** arm names a canonical public text the
reader already knows verbatim and transmits only an exact line patch. The
**self-canon** arm — the genuinely new, fully in-band mechanism — replaces a
long near-duplicate block with one `⟦a-b|patch⟧` reference to an earlier block
in the same message. Both arms are gated against a measured identity arm that
is the best of `apographeEncode` and `anagnorisisEncode`. On 10 real,
pre-existing licence files the codec is 33–52 tokens against 156–257 raw,
−76…−83 %, and 2–3 tokens below the previous leader ANAGNORISIS; on 0 of the
31 shipped lanes does it fire spuriously. A bare LLM (me) decoded one real
message byte-perfectly from the message text alone (§H).

## A. Formal model

**A1 — Admissible objects.** `text ∈ UTF-8*`, `enc ∈ {o200k_base,
cl100k_base}` (all measurements o200k_base). A message is `(contract, wire)`
where `contract` is in-band natural language and `wire` is text. A codec is
`E: (text, enc) → (contract, wire, decoded)` and `D: (wire, contract) → text`.
The counted resource is `M = countTokens(contract + "\n" + wire, enc)`; when
the contract is empty, `M = countTokens(wire)`. Success requires
`D(E(x)) === x` **byte-for-byte** (JS UTF-16 equality plus a CPython byte
comparison on the emitted messages). No system prompt, no skills file, no
tools, no retrieval, no second message. The reader is a language model that
may use its own weights.

**A2 — Information/access model.** Single chat I/O. The reader sees only the
message. Two codebooks are admissible: (i) an **in-message** codebook (a
glossary, an anchor block, a legend) whose cost is charged to M; (ii) a
**parametric** codebook — public canonical byte strings the reader already
holds — whose identity cost is a few tokens and whose *availability* is an
empirical property of the reader, not an axiom. ARCHETYPON uses both: the
self-canon arm uses only (i); the parametric arm uses (ii) but ships a
from-memory verification and an independent in-band-capable reader. No hidden
state, no cross-message memory, no external database.

**A3 — Resource counted.** o200k_base tokens of the whole one-chat message
(verified against `countTokensExact` by the repository's chunk-additivity
theorem, `bpe.ts`). Secondary: wall-clock ms (reported, never used as a gate),
number of catalogue entries, number of line edits, and `exact ∈ {0,1}`.

**A4 — Success/failure with quantifier order.**

- Ship predicate: `∃ x ∈ Lanes : D(E(x)) = x ∧ M_E(x) + 3 < min_{c ∈
  PriorCodecs} M_c(x)` — a strict, more-than-a-few-token win on at least one
  real lane, with exactness checked for EVERY lane encoded.
- Safety predicate: `∀ x ∈ Lanes : D(E(x)) = x ∧ M_E(x) ≤ min(M_frontier(x),
  M_anagnorisis(x))`. Both are gated in `archetyponEncode`; a failure of any
  gate returns the identity arm.
- Failure mode: `∃ x : D(E(x)) ≠ x` — never tolerated; the red team (38/38)
  and the CPython reader (10/10) are the receipts.

**A5 — Parameter regime, boundaries, units, tolerances.** `|text| ≤ 40 000`
chars, ≤ 400 lines; catalogue = 5 public texts; patch ≤ 16 `set` edits and
≤ max(3, ⌊len/4⌋) edits; a folded window ≥ 6 lines (parametric) / ≥ 8 lines
(self-canon); anchor token mass ≥ 40 tokens; ≤ 24 self-canon references.
Delimiters are chosen from a 9-character pool absent from every patch value.
EOL ∈ {LF, CRLF} settled once; mixed EOLs are not normalised — they simply
fail the exactness gate. Tolerances: tokens ±0 (integer), ms ±10 % (2-core
sandbox, sequential runs), bytes ±0.

**A6 — Adjacent problems NOT substituted.** (1) Classical lossless compression
(gzip/zstd/brotli) — the output must be human/model-readable text, not bytes.
(2) Arithmetic coding with an LLM prior (LLMZip, arXiv 2306.04050;
arXiv 2505.06297) — decoding needs bit-identical probability tables, which a
one-chat model cannot reproduce; the 2026 critique of arXiv 2505.06297 says
exactly this. (3) Lossy prompt compression / deletion-with-reconstruction
(LLMLingua; arXiv 2605.29000) — not byte-exact. (4) Learned latent context
compression (IC-Former, ICAE, Z-tokens) — needs a trained encoder/decoder and
is lossy. (5) A hidden lookup table in the decoder without a name in the
message — the contract must identify the canonical text in plain English.
(6) Shortest-common-superstring packing (openai/math family 128) — see §I:
an independent 2026 evaluation found the offset/index overhead removes the
advantage, and a one-chat reader cannot reconstruct the offsets.
(7) General prose compression — explicitly NOT solved here (§J).

## C. Frontier: best-known achievability / impossibility, and the open interface

*Imported results, restated with hypotheses:*

1. **Closed-world floor.** For text with no public canonical span, the shipped
   frontier chain (`apographeEncode` → OURA → EUTELEIA → … → CHIRON) reaches
   the dictionary/glyph floor on prose: `kb-article.txt` 656 → 622,
   `llm-answer.md` 733 → 674. Hypothesis: repeated token spans are the only
   uncharged redundancy and BPE merges are ~1 token per glyph. Measured in
   X39/X43 and re-confirmed here (`verify.jsonl`: 622 / 674 unchanged).
2. **Open-world floor.** ANAGNORISIS (Z45) showed that a public canonical text
   costs only `H(identity) + H(layout)` because the reader holds the text:
   `lic-mit.txt` 223 → 41 with a `【MIT】` reference. Hypothesis: the reader
   knows the SPDX/GitHub templates verbatim (Carlini et al., USENIX Security
   2021, showed even GPT-2 memorises the MIT licence). Re-confirmed here: 41.
3. **Interface.** Between (1) and (2) sits a region with **no** result: a
   canonical text with **arbitrary line differences** (not fixed slots), or a
   long block that is only a **near-duplicate** of another block in the same
   message. ARCHETYPON occupies exactly that interface with a general exact
   line patch. On the single-copy licence lanes it is 2–3 tokens below (2);
   that is a small but strict win, and the mechanism that produces it (LCS /
   positional `set` patch + clause auction + frontier composition) is what
   generalises to the near-duplicate case.

**Frontier repeat (this turn, real run).** `bench/x44/frontier-repeat.ts`
re-encoded a declared **17-lane subset** of the 31 X39 receipt lanes with
`apographeEncode(text, enc)` under `OMEGA_DET=1` and diffed raw, parent, total,
fired, header and the decode against the receipts. Result
(`bench/x44/receipts/frontier-repeat.log`, 336 s wall): **16/17 bit-identical,
1 difference — `markdown-table.md` parent/total 182 → 176**. This is exactly
the unexplained parent-number discrepancy X40, X42 and X43 already reported
(X43: 29/31 bit-identical on the full run, 3 223 s). The other reported
discrepancy (`npm-ls` 901 → 904) is in the untested set here because that lane
alone costs ~1 000 s.

**Answer to "is the frontier exactly the configuration mentioned by the test
ran last turn?" — no, and I restate it.** The shipped chain reproduces the X39
receipt configuration on 16 of 17 re-tested lanes; `markdown-table.md` is
**176, not 182**, in the parent's number and in the shipped total. No X44
number rests on that lane. I did **not** re-run the full 31-lane repeat (cost),
and the 14 untested lanes are listed in `frontier-repeat.json`. The
session-memory frontier from the parallel X40–X47 branch (PR #33: vix 550,
aapl 1407, prose 622…) is a **different lineage** whose codecs (SYSTOLE,
EMPEDOS, …) are not in this checkout; those numbers are not a baseline here.
A registry smoke (`bench/x44/smoke.ts`) loads `archetypon` by key from
`codecEntries()` — **207 entries**, family/fidelity `exact`, oneChat 38,
`decoded === source` — exactly the path a reader takes.

## D. Negative space — 19 result shapes that look like solutions and are not

1. **A hidden decoder table with no name in the message.** Fails A2: the reader
   has no way to know which table. Test: remove the `title` from the contract;
   the CPython reader and the hand-decode both fail.
2. **A parametric reference without a verification.** Fails A4. Test: G4 (the
   from-memory decode) is a mandatory gate; `bench/x44/receipts/hand-decode-fastify.txt` is the receipt.
3. **A line patch with insert/delete ops in "current line" numbering.** The
   X44 red team (A8, G1) measured 74/200 seeded round trips; fixed by the
   set-only, order-independent algebra. **This was a real bug in this turn.**
4. **A delimiter that occurs in a patch value.** Silent corruption. Test B1:
   the delimiter is chosen absent from every value, and a semi-colon copyright
   (`E8`) is an exact end-to-end case.
5. **Mixed EOL normalisation.** Would change bytes. Test: CRLF (C4/E3) and
   no-final-newline (C5/E4) are separate exact cases.
6. **Allowing a self-canon reference to point into an expanded line range.** The
   first self-canon draft used expanded-text line numbers; the fix uses WIRE
   line numbers and refuses nested anchors. Test D1–D6, F1–F2.
7. **Prefix-alphabet / enclitic 0-token phrase references on general prose.**
   Measured this turn on all 31 lanes (`bench/tmp/enclisis-final.ts`): the best
   arm never beat the frontier; standalone M on `kb-article` ≈ 649 vs 622.
   Fails because the legend cost and BPE interference exceed the ~1 token per
   elision. **Rejected with receipts.**
8. **Case-channel stego (capitalisation as a free bit channel).** 216/302
   lowercase words admit 3 token-neutral case patterns, but a per-word class
   stream needs more states than are available. Adjacent to LETHE (Y8), whose
   accent/space stego was already negative. Not built.
9. **Word-index / dense code-stream dictionary.** The legend (V distinct items)
   costs ~V tokens and the ordinal lookup is not reliably executable by a bare
   model over hundreds of positions. Measured on `kb-article`: legend ≈ 200
   tokens, no net win. Rejected.
10. **Stacking the prefix transform before the frontier chain.** Measured
    (`bench/tmp/stack-probe.ts`): the chain's dictionary returns *identity* on
    the transformed text (glued markers destroy token-pair repeats). Rejected.
11. **Applying the prefix transform to the frontier's output wire.** Measured
    on 7 lanes (`bench/tmp/epen-onwire.ts`): 0 plans pay. Rejected.
12. **Composing DIASTEMA's interval wire with `apographeEncode`.** Measured
    (`bench/tmp/compose-probe.ts`): find-listing 1140 = DIASTEMA 1140, prices
    133 = 133. No gain — the chain adds nothing. Rejected.
13. **Character-level stem dictionaries with exotic glyphs.** Measured
    (`bench/tmp/stemproto.ts`): ru 478 → 565, de 525 → 611. EUTELEIA's byte-
    fallback floor: rare code points cost 2–3 tokens. Rejected.
14. **LLM arithmetic coding / rank coding (LLMZip family).** Not one-chat
    decodable; arXiv 2505.06297's own §4.4 concedes non-deterministic logits.
    Rejected (A6).
15. **Lossy skeleton + LLM reconstruction.** arXiv 2605.29000 explicitly targets
    semantic, not byte-exact, reconstruction. Rejected.
16. **Shortest-common-superstring packing (openai/math #128).** Independent
    2026 evaluation (Lermont/math PR #1, cited in §I) concludes "no general
    compressor replacement"; overlap offsets must be transmitted. Rejected.
17. **A single-clause tournament with a selector byte.** The identity arm shows
    the selected arm's contract self-identifies the wire, so a selector byte
    is dead weight; the tournament is exact without one.
18. **Beating ANAGNORISIS on a multi-licence bundle with one long clause.**
    Measured: `third-party-notices.txt` — my parametric arm 308, ANAGNORISIS
    129. One short reference per copy wins. This is H∂ and is reported as a
    loss, not hidden.
19. **Claiming general prose gains.** Measured: `kb-article` 622 = frontier
    622, `ru-kb` 478 = 478, `find-listing` unchanged. Zero movement. Reported
    as the open gap in §J.

**Modal-shortcut test.** The most tempting shortcut is "the codec works
because the decoder has the catalogue". Test: delete
`ARCHETYPON_CATALOGUE` from the TS module and re-run the 19-lane verification;
the parametric arm must then return identity on all 19 lanes (it does — the
plan enumerator has nothing to enumerate). A *separate* test keeps the
catalogue but removes the contract's plain-English title: the independent
CPython reader must fail to decode (it does — `decode_parametric` returns
`None` without a title). Both are single-call falsifications.

## G. Second-order adversary A(C) per candidate

- **A(parametric):** a model that "knows" the MIT licence but re-wraps it at
  72 columns. Attack: G4 would fail. Defence: the codec refuses when the
  from-memory check fails; the self-canon arm and independent reader remain.
  Residual risk: a *different* model may know a different variant — stated as
  H∂.
- **A(self-canon):** an anchor that itself contains a `⟦` reference, or a patch
  whose delimiter appears in a value. Attack: red team D3/D4/B1/E8. Defence:
  nested anchors are refused, delimiter chosen by measurement, malformed
  references returned unchanged.
- **A(clause auction):** a wording that is cheaper but ambiguous. Attack: the
  3–6 candidates are scored on the *junction* price (EUTELEIA's lesson) and the
  CPython reader parses the winner; an unparseable winner would fail G3 and the
  arm would be refused.
- **A(identity tournament):** ANAGNORISIS's `decoderPrompt` not equal to the
  one-chat message. Attack: I recompute `countTokens(anMsg)` and verify
  `anagnorisisDecode(an.wire) === text` before it can be the floor;
  `verify.jsonl` shows 0 inexact.
- **A(token accounting):** a contract that is longer than reported. Defence:
  every M is `countTokens(contract + "\n" + wire)` on the actual emitted
  strings, and `messages.json` contains those strings for re-counting.
- **A(determinism):** the inherited DAEDALUS wall-clock budget. Defence:
  `OMEGA_DET=1` on every run; repeated runs of the 19-lane verification (two
  independent runs this turn, before and after the red-team repair) agree on
  every M.

**Compression-relevant papers (last 10 years, honest reading):**

- *Lossless Token Sequence Compression via Meta-Tokens*, arXiv 2506.00307 —
  LZ77-like lossless token-sequence compression, 27 %/18 % on two tasks. It
  is a token-ID-level meta-token scheme, not a one-chat natural-language wire.
  [11](https://arxiv.org/html/2506.00307)
- *Lossless Prompt Compression via Dictionary-Encoding and In-Context
  Learning*, arXiv 2604.13066 — LLMs learn encoding keys **in context** with
  the dictionary in the **system prompt**. Our constraint forbids a system
  prompt, which is precisely why ARCHETYPON puts the (much smaller) canonical
  reference in the one chat message instead.
  [9](https://arxiv.org/abs/2604.13066)
- *Boundless Byte Pair Encoding*, arXiv 2504.00178 (COLM 2025) — superwords
  merge across pre-token boundaries, +9–15 % bytes/token, but requires
  retraining the tokenizer. It validates the "boundary is the resource" thesis
  behind experiments 3/4 above; it cannot be used in-band.
  [1](https://arxiv.org/abs/2504.00178)
- *Bit-level BPE*, arXiv 2506.07541 — reduces UTF-8 byte-fallback tokens by
  treating bytes as bits. Needs vocabulary expansion; not in-band.
  [2](https://arxiv.org/html/2506.07541v1)
- *Lossless data compression by large models* (LMCompress), Nature Machine
  Intelligence 2025, doi:10.1038/s42256-025-01033-7, arXiv 2407.07723 — LLM
  predictions + arithmetic coding, ~⅓ of zpaq's text rate. Requires the same
  model at both ends; the one-chat constraint excludes it.
  [2](https://www.nature.com/articles/s42256-025-01033-7)
- *Lossless Compression of LLM-Generated Text via Next-Token Prediction*,
  arXiv 2505.06297 — claims 14–24× but, as the independent critique notes,
  reports no round trip and concedes non-deterministic logits
  [4](https://pith.science/paper/2505.06297), §4.4. Not a usable precedent for
  byte-exactness.
- *Text-Preserving Lossy Text Compression*, arXiv 2605.29000 — deletion +
  Gemini reconstruction; explicitly lossy. It is the closest published cousin
  of our H⁻ "let the model guess" negative result.
  [13](https://arxiv.org/html/2605.29000)
- *Diffuse to Compress*, arXiv 2608.11249 — diffusion-LM lossless compression,
  non-autoregressive symbol choice; needs a model at decode time.
  [10](https://arxiv.org/html/2608.11249)
