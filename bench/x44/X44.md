# X44 — ANALEPSIS (ἀνάληψις, "a taking up again, a resumption")

Registry index **34**, `src/lib/omega/analepsis.ts`, parent **KRISIS** (X43, index 33).

**The pareto frontier moved for the first time since X41: ls-full-iso 366 → 364.**
prose-01 also moved, 737 → 736. Thirteen lanes tested, **13/13 byte-exact, zero
regressions**. The gain is three tokens and is reported as three tokens.

The larger part of this turn's value is a set of **definitive negative results**
that close four directions, and one structural localization that names the exact
target for all future speed work.

---

## 1. The codec

Every codec from CHIRON to KRISIS decides what to compress *while* it is
compressing. ANALEPSIS is the only one that looks at the **finished wire** and asks
whether anything worth a rule was left behind.

`bench/x44/greedy.ts` scanned shipped bodies for maximal repeated substrings with
overlapping windows collapsed — so `administ`, `dministr`, `ministra`, `inistrat`
count as **one** find, not four — and priced each at its measured token count minus
a two-token definition. Real residue exists: `" JavaScript "` ×3 and
`" for you to "` ×2 in readme, `baseline-browser-mapping` and `browserslist` ×2 in
ls-full-iso, `" Q3 reconciliation"` and `" remittance "` in email-thread,
`"IDEOGRAPHIC SPACE"` ×2 in prose-01.

**Loop:** enumerate maximal repeats of the body, longest first, suppressing any
candidate contained in an accepted longer one → for each, build the wire with that
phrase appended as **one new rule** and measure `countTokens` of the **entire
frame** → keep the single best **iff it strictly reduces** that count → **decode
through the full chain and keep only if byte-identical to the source** → repeat
until nothing helps or `ANALEPSIS_MAX_ADDED=12` is spent.

The new rule is appended **last**, so it may reference any earlier rule and no
earlier rule can reference it — CHIRON's topological guarantee and its decoder are
untouched. The glyph is the first one-token character of the tape's own declared
script occurring nowhere in the frame, so `chiron.ts:144`'s self-declaration still
identifies the alphabet and nothing about it is transmitted.

**Why maximal repeats:** CHIRON's search is frequency-driven, i.e. Re-Pair.
**MR-RePair** (Nakashima, *Algorithms* 13(4):103, 2020) replaces the most frequent
**maximal repeat** instead, reports grammars **~55 % the size of Re-Pair's** on
highly repetitive text, and proves that under a stated condition the maximal-repeat
grammar is no larger than Re-Pair's. Maximal repeats are exactly what a first pass
leaves behind: a frequent short substring is consumed early and the longer repeat
containing it is never reconsidered as a unit.

**The tape/body split is attempted unconditionally**, not only when no upper layer
fired. `bench/x44/resid.ts` showed the `§ tape ¶ body` structure *survives* the
upper layers — ls-full-iso, page.html, chart.svg and readme all split cleanly with
ANTISTROPHE, PERITROPE or OURA active. This is safe only because the decode check
is load-bearing, and **relaxing it is precisely what unlocked ls-full-iso**: the
first, stricter version restricted ANALEPSIS to lanes where the whole upper stack
gated itself off, and on those it found only prose-01's single token.

## 2. Negative result — exact greedy rule pruning gains **zero**

`bench/x44/greedy.ts` Q1 removed one rule at a time, whichever *actually* reduced
`countTokens` of the whole frame, re-measured, and repeated.

| lane | rules | prunable | frame | **gain** |
|---|---|---|---|---|
| prose-01 | 31 | **0** | 726 → 726 | **0** |
| kb-article | 27 | **0** | 611 → 611 | **0** |
| email-thread | 39 | **0** | 477 → 477 | **0** |
| prose-02 | 36 | **0** | 770 → 770 | **0** |

**Not one rule can be deleted.** CHIRON's rule set is already optimal under
removal. This retroactively corrects an earlier reading of the same data — that 22
of 31 rules on prose-01 had "negative marginal value" — which was an artifact of
pricing phrases **in isolation**.

**The reason is itself the finding.** Rule references cost about **0.6 tokens
each** in situ, not 1.0, because **adjacent glyphs merge**: prose-01's body
contains runs like `كي` and `ارس` pricing as one or two tokens rather than two or
three. Pruning by the naive isolated-phrase criterion instead **loses 19–36 tokens
per lane** (`bench/x44/prune.ts`: prose-01 −19, prose-02 −33, kb-article −36,
email-thread −28), because the tape shrinks by less than the body grows.

## 4. Negative result — the alphabet has no better setting

`bench/x44/script.ts` applied a consistent bijection from the rules in use onto
each CHIRON script's pool **in tape order**, preserving the glyph *sequence* so
only the script changes (X43's `screen1` reordered by frequency, which destroys the
adjacency structure that §2 shows is what matters):

| lane | current | best alternative | worst |
|---|---|---|---|
| prose-01 | arabic, 725 | cyrillic 787 (**−62**) | polyglot/cjk/hangul 794 (**−69**) |
| kb-article | cyrillic, 610 | arabic 670 (**−60**) | polyglot/cjk/hangul 695 (**−85**) |
| email-thread | cyrillic, 476 | arabic 541 (**−65**) | cjk/hangul 560 (**−84**) |

**Every permutation of every script is worse by 53–85 tokens.** The current
collision-ordered choice at `chiron.ts:1344` — picked once, by minimum collision
count, never by cost — has no better setting to find. Combined with X43's
`screen1` (Latin remapping −43/−20/−17 on aapl) this closes the alphabet direction
from both sides.

*Caveat recorded honestly:* this reconstruction also failed to decode, for two
reasons that are bugs in the harness rather than in the finding — `chironDecode`
requires the leading `§`, which the harness stripped, and the pool filter excluded
only *body* literals while rule texts in the *tape* are literals too. The token
deltas are unaffected by either, and they agree in sign and magnitude with X43's
independent measurement.

## 5. The structural finding — where a swap's benefit is created

X43 recorded this as the highest-information test available: can `chironEncode`
(203 ms on pom.xml) stand in for the 36,505 ms `ouraEncode` trial it would replace?

**Refuted, and precisely.** `bench/x44/surrogate.ts` on ls-full-iso, for the swap
`"."↔"/"` — which is the one that **wins**:

| surrogate | text | swapped | verdict | truth |
|---|---|---|---|---|
| raw token Δ | 1175 | 1166 | promising | — |
| **chironEncode** | 423 | 422 | **lose** | **WRONG** |
| anadiplosisEncode | 367 | **361** | **WIN** | right |
| euteleiaEncode | 367 | **361** | **WIN** | right |
| ouraEncode | 367 | **361** | **WIN** | right |

A one-token difference at chiron level is swallowed by the five-token clause, so
the surrogate says *lose*; three layers down the same swap wins by six. On pom.xml,
where ANTISTROPHE genuinely loses, chiron agreed with the truth on **all three**
candidates. **The surrogate is right exactly where it does not matter and wrong
exactly where it does.**

`bench/x44/depth.ts` then walked the stack layer by layer and localized it: the
benefit is **created at ANADIPLOSIS**, the first layer below chiron, and is
**invariant above it** — anadiplosis, euteleia and oura all report 367 → 361.

The mechanism is plain once stated: a character swap changes **punctuation**, and
punctuation is what the framing and run-length layers key on. **No surrogate
shallower than ANADIPLOSIS can be predictive.**

### And ANADIPLOSIS is not cheap — it is the whole cost

| layer | ls-full-iso | pom.xml |
|---|---|---|
| chironEncode | 542 ms / **0.04M** calls | 266 ms |
| **anadiplosisEncode** | **86,703 ms / 15.83M calls** | **9,865 ms** |
| euteleiaEncode | 83,659 ms | 6,659 ms |
| ouraEncode | 85,512 ms | 33,424 ms |

**A 160-fold jump at a single layer.** ~43 s per call on a 2,549-character file,
~**8 million `countTokens` calls** to do it. Reading `bpe.ts`'s own exported
counters (`chunkCacheStats`) over a full encode:

| lane | countTokens calls | hit rate | distinct long | distinct short |
|---|---|---|---|---|
| pom.xml (1,797 ch) | **40,666,051** | 92.0 % | 37,769 | 1,202,237 |
| ls-full-iso (2,549 ch) | **18,596,983** | 76.3 % | 16,599 | 386,887 |

**Forty million tokenizer calls for a 1,797-character file.** But the hit rate is
92 %, so memoization is already doing its job — the cost is **search breadth**, not
repeated tokenization. That closes memoization as a speed lever and names the real
one: the ANADIPLOSIS/SYNCOPE search itself.

## 7. What is closed, and the one thing that is not

Closed by measurement, with receipts, and not to be retried:

1. **Rule-set pruning** — exact greedy removal gains **0** on 4/4 lanes; naive
   criterion **loses** 19–36.
2. **Residual n-gram augmentation** — net mass −9 … +1; ANALEPSIS harvests the last
   3 tokens and there is no seam behind them.
3. **Alphabet reassignment** — every script permutation worse by 53–85 tokens;
   Latin remapping worse by 17–43 (X43).
4. **Cheap surrogates for trials** — refuted at chiron depth; no surrogate
   shallower than ANADIPLOSIS can be predictive.
5. **Memoizing the tokenizer** — already implemented (`SHORT_CACHE`, `LONG_CACHE`,
   `CHUNK_CACHE`) and running at 76–92 % hit rate.
6. Digits at `ceil(W/3)` floor (X42, exhaustively over 1,110,000 strings).
7. Phrase dictionaries saturated on prose (X42 saturation ratio > 1).
8. CHIRON's grammar contributes **nothing** on prose/code — `rules=0` at every
   budget (X43).

**Open, and now precisely localized:** ANADIPLOSIS/SYNCOPE costs **43 s and 8 M
tokenizer calls** on a 2.5 KB file, a **160×** jump over chiron, and it is the
dominant cost of the entire stack. It is also the layer that *creates* most of the
compression on ops lanes (ls-full-iso 423 → 367, a 13 % win) and the layer at which
swap benefits become visible. **Speed and accuracy both live there.** Any future
turn that wants a large general gain should profile inside `anadiplosisEncode` and
its parent `syncopeEncode` — `anadiplosis.ts:271`'s `findCandidates` scan is
O(n × 64) with a `countTokens` per repeat found, but the measured 8 M calls say the
bulk is below it, in SYNCOPE.

## 8. Runtime honesty

All measurement ran **sequentially in single node processes on a 2-core sandbox**.
No parallelism, no distributed search, no independent agents, no simulators. Tools
actually used: `node`, `esbuild`, `gpt-tokenizer` (every measurement and every
encode), `tsc --noEmit` (type gate), `python3` (repo edits), `web_search` (two live
searches). **No Lean, no theorem prover, no compiler other than tsc, and no model
inference was executed.** Every mathematical and benchmark claim in §9 is reported
from search and was not verified by me.

The frontier move on ls-full-iso is bound to a **real decode**: `analepsisDecode`
returned the source byte-identically for all thirteen lanes, in the same process
that measured the token counts, and again through the registry by key.

## 9. Citations added this turn

**Grammar compression (new sources, all ≤10 years old except the two classical
bounds, which are named as such):**

- **MR-RePair** — Nakashima, *Algorithms* **13**(4):103, 2020. Maximal repeats
  instead of bigrams; **~55 %** of Re-Pair's grammar size on highly repetitive text;
  conditional size guarantee. **The direct basis for ANALEPSIS's candidate rule.**
- **arXiv 2608.19228** — *Assembly Theory and the Smallest Grammar Problem*, July
  2026. Empirical evaluation of **eight** grammar and dictionary compressors over
  **408 strings**; introduces **Re-Pair T-NDR**, a branch-and-bound tie-resolving
  variant, lowest mean error **4.03 %**; finds **Re-Pair dominates across all ten
  sets**, with Sequitur the most versatile alternative but *not* on the Pareto
  frontier.
- **arXiv 1704.08558** — *Practical and Effective Re-Pair Compression*. Linear-time
  heuristic whose grammar encoding uses on average only **2.8 % more bits than the
  information-theoretic minimum**, and beats 7-Zip at maximum compression on **half**
  the tested cases.
- **Charikar–Lehman–Liu–Panigrahy–Radhakrishnan–Sahai–Shelat**, IEEE TIT 2005
  (classical): every efficient smallest-grammar algorithm has approximation ratio
  **≥ 8569/8568 unless P=NP**; best upper bound **O(n^½)**; two algorithms at
  **O(log³ n)** and **O(log(n/m\*))**.
- **The Smallest Grammar Problem Revisited**, IEEE 9259056: LZ78 is
  **Θ((n/log n)^⅔)**, BISECTION **Θ(√(n/log n))**, and RePair's lower bound improves
  from **Ω(√log n)** to **Ω(log n / log log n)**.
- **On the Complexity of the Smallest Grammar Problem over Fixed Alphabets**,
  *Theory Comput. Syst.* 2020: NP-complete and **APX-hard** even for a fixed
  alphabet of size **≥ 17**.
- **arXiv 2202.08447** — *RePair Grammars are the Smallest Grammars for Fibonacci
  Words*.
- **A machine-found error in a published proof**, recorded as an instance of the
  meta-verification pattern this repository uses in its `handcheck` decoders: a
  referee report on **arXiv 1908.06428** published by Pith locates a break in
  **Theorem 3.7, Claim 2** — the proof fixes *G*, the SLP after *k−1* rounds, and
  argues the start rule has many distinct factors of length Θ(log k), **but RePair's
  total grammar size is non-increasing under replacement**, since substituting a run
  of length ℓ≥2 by one nonterminal occurring r≥2 times changes size by
  ℓ−(ℓ−1)r ≤ 0. **So *G* is an upper bound on the final size, not a lower bound.**
