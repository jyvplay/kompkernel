# Z11 — KANON (HYLE table-fold gate → DAEDALUS; AMPHORA otherwise), and what the PR audit found

Branch `arena/da2b9818-kompkernel`. New codec registered: `kanon` (`src/lib/omega/kanon.ts`, uses `src/lib/omega/hyle.ts`).
Verdict in one line: **a narrow, measured gain on the tabular lane (−13.0% on the 10 files where it fires, −1,340 tokens over 80 files, all exact). It is not a general gain.** Prose and code are unchanged.

## 0. Runtime honesty (what actually ran)

- Tools used: `bash` (Linux, 2 CPU, 3 GB RAM), `esbuild` bundles run under Node 22, `tsc --noEmit -p .` (exit 0 at the end), `git`, `gh` (PR list, branch list, `gh api` for openai/math metadata), `python3` (JSON and receipts analysis), `start_process` for two background shards, `web_search` ×3, `fetch_page` ×0 this turn.
- Not used: no LLM run (none in the sandbox). **No Lean toolchain is installed** (`which lean lake elan` returned nothing), so no Lean proof was checked by me. No theorem prover, simulator, database, or GPU.
- Parallelism: two background Node shards for the 80-file evaluation. Everything else sequential.
- Context usage: **unknown**. I have no tool that reports this conversation's token count or what remains. Check the Arena UI.

## 1. Formal model (A)

- **Objects:** UTF-8 text `d` with a tabular or CLI-output structure. Codec `E(d) = (wire, contract)`. Reader: one bare chat turn, no system prompt.
- **Access:** encoder may run HYLE's O(n) fold certificate, the tokenizer, and the fixed DAEDALUS / AMPHORA arms. No model calls.
- **Resource:** o200k_base tokens of the whole message = decoder contract + wire (counted once).
- **Success:** `∀d∈D: decode(E(d)) = d` (byte-exact), and `∃ lane L ⊂ D: |{d∈L: M(KANON,d) < M(AMPHORA,d)}| > 0` with a material total gain, and no regression on `D∖L` (identical output).
- **Failure:** any non-exact decode; any regression in total; any gain claimed without a verifier.
- **Parameter regime:** 80 files: 55 holdout (from the repo's `bench/holdout*`) and 25 fresh (14 sandbox command outputs and 11 CSVs from `bench/tmp/csvcorpus`, never used to pick the gate).
- **Boundary:** the gate opens only on files with a table directive and no indentation directive.
- **Not substituted:** lossy compression; Rosetta modes (excluded per instruction); wire-only counts (we bill the decoder contract too); DAEDALUS-only comparisons (AMPHORA is the incumbent).

## 2. Outcome space (B)

- **H+ (achieved, narrow):** on tabular text with generated columns or aligned columns, a deterministic fold plus one fixed arm beats the incumbent. Measured below.
- **H− (not achieved):** a general one-codec gain over AMPHORA across prose, code, JSON, and logs. Measured: JSON indentation folds lose under DAEDALUS; JSON columnar notation loses to DAEDALUS; RAPTOR and REPLAY never beat AMPHORA.
- **H∂ (boundary):** the gate misfires on at least one file (`git-numstat`, +34). The fold's win depends on DAEDALUS's arm, which is wall-clock budgeted.

## 3. Frontier and imported results (C)

- **Incumbent:** AMPHORA (`src/lib/omega/amphora.ts`, previous turn). Per file = min(DAEDALUS, CHIRON-KAIROS) over exact candidates, identity fallback.
- **HYLE** (branch `arena/594be96e-kompkernel`, no open PR): deterministic folds (indent `I`, table `T`, aligned spaces `A`, generated columns `G`) plus an arm search (variant × arm tournament). Its fold certificate is exact (`hyleDecode` round-trip). Imported as-is in `src/lib/omega/hyle.ts`.
- **DAEDALUS** wall-clock budget: `budgetMs = min(20000, 1200 + len·1.1)` (`daedalus.ts`). Output varies with machine load (aapl: 1664 in the z10 run, 1613 in this run; same input).
- **CHIRON** KAIROS work units: deterministic (`KAIROS_WORK_UNITS = 32_000_000`).
- **ONTO** (arXiv 2604.17512, Apr 2026): columnar notation for uniform JSON arrays, 46–51% token reduction vs JSON on synthetic data. **Imported baseline check:** the relevant comparison is vs a strong LZ-grammar, not raw JSON. DAEDALUS on compact JSON already reduces 2,992 → 1,216 tokens (−59%) on real `gh pr list` output. ONTO's gain is mostly captured. Measured: TABLE-T1 (`table.ts`, branch `arena/01a0a3d2`) is identity on pretty and compact JSON, and 2,118 vs AMPHORA 1,233 on the native `gh` output. Negative.
- **Imported result with missing hypothesis:** the Lean-verified OpenAI claims (below) state their verification in Lean; I could not check Lean here.

## 4. Negative space (D): result shapes that look like solutions and fail

Each entry: why it fails, and the test that catches it. Tests are in `bench/z11/`.

1. **Indentation removal on every JSON file.** Fails: DAEDALUS already exploits repeated indentation runs. json-pkg +8.2%, gh-api +0.9% vs AMPHORA in `fold-arm.ts`. Those numbers under-count the decoder prompt (see item 8), so the true losses are larger; the direction holds. Gate rejects I-folds.
2. **Columnar JSON (ONTO-style) as a replacement for DAEDALUS.** Fails: identity on pretty or compact JSON, and +72% vs AMPHORA on the native `gh` output (2,118 vs 1,233). Test: `bench/z11/table-probe.ts`.
3. **Fold + CHIRON (fixed CHIRON arm).** Fails on prose: CHIRON loses to DAEDALUS on 8 of 8 long prose files (z10 receipts, `amphora-verify-long8.jsonl`). `bench/z11/fold-chiron.ts` gives the same direction on the 55 holdout files.
4. **Fold that uses HYLE's O(n) certificate as the only check.** Fails on numstat (+34). Disclosed as the known gate misfire.
5. **Re-using HYLE's fast-mode message total as the cost.** Fails: it bills the raw arm, not the composed message. Test: the composed one-chat count in `bench/z11/kanon-eval.ts`.
6. **Counting the DAEDALUS decoder prompt twice.** This was my bug (`prompt + wire` where the prompt already contains the wire). It inflated KANON by ~1 wire length on fold files (aapl 2380 vs correct 1245). Caught by `bench/z11/acct-check.ts`; fixed; the uncorrected rows are kept in `kanon-eval-*.jsonl` and superseded by `kanon-final-80.jsonl`.
7. **Duplicate arm directive (`Bb;Bc`).** HYLE's fast certificate writes its own `Bb`; appending `Bc` made both appear. Still decodes (last `B` wins) but wastes tokens. Fixed in `kanon.ts`.
8. **Fold-arm numbers from `bench/z11/fold-arm-*.jsonl`.** Under-count the decoder prompt when DAEDALUS does not force it. Superseded. Do not cite them.
9. **TABLE-T1 on pretty-printed JSON.** Identity: the fold never fires because the template is not uniform after whitespace normalisation. Test: `bench/z11/table-probe.ts`.
10. **RAPTOR-T1 and REPLAY-R1 (readable LZ).** Exact on 55/55 but 140k and 143k tokens vs AMPHORA 96k; never beat AMPHORA on any file. Test: `bench/z11/pr-perfile.ts`.
11. **FOLD-F1, PATH-P1, KRASIS, LYSIS, PINAX, STOICHEIA, VEXILLA.** Exact 80/80 each, but output equals the raw total (no gain). Test: `bench/z11/pr-triage.ts` (`pr-triage.jsonl`).
12. **Full HYLE (variant × arm).** Adds arms (CHIRON, GLOSSIA, EIDOS, AION, KIONES) and picks the min. It is a tournament. Not adopted.
13. **PRISM-P1 (`arena/01a09e54`).** Its argmin over prepasses is a tournament by design. Not measured; not adopted.
14. **Starlight family (PR #2).** Wrappers with a 174-token system prompt. Violates the single-chat contract. Negative from the earlier review, re-confirmed by reading.
15. **Cyrillic transliteration, Rosetta leaders** (earlier turns): excluded.
16. **Trusting DAEDALUS's total across machines.** Its wall-clock budget changes the number by up to ~2%. Report with the load caveat.

## 5. Mechanism portfolio (E)

Six mechanism-distinct approaches were tested. Each reports: central construction, artifact, proved portion, unresolved interface, falsification test, local or global.

1. **Deterministic layout fold (HYLE I-fold, indentation).** Construction: `leading whitespace = unit × depth` derived from bracket depth. Artifact: `bench/z11/fold-arm-*.jsonl`. Proved: exact decode (`hyleDecode`). Unresolved: whether DAEDALUS's own repeat detection can be kept while removing indentation. Falsification: fold+DAE vs DAE raw. Result: loses on 2 of 3 JSON files. **Local gap** (indentation is exploited by the arm), not equivalent to the original problem.
2. **Generated-column elision (HYLE G-fold, arithmetic and date columns).** Construction: a column that is an affine or cycle function of the row index costs O(1) directives. Artifact: `csv-9`: `G0="{1+1}"`. Proved: exact decode; blind manual decode of rows 1–4 and 200 matched (n = 1, self-authored). Unresolved: how often real data contains generated columns (2 of 25 fresh files folded; 11 of 55 holdout files had some fold). Falsification: fresh-set count. **Local.**
3. **Aligned-space table fold (HYLE A/T-fold).** Construction: padded CLI columns re-emitted as field positions. Artifact: `psql`, `df-h`, `kubectl`. Proved: exact. Unresolved: generalisation to unseen CLI tools (0 of 14 fresh ops files folded). **Local**, lane-specific.
4. **Columnar JSON notation (TABLE-T1).** Construction: schema once, data many. Artifact: `bench/z11/table-probe.ts` output. Fails against DAEDALUS. Falsification: measured. **Equivalent to the original problem's LZ-grammar baseline; does not extend it.**
5. **Readable LZ and path factoring (RAPTOR, REPLAY, PATH).** Construction: copy spans and nested-path factoring. Artifact: `pr-perfile-55.jsonl`, `pr-triage.jsonl`. Fails against DAEDALUS on all 55 files. **Subsumed by DAEDALUS.**
6. **Cascade over partition (PRISM).** Not measured. Tournament by design. **Not adopted.**

## 6. The shipped codec: KANON (F, G)

Construction (`src/lib/omega/kanon.ts`):
1. Run HYLE's deterministic fold certificate (`fast: true`, no arm search).
2. **Gate:** open only if the directives include a table fold (`T`) and no indentation fold (`I`). Otherwise AMPHORA.
3. Fold path: body = folded text; arm = DAEDALUS (one encode). Wire = `¦<dirs>;Bc\n<DAEDALUS wire>`. Decoder = `hyleDecode` (HYLE's verified unfold; arm `c` = shared CHIRON reader).
4. Accept only if `decode(wire) = input` and the one-chat message is below identity; else AMPHORA.

Artifacts: `bench/z11/kanon-final-80.jsonl` (80 rows; one per file), `bench/z11/kanon-eval-*.jsonl` (raw shard output, includes the buggy rows; superseded for the 10 fold files), `bench/z11/kanon-fold-fixed.jsonl` (9 fixed fold rows), `bench/z11/csv9-only.txt`.

**Measured (o200k, one chat, all exact):**

| set | files | KANON | AMPHORA | delta |
|---|---:|---:|---:|---:|
| all | 80 | 124,960 | 126,300 | **−1,340 (−1.06%)** |
| holdout | 55 | — | — | −962 |
| fresh (not used to pick the gate) | 25 | — | — | −378 |
| gate-open lane | 10 | 8,940 | 10,280 | **−1,340 on lane, −13.0%** |

Per gate-open file: psql −129 (−32.5%), aapl −368 (−22.8%), vix −254 (−18.2%), kubectl −78 (−18.1%), dump.sql −114 (−15.4%), df-h −44 (−15.7%), csv-9 −350 (−13.2%), csv-5 −28 (−5.7%), markdown −9 (−3.9%), **git-numstat +34 (+1.7%)**. The other 70 files are byte-identical to AMPHORA.

Dominance: KANON is better on 9 of 80 files, worse on 1, equal on 70. So it is **not strictly Pareto-superior file-by-file** (numstat). It is Pareto-superior on the tabular lane in total, and never worse in total.

## 7. Second-order adversary (G) on KANON

- **A1, arm nondeterminism:** DAEDALUS's budget changes the body encoding. Measured: aapl 1664 vs 1613 on two runs. The exactness check still holds (verified at encode time). Size can drift ±2%.
- **A2, gate misfire:** numstat's `T\t8-399+G1` costs 34 more tokens after DAEDALUS. The gate uses only HYLE's O(n) estimate. Disclosed; not fixed.
- **A3, quantifier order / hidden assumption:** the gate assumes that a table directive is always cheaper after DAEDALUS. False for numstat. The encode-time exactness check is the guard for correctness, not for cost.
- **A4, adversarial generator:** a generated column that matches a pattern in one file and not in others. Guard: `hyleDecode(wire) === input` is checked before accepting. Falls back to AMPHORA.
- **A5, decoder-prompt double count:** the bug I made (see §4.6). Guard: the accounting test in `acct-check.ts`; the final receipt counts contract once.
- **A6, readability:** the HYLE directives are read by the LLM. Tested by hand on csv-9 (n = 1, self). The DAEDALUS body is a CHIRON-family macro grammar. I did not verify by hand that an LLM can decode it without help. **Not verified.**
- **A7, global compatibility:** KANON uses AMPHORA as its fallback, so non-fold files are unchanged. Global total is never worse than AMPHORA on the 80 files.
- **A8, limiting regime:** tiny inputs. The fold path is gated by `messageTokens < inTokens`, so tiny inputs fall back to identity or AMPHORA.

## 11. What we missed (Q)

- **Baseline first.** Most "new" columnar and LZ ideas are already captured by DAEDALUS on real data. Checking the incumbent on real files before building saves a whole branch.
- **The gain is in the generator, not the grammar.** HYLE's real insight is that a generated column costs O(1) tokens. The gate only fires when the data has one. Coverage is the limit, not the mechanism.
- **Latency is an unoptimised metric.** AMPHORA and KANON cost 20–80 s per document, because DAEDALUS runs a wall-clock search. HYLE's certificate runs in milliseconds. A fold-only codec that skips the search would be fast but loses the arm gain.
- **Output tokens.** The RCT shows that cutting input can raise total cost via output expansion. Our wires are read by the model, so the model's reasoning output may change. Not measured.
- **Decoder-side competence as a resource.** HYLE treats the LLM's formatter and arithmetic as free. This is correct only where the decoder is reliable. Arithmetic beyond small counters is not verified.
