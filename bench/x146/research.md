## Compression / representation searches
Fresh terms included `token compression reversible text morphology tokenizer vocabulary`, `grammar compression string attractors substring complexity bidirectional macro schemes`, and `JSON nested string compression escaping serialization`.

1. **Schmidt et al., Tokenization Is More Than Compression**, EMNLP 2024, pp. 678–702, DOI 10.18653/v1/2024.emnlp-main.40. Primary ACL page fetched. PathPiece finds a minimum-token segmentation for a given vocabulary; the paper reports that fewer tokens do not automatically improve downstream performance across its trained-model experiments. This is NOT an inference-time codec for a fixed chat tokenizer: our endpoint retokenizes emitted text. [1](https://aclanthology.org/2024.emnlp-main.40/).
2. **Navarro/Urbina, L-Systems for Measuring Repetitiveness**, CPM 2023, DOI 10.4230/LIPIcs.CPM.2023.25. Primary DROPS metadata/abstract fetched. Model: a non-erasing morphism φ, axiom s, depth d, coding τ and output-prefix length n determine w=τ(φ^d(s))[1:n]. Description size and substring complexity can separate on constructed families; NU-systems combine morphisms and bidirectional copying. This does not imply gains on our prose, BPE prices or native reader. [3](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.CPM.2023.25).
3. **Kempa/Prezza, At the roots of dictionary compression: String attractors**, STOC 2018. Search extracted primary DTU PDF text; full paper not replayed. For a finite string T, an attractor is a set of positions crossed by some occurrence of every distinct substring. A size-γ attractor supports an O(γ log(n/γ)) bidirectional parse (log capped below by a constant at the boundary γ≈n). k-attractor optimization is NP-complete for k≥3. Neither the objective nor the computational/access model is our billed native prompt. [2](https://backend.orbit.dtu.dk/ws/files/151671611/stoc18main_p125_p.pdf).
4. **Amazon Redshift nested JSON serialization**, primary documentation fetched. It documents parsing nested JSON strings into inline values to avoid escapes. That establishes ordinary serialization prior art, not a new compression theorem. Importantly, changing a string to an object changes the value type and does not preserve original bytes. EKDYSIS instead transmits a quoting instruction and accepts only exact serializer spellings. [1](https://docs.aws.amazon.com/redshift/latest/dg/serializing-complex-JSON.html).
5. `compress-json` and a 2023 .NET escaping article were search leads only; no guarantees imported. Binary JSON deduplication and serializer safety options are different contracts from basic-chat reconstruction.

## Repository novelty boundary
Audited related source headers/logic: JSON-ESCAPE-FOLD (five punctuation escapes, not a complete string layer); CIRCE (HTML/numeric entities and selected percent encodings); EPISTLE (quoted-printable); GRAMMA (layout outside string contents); PROBOLE/ROSETTA (record templates/typed notation); PYKNOSIS (alphabet recoding); SCALAR (surrogate-safe grammar state specialization). EKDYSIS's complete serialization-layer inverse, including root-layer powers, was not found in that scoped search. This is a new repository implementation, not a claim that humans never considered dequoting or that every module was formally proved nonequivalent. Its primitive is standard JSON serialization.

## Causal transfer
The useful transfer is verification discipline, not a borrowed miraculous compression algorithm: bind claims to actual source bytes and actual emitted messages; distinguish challenge from solution, program from behavior, default build from special targets, and a bounded experiment from a universal theorem. Independent Python and gpt-tokenizer checks implement that discipline here. The missing clean-chat native gate remains missing.
