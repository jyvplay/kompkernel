# X69 — DIORTHOSI: version deltas, with an honest negative result

## Runtime honesty
Used Node v22, TypeScript compiler, esbuild, npm dependencies, shell, Git/GitHub CLI, and live web search. There were no independent agents, external LLM decode trials, Lean runs, database queries, or simulator runs. Search results are not proof verification. We do not claim to have reviewed all published AI math results or discovered a terminal codec.

## Contract / hypotheses
Input is a JavaScript UTF-16 string (for well-formed UTF-8 text this preserves the text's encoded bytes); arbitrary byte sequences are not accepted as bytes. Output is one self-contained chat message. Count `o200k_base` tokens on the full message, not only payload. Compare with the *same source* TAGSTACK parent set plus SIBLING-TEMPLATE; this is not a registry-wide tournament. Exact code-unit equality is mandatory, including delimiters, whitespace, CR and JSON escaping. For the admitted 3–128 versions, <=80,000 units, <=2,000 lines, equal line count, and literal LF---LF separator, decoder applies independent patches to version 0; elsewhere return the parent. For every admitted source, deterministic inverse equality must hold; success on a particular lane additionally requires a complete parent gate and strict token reduction. Wall-clock and CPU are distinct metrics.

H+: a narrow lane could beat this parent set; H−: no lossless code can compress every possible input under a finite alphabet length measure (pigeonhole principle); H∂: gains depend on source structure, tokenizer and complete contract. We require a full same-source comparator and exact inverse before claiming a token win. We have not met that threshold. Counting alone says nothing about LLM fidelity.

## Mechanism and verification
DIORTHOSI is an in-band version-delta codec, not a new compression primitive. Each version independently patches a shared base, so errors do not accumulate across versions. A local greedy isolated-token choice selects full-line or prefix/middle/suffix patches; the full-message gate decides emission. Nested contracts and entropy coding are deliberately avoided. Both the encoder and decoder are implemented in `src/lib/omega/diorthosi.ts`, registered under `diorthosi`, with a direct in-band contract.

Reproduction: `npm ci`, then `npx esbuild bench/x69/test.ts --bundle --platform=node --format=esm --packages=external --outfile=bench/x69/test-run.mjs && node bench/x69/test-run.mjs`. The seeded unit test exercised 1,000 constructed strings containing CR, tabs, emoji, quote/backslash, NUL and unpaired surrogates, and malformed patch cases. This checks algorithmic round trips, not UTF-8 byte preservation of unpaired surrogates. A separate Python inverse (`crosscheck.py`) reproduced one Unicode case, not a broad independent test. `npx tsc --noEmit --pretty false` passed. Full-gate scripts `experiment.ts` and `experiment2.ts` can be built similarly; receipts record synthetic version histories generated from an existing KB article. These are constructed stress cases, not naturally occurring held-out version histories.

Initial line-replacement design was exact but lost 848 vs 665 tokens; it was repaired with substring edits and its tests rerun. The repaired sparse-edit case loses 883 vs 665 tokens (`experiment-receipt.json`). The heavily edited stress case in `experiment2-receipt.json` is exact but loses 3915 vs 1350 tokens. A fallback returns the smaller parent. No new Pareto size or speed winner is claimed. No full-suite speed improvement is claimed. No external LLM was tested: a printed rule is not evidence that an LLM natively decodes reliably, particularly with UTF-16 indexing and long outputs. One-shot accuracy needs independent blind model trials against exact expected bytes, including Unicode and large messages.

## Six candidate mechanisms / falsification
1. Independent version delta (implemented above): executable, inverse tested; missing a strict gated win and independent reader test. Cheapest: version-history corpus with full-message parent comparisons; gap is local to lane.
2. Shared repeated edit across versions: represent one change operation applied to multiple lines; concrete extension to patch grammar. Need collision-checked applicability and exact ordering; attack variable offsets/Unicode. Cheapest is token-count synthetic screen followed by full gate. Local.
3. Transpose frame fields (PROBOLE, X67): executable with checked JSON inverse; measured labels +239 and commits +255. Attack parent context loss. Gap is local.
4. Token-surface aliases (FOTAR, X65): executable inverse; ops lane 1080 vs 885, prior receipt `bench/x65/receipts/fotar-fullgate.json`. Attack alias/table overhead and boundaries. Local.
5. Entropy coding with a language-model prior: published lossless byte coding, but binary arithmetic decoder and matching model state violate single-message direct-read constraint. Cheapest falsification: blind chat restoration with no tool. Gap is the core access model.
6. Memoize repeated searches (ENGRAMMA, X68): executable with replayed work counts, prior cold measurements 1.04–1.40x on specified lanes, unchanged message bytes. Attack unaccounted budgets and order effects; re-run cold processes. Local speed lane, no token claim.

## Negative space: 15 failure shapes and detectors
1. Payload-only savings: count entire header+payload. 2. Character savings: count actual BPE tokens. 3. Smaller than raw but larger than parent: full same-source gate. 4. Compare different sources: hash input. 5. Incomplete comparator: require frontierComplete. 6. Rely on hidden table: decode serialized message in fresh process. 7. Lose whitespace: byte/code-unit compare. 8. Unicode normalization: adversarial combining and surrogate cases. 9. Escape canonicalization: escaped/literal JSON tests. 10. Implicit ordering: duplicate/out-of-order index rejection. 11. Accumulating patches vs independent patches: mutate one version and check all others. 12. An in-band description mistaken for LLM reliability: held-out blind LLM trials. 13. In-process speed gain from cache warmth: counterbalanced cold processes. 14. Treat synthetic version history as a natural corpus: label provenance. 15. Global novelty from a partial search: cite prior art and limit claim. Modal shortcut is comparing compressed payload to raw input: contract and the already strong parent can exceed the advertised saving; detect it by serializing the complete message and counting it against all required same-source parents.

## Live research and math boundary
Wollmer et al. (2023), https://journals.riverpublishers.com/index.php/JWE/article/view/22327, describes cross-entity delta compression using previous browser assets, not in-band chat decoding. Deletang et al., *Language Modeling Is Compression*, ICLR 2024, https://proceedings.iclr.cc/paper_files/paper/2024/file/3cbf627fa24fb6cb576e04e689b9428b-Paper-Conference.pdf, combines probabilistic models and arithmetic coding; those results assume a shared model/decoder, not this one-chat model. Neither result proves DIORTHOSI superior or model-readable.

OpenAI and Anthropic's 2026 claimed subexponential SAT results were located through live search, but not rebuilt or validated here; a source audit notes the OpenAI formal bound is weaker than its manuscript bound, https://github.com/MoralityLabAI/EvalMath/pull/10; Anthropic's scope and machine-model qualifications are described at https://github.com/jkbennitt/math-release-atlas/pull/21. These claims remain under review, not imported as theorems. Even a valid asymptotic SAT result would not itself supply a practical readable codec. Google's AlphaProof/AlphaGeometry announcement https://deepmind.google/blog/ai-solves-imo-problems-at-silver-medal-level/ concerns formal competition mathematics, not lossless direct-chat compression. No comprehensive review of all frontier labs was performed.
