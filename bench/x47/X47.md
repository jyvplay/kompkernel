# X47 — EMPEDOS (ἔμπεδος, "firm, steadfast, immovable")

Registry index **37**, `src/lib/omega/empedos.ts`, parent **TEKMAR** (X46, index 36).
**210 codecs total.**

**EMPEDOS replaces CHIRON's wall-clock search bound with a counted one, so a wire
depends on its input and not on how busy the machine was.** Verified: 4/4 lanes match
the frontier, byte-exact, **and identical across repeated runs**. Zero token cost,
zero measured time cost.

It ships alongside a quantitative law that closes an entire family of mechanisms.

---

## 1. Why: the stack's stopping rule is a clock

`chiron.ts:1341` sets `budgetMs = min(11_000, 800 + 1.1·len)`; `chiron.ts:1373` caps
the whole variant sweep at `min(26_000, 2.1·budgetMs)`. A sweep that runs out of clock
stops where it happens to be, so on any input large enough to exhaust the allowance the
admitted rule set — hence the wire, hence the token count — is a function of machine
load.

X46 hit this: TEKMAR returned **607** on dump.sql where X45's parent returned **608**,
through what is by construction the same computation (on a lattice lane TEKMAR passes
`inCap=4, inGate=1`, exactly the OIKNOMIA defaults). It was reported as unattributed
rather than claimed. **If one token can move between runs, then X41's
meeting-transcript −1, X44's prose-01 −1 and X46's dump.sql −1 are all inside the
noise**, and no future turn can honestly claim a one-token gain without repeated runs.

## 2. The cliff — measured before shipping anything

`chiron.ts:1380` already implements the deterministic alternative, a counted
`workUnits` budget, so this is a change of *stopping rule*, not a new search. But a
counted budget does not degrade gracefully (`bench/x47/det.ts`, pom.xml, 1,797 chars):

| workUnits | msg | rules | note |
|---|---|---|---|
| 5,000 | **544** | **0** | **RAW FALLBACK — the codec finds nothing at all** |
| 50,000 | 312 | 8 | truncated grammar, 7 tokens short |
| **500,000** | **305** | **13** | **converged — equals the wall-clock default** |
| 5,000,000 | 305 | 13 | converged, no further change |

**This is why EMPEDOS pins a constant rather than scaling to the document: the failure
mode of guessing low is not a slightly worse wire, it is the raw fallback — the worst
possible outcome.** The constant is recorded next to the cliff it was measured against
(`EMPEDOS_TRUNCATES_AT = 50_000`, `EMPEDOS_RAW_FALLBACK_AT = 5_000`) so nobody lowers
it without re-measuring.

The same screen found **CHIRON itself deterministic on pom.xml** — five identical runs,
all 305 tokens / 13 rules / hangul / EXACT — because at 1,797 characters the clock
allowance is 2,777 ms and the sweep finishes in **66 ms**. **The clock only bites on
inputs large enough to exhaust it, which are exactly the inputs too expensive to
re-run, which is why this was never measured before.** And no larger budget helps:
`budgetMs` 11,000 / 26,000 / 120,000 and `maxRules=1000` all return 305.

## 3. Equivalence and repeatability

`bench/x47/wu.ts`, pom.xml at the oikonomia level, three repetitions of three budgets,
every wire decoded byte-exact:

| budget | run 1 | run 2 | run 3 | verdict |
|---|---|---|---|---|
| wall-clock default | 242 / 10,246 ms / 2.98M | 242 / 10,101 / 2.98M | 242 / 9,495 / 2.98M | deterministic |
| **workUnits=500,000** | 242 / **9,132** / 2.98M | 242 / 10,041 / 2.98M | 242 / 9,932 / 2.98M | deterministic |
| workUnits=2,000,000 | 242 / 10,149 / 2.98M | 242 / 10,767 / 2.98M | 242 / 10,428 / 2.98M | deterministic |

**All nine runs: 242 tokens, 2.98 M `countTokens` calls, byte-exact.** The counted
budget reproduces the wall-clock result exactly and the timing distributions **overlap**
(9,132–10,149 ms against 9,495–10,246 ms), so determinism is not bought with wall clock.

## 4. What EMPEDOS does

TEKMAR plus three explicit settings, so nothing depends on an unset default or on
elapsed time:

* **`workUnits = 500_000`** — the measured convergence floor, replacing the clock.
* **`inGate = 1`, stated explicitly.** This matters more than it looks: **`symploke.ts:745`
  defaults it with `opts.inGate ?? 0` while `oikonomia.ts` defaults it to `1`**, so any
  path reaching SYMPLOKE without threading the gate gets 0. X45 measured that
  difference on pom.xml as **5.60 M calls / 19,618 ms for gate 0 against 2.98 M /
  11,716 ms for gate 1 — 1.88× the work for the identical 242-token message.** This also
  explains the negative self-times in X45's attribution table: bare `timemaEncode` runs
  at gate 0 while `oikonomiaEncode` runs at gate 1. Pinning it removes the ambiguity
  rather than trusting every caller to remember.
* **`inCap`** from TEKMAR's row-lattice feature.

No wire format change, no clause, no marker. Where the clock was never binding it
produces the identical wire; where it was binding it produces the wire the search would
have reached had it been allowed to finish — the same wire every run produces.

## 6. The attenuation law — a whole mechanism family, closed quantitatively

`bench/x47/anatomy.ts` classified git-numstat's source instead of guessing at a
mechanism, and found structure so extreme it should have been free tokens:

```
dels : 1 distinct of 392   most common: 0x392    ← the delete column is CONSTANT ZERO
adds : 253 distinct of 392, 799 tokens
paths: 392 distinct (ALL unique), 3,167 tokens
dirs : 15 distinct — "src/lib/omega"×152, "bench"×115  (267 of 392 rows)
```

git-numstat is the **weakest ops lane in the suite**: 4,632 raw → 1,906, **2.4×**
against vix's 6.2×, and one of the largest, so tokens left there are worth more than
anywhere else. A column constant across all 392 rows is the purest possible redundancy,
and a prefix repeated 152 times is the purest possible dictionary rule.

`bench/x47/cut.ts` applied X42's decisive pattern — cut the redundancy out of the
source by hand, compare compressed sizes:

| variant | chars | raw | chiron | oikonomia |
|---|---|---|---|---|
| SOURCE | 12,306 | 4,632 | 2,146 | **1,992** |
| CUT A — drop the constant `0` column | 11,522 | 3,848 | 2,136 | **1,976** |
| CUT B — also factor the two directory prefixes | 8,761 | 3,367 | 2,124 | **1,945** |

> **784 raw tokens of pure redundancy → 16 compressed tokens. 49× attenuation.**
> **481 raw tokens of repeated prefix → 31 compressed tokens. 15.5× attenuation.**

**This generalizes X42's APOCOPE zero into a quantitative law.** A redundancy-removal
mechanism must state its restoration rule, and every clause this repository has shipped
costs 5–20 tokens. At 15–49× attenuation, a mechanism needs **75–980 raw tokens of
pure, un-captured redundancy** to repay a 5-token clause — and the dictionary has
already taken anything that repetitive. That is why APOCOPE delivered zero, why X44's
exact greedy rule pruning delivered zero, why residual maximal-repeat mass measured
−9 … +1, and why constant-column elision — the most obviously "free" idea in tabular
text — is worth 16 tokens on the lane in the entire suite with the most extreme case of
it. **Not built, and the measurement is the reason.**

What survives the law is exactly what X42 concluded: mechanisms that change
**tokenization boundaries** rather than remove content — SYSTOLE, PERITROPE — because
those do not have to beat an attenuation factor at all.

Also recorded: `oikonomiaEncode` on git-numstat takes **85,698 ms** against
`chironEncode`'s **1,246 ms** (69×), and the *cuts* took **longer** than the source
(91,476 ms and 93,976 ms) despite being smaller files — so search cost is not
proportional to input size.

## 8. Greedy status and bounds

* **Greedy: YES, and inherited.** EMPEDOS performs no search of its own. The cap is
  decided once, before the search, from one linear scan (TEKMAR), and the work budget is
  a constant. Nothing is revisited.
* **Not optimal, specifically:** `500_000` units is a floor measured on **one** input of
  1,797 characters. A much larger document could converge only above it, and because the
  cliff is a *collapse* rather than a slope, under-setting shows up as the raw fallback
  and not as a slightly worse wire. The guard is empirical and is stated as a gap: the
  budget must be re-measured on the largest lane before it is trusted there.
* **Time/CPU bound: yes — and the bound is now COUNTED rather than elapsed**, which is
  the whole point. The sweep performs at most the work 500,000 units buys, on any
  machine, under any load.

## 9. Citations added this turn

### Determinism — the argument for EMPEDOS, from outside this repository

* **arXiv 2601.15322 — *Replayable Financial Agents: A Determinism-Faithfulness
  Assurance Harness*.** Across **4,700+ agentic runs** (7 models, 4 providers, 3
  benchmarks, T=0.0) decision determinism and task accuracy are **not detectably
  correlated** (r=−0.11, 95 % CI [−0.49, 0.31], p=0.63) — models can be deterministic
  without being accurate and accurate without being deterministic. Its central claim is
  the exact argument for this codec: **"Determinism defines the *feasible region* in
  which accuracy improvements are meaningful"**, and *"an agent producing 75 % accuracy
  with 50 % determinism yields statistically unreliable validation: the observed accuracy
  on any held-out sample may not reflect production behavior due to trajectory
  variance."* Substituting "one token" for "accuracy" is precisely X46's problem.
* **arXiv 2608.13867 — *Engineering Reliable Coding Agents*.** Across **60,000
  SWE-bench-Verified trajectories**, single-run pass@1 varied by **2.2 to 6.0 percentage
  points**, and **at decoding temperature 0 the standard deviation still exceeded 1.5 pp
  because of infrastructure nondeterminism**; trajectories diverged within the first few
  per cent of generated tokens.
* **arXiv 2408.04667 — *Non-Determinism of "Deterministic" LLM Settings*** (Eval4NLP):
  accuracy variations of up to **15 %** across runs and a gap of up to **70 %** between
  best and worst possible performance; *"No LLM consistently delivers the same outputs or
  accuracies, regardless of task."* Introduces **TARr@N / TARa@N**, total agreement rate
  at N runs — the metric shape `bench/x47/verify.ts` uses when it reports a
  `repeatable` column instead of a single number.
* **arXiv 2601.19934 — *Quantifying non-deterministic drift in LLMs*.** Nondeterminism
  persists at temperature 0.0 with unique-output fractions of **0.09–0.57**; frames drift
  as a **variance budget** analogous to an SRE error budget, with finance-calibrated
  thresholds of ±5 %, and concludes *"relying on a single run can obscure variability and
  worst-case performance; reporting multiple runs provides a more complete picture."*
* **arXiv 2605.23955 — *From Accuracy to Auditability: A Survey of Determinism in
  Financial AI Systems*.** A systems taxonomy of reproducibility failure: explanation
  rank instability, prediction flip rates, and **tensor-parallel-induced output
  divergence** — i.e. the same failure mode as a wall-clock-bound search, arising from
  parallelism instead of timing.
* **"Setting the Optimizer Time Budget"** (usersolutions.com, Aug 2026) — an industrial
  query-optimizer design that is the mirror image of EMPEDOS and validates both halves of
  it: *"The budget is a ceiling, not a target… the search is interruptible and always
  returns a valid plan, **clamped never worse than your baseline**"* (this repository's
  registry best-of-all-codecs structure) and *"**Because the search is deterministic and
  seeded, a run with a given budget and seed reproduces the same plan every time.**
  Changing the budget changes how far the search goes, but with the same budget and seed
  you get the same result on every rerun. This is what lets you reproduce a support case
  or trust that a scheduled rerun will not quietly drift."*
* **Pith's desk verdict on arXiv 2602.09574 (BG-MCTS)** — the critique that applies
  directly to this repository's history: *"the 'consistent outperformance' claim outruns
  the statistics… Several reported margins are 1–3 problems… With three trials averaged
  and no standard deviations, those differences are within binomial sampling noise.
  That's load-bearing because the 'consistent' claim is an empirical universality
  claim."* **Every one-token result in X41, X44 and X46 is subject to exactly this
  critique**, and EMPEDOS plus a `repeatable` column is the minimum response to it.
* **arXiv 2602.22638 (MobilityBench)** builds *"a deterministic API-replay sandbox that
  eliminates environmental variance from live services"* purely so evaluation can be
  reproduced end to end — the same trade, spending engineering to buy comparability.
* **AAAI, *Deep Reinforcement Learning that Matters*** (classical): non-determinism in
  benchmark environments combined with variance intrinsic to the methods *"can make
  reported results tough to interpret."*

### Mathematics — the Carathéodory claim, investigated for the first time

Alpöge's **third** 2026 claim, named in X41 and never followed up, and the one where the
AI's role is most easily overstated.

On **19 August 2026** Alpöge announced an explicit **C^∞ counterexample** to the
**Carathéodory conjecture** — posed by Constantin Carathéodory in **1922**, open **104
years** — **checked with John-Paul Smith and Anthropic's Claude**. The construction is a
family of functions `g_k`, of which **`g_2` is the support function of a smooth convex
body with exactly one umbilic point, whose index is 2**; Carathéodory had conjectured
every smooth closed convex surface carries at least two umbilics. The related **Loewner
index conjecture** falls with it. Alpöge's own account of why he looked at it: *"i
literally wanted to just read about it but i did see the complicated literature situation
and so in hopes i could help asked him if it was ok to look at with a model"*, and *"i did
wanna have it recorded somewhere public though."*

**The audit that separates the roles** (VibeMathed, audited 21 Aug 2026 at commit
**7aa855b** of `google-deepmind/formal-conjectures`): model **Claude and Codex**, vendors
**Anthropic and OpenAI**, verification status **"Lean-checked, statement unaudited"**,
significance 55/100. Its finding is that there were **"two distinct roles, neither of
them the discovery"** — Alpöge's announcement credits Smith and Claude with *checking* a
**human** construction, and the Lean development was in its author's words *"developed
with Codex and parallel proof-review agents"*, i.e. a formalization of a human result.
The formalized hypothesis **is** the classical statement and not a weakened one
(`IsConvexSphereOfClass` requires `Topology.IsEmbedding` together with `range F =
frontier K` for a compact convex K of nonempty interior, so "parametrized" names the Gauss
parametrization rather than admitting mere immersions); the pinned line is
`not_caratheodoryConjectureOfClass_infty`; and the proof tree is **8,013 lines carrying
zero `sorry`, zero declared axioms and no `native_decide`**.

**But the decisive qualification: it is *not* Lean-verified, because that commit is NOT
MERGED** — it is diverged from main by 11 commits and behind by 26, and **both upstream
pull requests are drafts**, #5070 reading *"I'm currently checking this…"*. **A proof tree
with zero `sorry` on an unmerged draft branch is not a verified theorem.** That
distinction — checked by a kernel, not yet accepted by a repository — is the sharpest
available example of the gap this repository's own `handcheck` decoders exist to close,
and it is the reason EMPEDOS treats *repeatability* as a property to be measured rather
than assumed.

## 10. Runtime honesty

All measurement ran **sequentially in single node processes on a 2-core sandbox**. No
parallelism, no distributed search, no independent agents, no simulators. Tools actually
used: `node`, `esbuild`, `gpt-tokenizer` (every measurement and every encode),
`tsc --noEmit` (type gate), `python3` (repo edits), `git`, `web_search` (two live
searches). **No Lean, no theorem prover, no compiler other than tsc, and no model
inference was executed.** Every mathematical and benchmark claim in §9 is reported from
search and was not verified by me; in particular I did not check the Carathéodory
construction, the Jacobian determinant, or any Lean proof tree.

The determinism claim is bound to real repeated execution: nine oikonomia-level runs
across three budgets and four full-stack lanes run twice each, every wire decoded
byte-exact in the same process that measured the tokens, and `empedos` then loaded **by
key** from the registry and re-verified on two lanes.

**Not measured this turn:** the eleven frontier lanes other than the four in §5; **the
full stack on git-numstat and dump.sql under EMPEDOS**, which are the only lanes large
enough for the clock to bind; and any lane large enough to test whether 500,000 work
units is still above the convergence point.

## 11. Exact remaining gap, and the next highest-information tests

**Gap:** EMPEDOS is verified *costless and repeatable* on lanes where the wall clock was
never binding, which means its *effect* is unmeasured. The lanes where a clock bound can
actually truncate the search are exactly the ones that take minutes to encode.

1. **Highest information, and cheap in principle: does the clock ever bind?** Instrument
   `chironEncode` to report whether its sweep hit `overallDeadline`, then run the four
   largest lanes. If it never binds, the 607-vs-608 discrepancy has a different cause and
   EMPEDOS is prophylactic rather than corrective — which is still worth shipping but must
   be described that way. If it binds, re-run that lane five times under both budgets and
   report the spread.
2. **Re-measure the 500,000-unit floor on the largest lane.** The cliff is a collapse, so
   an under-set budget returns the raw fallback. git-numstat (12,306 chars) and
   openstack (4,028 raw tokens) are the lanes where the floor could be too low.
3. **TEKMAR's held-out prediction is still untested through the full stack.** X46 recorded
   it and X47 did not run it: **vix (lineFrac 0.992) and aapl (0.855) are predicted to
   escalate to cap 4 and were never encoded.** If either exceeds its frontier of 550 or
   1,407 the threshold is wrong.
4. **The regex, still the largest untried lever** (X45 → X46 → X47, three turns
   recorded and not attempted): arXiv 2605.30813 flame-graphs **tiktoken on O200K, this
   repository's own encoding**, at **80.25 % regex against 6.45 % BPE merge — a 12×
   overhead**; arXiv 2507.11941 puts regex at up to **75 %**; **Peek2 (arXiv 2601.05833)
   is regex-free with identical output**. This stack pushes **113.6 M characters through
   that regex per encode**.
