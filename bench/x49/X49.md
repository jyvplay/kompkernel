# X49 — KOLUMN: exact column laws for bounded delimited text

**Status:** added to the registry as `kolumn`, marked `deep` because the inherited full-frontier encode is expensive. **Fidelity:** local byte-exact UTF-8 reconstruction on valid UTF-8 inputs. **Strict win:** one fresh complete-message lane, `metrics.tsv`, by one o200k token. This is not a general prose or ops win and not a registry-wide tournament.

The implementation is `src/lib/omega/kolumn.ts`. Reproducible artifacts are under `bench/x49/receipts/`; the existing X48 verifier and red-team receipts remain under `bench/x48/receipts/` because the X48 implementation was staged there before the X49 addition. No native LLM decoding, hidden prompt, system skill, external tool, or side-model decoding was run. The emitted contract is in-band and designed for one-chat reading; actual LLM-native decoding remains unverified.

## Formal model and quantifier order

Let \(\mathcal D\) be valid UTF-8 strings within the structural caps that contain a literal header and at least eight rectangular, unquoted data rows, with at least two columns separated by comma, tab, pipe, or semicolon. Quoted CSV, embedded record newlines, ragged tables, and inputs outside the caps are outside \(\mathcal D\) and are refused. Bytes are compared after UTF-8 encoding; no normalization is allowed.

For a complete in-band message \(m\), let

\[
  C(m)=\operatorname{countTokens}_{\text{o200k\_base}}(m).
\]

For each fixed input \(x\), define the measured comparator set \(P(x)\) as the same-source TAGSTACK runtime parent set—SYNKRISIS, eligible BIFRONT, KANON, AKOLOUTHIA-2, APOGRAPHE, DIASTEMA, eligible METRON/HEMERA—plus SIBLING-TEMPLATE. The scope is deliberately **not** the full registry. Let

\[
  F(x)=\min_{p\in P(x)} C(m_p(x)).
\]

The encoder enumerates a KOLUMN transform and two KOLUMN message forms (direct and APOGRAPHE-composed). It emits the lowest-cost exact candidate only if it strictly beats \(F(x)\); otherwise it returns the lower-cost measured TAGSTACK/SIBLING parent. The code-level gate invariant is:

\[
  \forall x\text{ on which the parent measurements complete},\quad
  \operatorname{emitK}(x)\Rightarrow D(m_K(x))=x\ \land\ C(m_K(x))<F(x),
\]

and a declined candidate returns a measured parent message, so its cost does not exceed that parent minimum. This is an implementation invariant conditional on the measured parent implementations and token counter, not a paper proof or registry-wide Pareto theorem.

The quantifier order matters. A strict win on one fixed lane establishes **\(\exists x\)** in this declared corpus. It does not establish **\(\forall x\)** over prose, ops listings, tables, markup, all files, or future prompts. Likewise, every lane must be remeasured against the actual applicable frontier before saying that KOLUMN is locally Pareto-superior there. The fresh repeat below reconfirms the metrics frontier, not the other lanes.

### H+, H−, and H∂

- **H+ (structured redundancy):** real rectangular telemetry/tables with repeated values, duplicate columns, small cycles, or arithmetic/time progressions may amortize the grammar and contract over enough rows. Falsifier: exact candidates fail to beat the complete-message frontier on held-out files. Evidence: one strict win on `metrics.tsv`; not a general claim.
- **H− (ordinary text / irregular records):** short prose and irregular or structurally incompatible files will not benefit; KOLUMN should refuse or fall back without loss. Falsifier: a complete-frontier prose/ops win from KOLUMN. Evidence so far: ordinary prose is refused; `find-listing` and `ls-full-iso` are refused; the separate casefold token-cost probe loses on all 68 files (+20,605 aggregate tokens). These are limited samples, not a universal impossibility proof.
- **H∂ (overhead boundary):** even highly structured data may sit on the one-token boundary after the full contract and parent composition. Falsifier: a fresh same-source frontier repeat changes the relevant parent cost or the candidate fails exactness. Evidence: `metrics.tsv` is 209 versus 210, then a fresh frontier repeat again measures 210. A one-token margin is real under this counter, but fragile and not a practical compression ratio claim.

## Mechanism and decoder contract

KOLUMN preserves the header literally, detects and preserves LF versus CRLF and the final-EOL bit, and replaces only the data rows. It refuses quoting, raggedness, empty records, unsupported separators, marker collisions, short tables, and inputs above its caps. Its in-band contract names the selected marker characters and only the grammar operators that actually occur in the message.

Each column independently selects one descriptor:

- `L`: literal values;
- `C`: one repeated value;
- `R`: a zero-based reference to an identical earlier column;
- `Qp`: a period-`p` value cycle;
- `T`: canonical UTC ISO date or whole-second timestamp with a fixed millisecond step from the first value;
- `Dk`: fixed-scale decimal integers represented as first value plus signed running deltas;
- `Gkxp`: first fixed-scale value plus a period-`p` cycle of signed deltas;
- `Pk`: fixed-scale arithmetic progression from base and step.

Date parsing validates calendar round-trips, the UTC `Z` spelling, and exact whole-second input; numeric modes use `BigInt`, not binary floating point. Scale mismatches, leading-zero spellings, negative zero, and exponent notation fall back to literal mode so that textual spelling is not silently normalized. The decoder checks framing, row/column counts, legal mode parameters, safe timestamp arithmetic, and exact reconstruction for encoder-produced messages. This is not an authenticated format: a syntactically valid tampered delta can decode to a different table; no checksum or tamper-detection claim is made.

### Greedy/search status

The parser checks the four supported separators and selects the rectangular interpretation with the most columns (ties follow the fixed separator order). Within each column, the encoder performs deterministic bounded enumeration of eligible descriptors. It token-counts each descriptor under o200k, chooses the lowest-cost descriptor, and uses a deterministic mode-name tie break. Columns are optimized independently; this is **not** a globally optimal joint code search. Period candidates are enumerated only up to 64.

After transformation, the encoder compares only two KOLUMN message candidates: direct and APOGRAPHE-composed. The complete contract-plus-wire count decides between those candidates; exactness is checked before emission; and the strict gate compares the winner against the same-source measured TAGSTACK/SIBLING floor. No raw-wire proxy decides shipping. The no-regression fallback is part of the codec.

### Time / CPU bound

The local planner has hard structural caps: 100,000 UTF-16 code units, 10,000 data rows, 32 columns, at least 8 data rows, and period at most 64. Descriptor search is bounded by rows × columns × the fixed period cap, plus bounded BPE tokenization of each descriptor. This is a finite deterministic work bound for the local transform, not a wrapper-wide latency bound.

There is **no global CPU/wall-clock cap around the inherited frontier tournament**. The fresh `metrics.tsv` full gate took 371,789 ms total: TAGSTACK 352,416 ms, KOLUMN call 19,363 ms. The dedicated frontier repeat took 340,988 ms. These observed times are environment/load measurements, not production latency guarantees. KOLUMN is therefore marked `deep` and excluded from ordinary audit sweeps.

9. **`find-listing`:** not rectangular under the delimiter grammar; refused.
10. **`ls-full-iso`:** not rectangular under the delimiter grammar; refused.
11. **Ordinary English prose:** not a table; refused, not counted as a zero-cost KOLUMN win.
12. **Quoted CSV / embedded-quote values:** refused because raw splitting would not be sound.
13. **Ragged rows:** refused rather than padded, truncated, or normalized.
14. **Table below eight data rows:** refused; the contract overhead is not waived.
15. **Input above 100,000 code units:** refused by the planner cap.
16. **Mixed decimal scales:** delta/progression candidate is not used; exact literal representation remains.
17. **Leading-zero numbers:** not parsed as canonical fixed decimals; preserved literally.
18. **Negative zero:** not mapped to integer zero; preserved literally.
19. **Exponent spelling:** `1e3` is not normalized to `1000`; preserved literally.
20. **Invalid ISO calendar value:** timestamp descriptor is rejected by the decoder round-trip check.
21. **Fractional-millisecond timestamp step:** not represented by `T`; rejected.
22. **Missing close marker / illegal header-column count / scale overflow:** malformed streams are rejected.
23. **Valid-looking delta tamper:** decoder can produce a different table rather than detect corruption. KOLUMN has no checksum/authentication and does not claim tamper detection.
24. **Assume comma delimiter:** modal-shortcut test changes a semicolon stream to comma and the decoder rejects it.
25. **Assume LF:** changing CRLF to LF changes reconstructed bytes.
26. **Assume final newline:** changing the no-final-EOL case changes reconstructed bytes.

Items 9–26 are parser/decoder adversaries, not full-frontier measurements. Red-team pass means the expected refusal/exactness property occurred; it does not turn a failed or refused candidate into a compression win.

## Structure-specific adversaries and repair re-gates

- **Delimited tables:** quoted fields, embedded newlines, empty/ragged records, duplicate-separator ambiguity, marker collisions, a header with a different number of fields, and a final-EOL flip. The implementation refuses the unsupported quote/ragged domains and preserves the observed separator/EOL/trailing-EOL bits. The seeded fuzz corpus constructs rectangular mixed columns; it is generated, not a real-world holdout.
- **Numeric columns:** decimal-scale changes, leading zeros, negative zero, exponent notation, values beyond Number precision, malformed BigInt literals, delta mutation, scale overflow, and descriptors with a wrong number of fields. `BigInt` and literal fallback preserve text spelling; a valid-looking mutation can still change the output, as documented above.
- **Time columns:** leap-day crossing, impossible calendar dates, invalid UTC spellings, fractional steps, large timestamps, and steps that leave the supported date range. Calendar round-trip and safe-integer checks fail closed.
- **Modal shortcuts:** delimiter, LF/CRLF, and final-EOL assumptions were each independently falsified by a semicolon/CRLF/no-final-newline fixture. Each wrong assumption either rejects or changes bytes; the correctly declared wire reconstructs the exact fixture.
- **Markup, code, prose, shell listings:** these were not silently coerced into tables. Ordinary prose is refused; `find-listing` and `ls-full-iso` are refused; the Markdown table and AAPL table are exact transforms but larger than their raw files before the full envelope.

After the final contract edits, the transform red team was rebuilt and run: **234 checks = 34 authored checks + 200 deterministic seeded table cases; 0 failures; all 200 planned fuzz wires were exact**. Receipt: `bench/x48/receipts/kolumn-redteam.json`. The suite covers parser/transform/inverse only; the full-message frontier gate is separate. The `metrics.tsv` gate is exact, count-consistent, frontier-complete, strict, and no-regression. The fresh frontier repeat is exact and complete and remeasures 210. No all-lanes rerun was performed; the prior all-lanes command timed out after VIX.

## Prior art and novelty boundary

This is a text-codec composition, not a new universal compressor. The exact use of an in-band one-chat contract and the repository-specific strict gate is the implementation contribution; no compression-theory novelty or universal novelty is claimed.

Relevant adjacent work:

- [PAX: Weaving Relations for Cache Performance](https://research.cs.wisc.edu/multifacet/papers/vldb01_pax.pdf) groups values of the same relational attribute together within database pages. It is columnar layout, not this in-band text grammar.
- [Gorilla](https://www.vldb.org/pvldb/vol8/p1816-teller.pdf) compresses timestamps with delta-of-delta and floating values with XOR; KOLUMN's UTC progression is adjacent, not a new timestamp-compression idea.
- [PForDelta / PFOR](https://doi.org/10.1109/ICDE.2006.150) uses patched frame-of-reference/delta coding for integer sequences; KOLUMN's signed integer deltas are not novel in isolation.
- [ALP](https://doi.org/10.1145/3626717) losslessly maps decimal-origin floating values to integers with exact-correction techniques; KOLUMN instead parses explicit decimal text with `BigInt`, preserving textual spelling by refusing noncanonical cases.
- [Pcodec](https://arxiv.org/abs/2502.06112) is a lossless numerical-sequence codec using mode decomposition, delta coding, and binning.
- [FLEA](https://doi.org/10.1145/3802063), published in May 2026, is particularly close prior art for periodic lossless time series: it uses frequency-domain components, residuals, and rate-optimal search. KOLUMN's bounded small-cycle descriptors are far less general and are not claimed to supersede it.

Fresh search found this close prior art; it was not a complete novelty search. Do not claim that periodic coding, columnar coding, delta coding, arithmetic progression coding, or the general idea of a text reader contract is new.
