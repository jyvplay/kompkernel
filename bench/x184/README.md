## New artifact

`src/lib/omega/kartes.ts` implements **KARTES: Cartesian-tree shape/preorder-field
separation**. It creates a priority-induced tree over arbitrary ASCII-space
fields, sends its child flags and preorder labels, and reconstructs by inorder
traversal. Empty fields, CRLF, tabs, Unicode and other characters remain exact.
It is not a renamed BST dictionary (KLADOS), tableau (PINAKAS), or JSON traversal
(STOIBAS). Classical Cartesian trees are prior art; all-stack semantic novelty is
not certified. The decoder instruction, shapes, values and parent are all paid.

The decisive theoretical trap is tested: two different increasing sequences have
the same Cartesian shape. An RMQ compression theorem does NOT let us omit their
values. Neither that theorem nor this code establishes native LLM decoding.

## Verification and speed

Tests include exhaustive ternary field sequences through length8, empty fields,
Unicode transport, malformed flags, child arity, unary chains, frame/output caps,
independent Python reconstruction, and a separate recursive Cartesian oracle.
The six-family adversary includes structural attacks and Boolean acceptance-gate
tests; those logical tests are not empirical native trials.

The speed candidate uses streaming regex token-count scans, with contiguous
coverage guards and the tracked-tail path unchanged. It is bundle-only. A real
Node CPU profile found countLongRaw at10.47% self time on KB (one profiled run,
not a general theorem). Count/vector/merge/stream differential gates were rerun
on both arms after fixing the attack harness's treatment of literal special
spellings. Full-stack six-lane ABBA decides promotion; no inference from the
profile or microtests alone.

codec. It isolates whether the reordered field stream helps the parent at all.

**Next highest-information test:** audit the canonical parent wires' residual
literal costs and test one locally invertible change on those residuals before
any further whole-document reordering. Require a free-instruction ablation to

claim. Full-stack speed needs a different profiled optimization; do not promote
this streaming loop or relabel its small per-lane wins as a general speed gain.
