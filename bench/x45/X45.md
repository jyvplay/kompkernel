## 1. What was built

SYNKRISIS has two distinct exact folds behind one measured gate.

1. **WORD-CANON.** Match one of the public canonical text entries by its first
   three words, flatten the matching body to a word stream, and compute an LCS
   word diff against the source. Each hunk becomes a short, unique
   old-phrase → new-phrase edit. The message also carries the exact line word
   counts, sparse indentation, EOL kind, final-EOL bit, and untouched prefix /
   suffix. Thus lexical edits and whitespace layout are separate channels:
   rewrapping does not turn each line into a literal replacement. The contract
   names the public standard by ID; the catalogue is not sent as a private
   decoder table.
2. **MULTI-COPY.** For three or more exact standard MIT blocks with the same
   body and the same literal separator, send the differing copyright-line
   values once each. The decoder inserts each into standard MIT line 3 and
   joins the blocks with the declared separator.

A candidate is emitted only if the library decoder reconstructs the input
exactly and the **full** message costs strictly fewer o200k tokens than
ARCHETYPON's exact prior-best message. Otherwise the codec returns that parent
message unchanged. In particular, an attractive transform on the raw text is
not sufficient: the contract and wire are both charged.

## A. Formal model and exactness argument

### A1 — Objects and message model

Let `x ∈ UTF8*` be the source string and `e ∈ {o200k_base, cl100k_base}`.
The one-chat encoder emits `(contract, wire, y)`, where `y` is the decoder's
reconstruction. The measured resource is

```text
M_e = countTokens(contract + "\n" + wire, e)
```

for a nonempty contract, and `countTokens(wire, e)` for the identity form.
No system prompt, skills file, tool, retrieval call, or second message is
available to the reader. The code-side public-text catalogue is an encoder
measuring instrument; an actual bare reader must know the named public text
from its own memory. That availability is empirical, not an axiom.

### A2 — WORD-CANON decoder algebra

For canonical entry `c`, let `W(c)` be its whitespace-split word sequence. The
wire payload is

```text
(id, prefix, edits, layout, indents, eol, final, suffix)
```

where `edits` is a list of unique phrase substitutions, `layout[i]` is the
number of words on output line `i` (`0` denotes a blank line), and
`indents` is a sparse map from 1-based line number to leading ASCII spaces.
The decoder computes:

```text
w := apply_each_unique_phrase_edit(W(c), edits)
body := join_eol(repartition(w, layout, indents), eol)
if final: append eol to body
output := prefix + body + suffix
```

The encoder obtains candidate hunks by LCS, searches up to ten words of context
for a phrase unique in the current sequence, then re-applies the phrase edits.
It discards the candidate unless that result equals the target word stream.
The decoder also checks the layout sum, ranges, duplicate indent lines, and
message/output bounds. Finally, the complete decoded string is compared to the
original source before the candidate may be priced or emitted. This is a
constructive exactness argument with an explicit end-to-end equality gate; it
is **not** a Lean-checked theorem.

### A3 — MULTI-COPY decoder algebra

Let `T` be the repository's standard 21-line MIT template and let `v₁,…,vₖ` be
nonempty single-line values. For the declared separator `s`,

```text
D(v₁,…,vₖ) = T[line 3 := "Copyright (c) " + v₁] + s + ...
              + T[line 3 := "Copyright (c) " + vₖ] + LF
```

The encoder accepts only exact source blocks matching that template and exact
separator, and compares the constructed result byte-for-byte with the source.
The decoder rejects malformed count/value shapes rather than guessing.

### A4 — Gate and quantifier order

For every measured lane `x`, let `P(x)` be ARCHETYPON's byte-exact prior-best
one-chat message. SYNKRISIS returns either `P(x)` unchanged or a candidate
`S(x)` satisfying both

```text
D(S(x)) === x
M(S(x)) < M(P(x))
```

This gives `M(S(x)) ≤ M(P(x))` for the shipped result on each measured lane.
The guarantee is **relative to ARCHETYPON**, not to every local codec. If the
parent itself fails exactness, the implementation uses raw identity as its
fallback rather than blessing an inexact parent.

### A5 — Parameter regime and resource bounds

- Source text: at most 40,000 JavaScript characters.
- Word-canon: at most 800 words and 800 layout lines; at most 12 LCS hunks and
  32 changed words; only LF or CRLF, consistently. Tabs, repeated interior
  spaces, and trailing spaces in the folded region are refused, not normalized.
- Catalogue scan: 50 public `kind: text` entries (57 total catalogue entries).
  Each anchored candidate has at most 800 × 800 word-LCS cells. The worst-case
  LCS work is therefore bounded by 50 × 800² cells, plus bounded phrase-context
  and layout work.
- Repeat arm: 3–25 blocks, each differing only at the declared MIT copyright
  line; each value is at most 2,048 characters; the complete source is still
  subject to the 40,000-character cap.
- Decoder: messages over 100,000 characters, arrays beyond the stated caps,
  and reconstructions over 40,000 characters are returned unchanged.
- Token tolerance: ±0. Byte equality tolerance: ±0.

The SYNKRISIS scan is **CPU-bounded**, with no wall-clock cutoff of its own.
The total API call is dominated by the inherited ARCHETYPON/APOGRAPHE floor.
Under production settings, DAEDALUS uses a wall-clock budget
`min(20,000 ms, 1,200 + 1.1 × inputChars)`; under `OMEGA_DET=1` that clock is
frozen and the inherited search runs to its natural end. Do not read the
measured benchmark wall time as a production latency bound.

### A6 — What the construction is not

It is not byte-level compression (the reader needs a natural-language message),
not ordinary lossy prompt shortening, not a hidden lookup-table protocol, and
not a general-purpose word dictionary. It relies on the reader knowing a
named, public canonical license text. If that memory/version assumption fails,
the message can be undecodable to that reader even though the repository's
public-table reader is exact. The from-memory decodes in §H are evidence for two
specific texts and one current assistant, not a universal model guarantee.

## D. Negative space — 20 near-solutions that do not qualify

1. **General English prose.** The five held-out prose items all retain the
   parent M. The word-LCS mechanism has no template to name there.
2. **Operational timestamp listing.** `find-listing` is 1,267 at the X45
   parent and 1,140 under DIASTEMA. The codec is exact but not the local leader.
3. **Git log output.** `git-log-fuller` remains 143; no word-canon fire.
4. **Single MIT/ISC file.** Existing parametric references already cost 33–52
   on sampled real licenses; SYNKRISIS does not beat ARCHETYPON in the X44
   comparison.
5. **Flask's double-space BSD-3 rendering.** The word parser refuses repeated
   internal spaces; it stays exact at parent M 296 rather than normalizing
   whitespace and corrupting bytes.
6. **Mixed LF/CRLF within one source.** `detectEol` refuses the word arm;
   there is no silent newline normalization. The red team checks this boundary.
7. **Tabs in a folded line.** The word layout alphabet does not encode tabs;
   refusal is safer than pretending a space is equivalent.
8. **Trailing spaces.** They are not dropped. The candidate is refused rather
   than losing them.
9. **Bare CR line endings.** Only homogeneous LF and CRLF are supported.
10. **Custom or project-specific licenses.** PostgreSQL remains at parent 262;
    no general canonical title is inferred from similar prose.
11. **More than 12 lexical hunks.** Candidate creation stops; no huge patch is
    serialized in hope that its token price is favorable.
12. **More than 32 changed words.** Same refusal; the bound is an exact scope
    cap, not a claim that larger diffs cannot be represented.
13. **More than 800 words or layout lines.** The word arm does not attempt an
    unbounded quadratic LCS or decoder output.
14. **More than 40,000 source characters.** The public-canon arms decline.
15. **Ambiguous old phrase.** Phrase edits require a unique match in the current
    word sequence; duplicate occurrences are not guessed. Red-team mutation
    with an absent phrase returns the malformed message unchanged.
16. **Repeated MIT values beyond 25, or below 3.** The repeat arm fails closed;
    the supported shape is bounded and tested, not a generic run-length codec.
17. **Multiple differing MIT lines.** The repeat arm recognizes only the
    declared line-3 hole; any other changed line breaks the exact match.
18. **A separator or copyright value containing embedded line breaks.** It
    cannot be encoded as a single value; the candidate is refused.
19. **A codebook title without the expected canonical bytes.** A model with a
    different license rendering cannot decode the parametric reference; the
    contract does not prove the reader has the right version.
20. **Oversized/adversarial JSON.** Message length, edit count, word count,
    layout size, indent size, value size, and reconstructed output are capped;
    mutations beyond those limits return unchanged instead of allocating an
    unbounded expansion.

The red-team receipt contains the executed malformed-payload cases. Items 6–9,
11–14, and 16–20 are also format boundaries enforced by the encoder/decoder;
not every boundary is a separate benchmark lane.

## G. Second-order adversary A(C)

- **A(phrase edit):** an attacker changes a phrase so it appears zero or two
  times. Decoder rule: every old phrase must occur exactly once; otherwise the
  whole candidate returns unchanged. The red team mutates a real old phrase to
  an absent phrase and checks fail-closed behavior.
- **A(layout):** an attacker sends 801 layout lines, a 40,001-space indent, a
  non-integer word count, or a layout sum inconsistent with the edited words.
  Decoder rule: reject before line expansion; output length is checked against
  40,000. Over-limit layout and indent payloads are in the red-team receipt.
- **A(repeat):** an attacker sends too few or more than 25 values, empty values,
  embedded CR/LF, or a changed MIT line outside slot 3. Decoder rule: exact
  template/slot/count checks, else return the input message unchanged.
- **A(marker collision):** source text itself contains `SYNKRISIS/WORD`. The
  encoder only emits if its complete candidate is read back as the source; a
  marker collision that makes the reader select the wrong suffix therefore
  fails the round-trip gate.
- **A(canon drift):** a public license rendering changes between the model's
  remembered version and the named source. The codec cannot repair this by
  assertion. The independent table reader and source equality gate identify
  the repository's version; an LLM whose remembered text differs may fail.
- **A(codebook side channel):** remove the canonical table, contract, or exact
  public title. The output is no longer a valid one-chat reference. SYNKRISIS
  does not count an unmentioned hidden table as free information; its one-chat
  contract names the public text, and the direct model-decode receipt only
  supports the two tested messages.
- **A(token accounting):** make the contract expensive enough to erase the
  wire saving. Every candidate's `M` is counted on the concatenated actual
  contract and wire. No proxy estimate or raw-wire-only count is used.
- **A(parent selection):** compare only against a weak identity arm. The parent
  itself measures the shipped frontier and ANAGNORISIS; however, X45's safety
  predicate is still explicitly only `M ≤ ARCHETYPON`, not every specialized
  local leader. `find-listing` is the concrete counterexample to a broad
  Pareto claim.
- **A(compute):** adversarial input expands the quadratic core. Input, words,
  template count, hunk count, output size, and repeat count have caps. The
  inherited parent remains the expensive component; its production wall-clock
  budget and measurement-mode natural end are disclosed in §A5.

## I. Live research and individual review of recent AI-assisted mathematics

Searches on 2026-10-26 used new queries for word-stream deltas, system-prompt
codebooks, proof-repository correction histories, and first-party lab results.
The cited papers and preprints are from 2018–2026 (all within ten years); older
standards are marked as prior art, not as recent literature.

### I1. Compression literature and design boundary

- **Lossless Prompt Compression via Dictionary-Encoding and In-Context
  Learning** (arXiv:2604.13066, March 2026) hierarchically finds repeated
  whitespace-delimited sequences and checks that dictionary overhead does not
  exceed token savings. Its LLM-facing protocol places the dictionary in the
  **system prompt**; that is outside this task's one-chat/no-system-prompt
  constraint. Its reported template decompression results are useful adjacent
  evidence, not a byte-exact one-chat precedent.
- **Lossless Token Sequence Compression via Meta-Tokens** (arXiv:2506.00307,
  2025) uses token-ID subsequences, adds special meta-token vocabulary, and
  fine-tunes the reader. It reports 27%/18% sequence reductions on its two
  tasks. That is a different reader/model setup from a native text-only message.
- **Text-Preserving Lossy Text Compression** (arXiv:2605.29000, 2026) deletes
  information and relies on LLM reconstruction; it is explicitly lossy and
  does not satisfy SYNKRISIS's byte-equality predicate.
- **VCDIFF, RFC 3284** is established byte-level ADD/COPY/RUN delta coding.
  It is relevant prior art for exact differencing, but its binary delta is not
  itself the human-readable one-chat LLM protocol here. SYNKRISIS does not claim
  to invent word diffs, dictionary encoding, or lossless delta coding.

### I2. OpenAI — the proof corpus and the Navier–Stokes announcement

- The OpenAI `math` repository's **8 October 2026 history** records three
  withdrawals following a sign error in a stabilization-trace cancellation

### I8. Review rule applied across all of the above

A Lean-accepted artifact verifies its formal statement under the proof assistant
and imported axioms; it does not by itself show that a natural-language paper
was translated faithfully or that a database's intended question was captured.
The Navier–Stokes and Aletheia examples make that boundary concrete. Conversely,
a mismatch in one formal estimate does not by itself refute a separate
natural-language argument. This report preserves those distinctions and makes
no claim of local Lean/Isabelle verification or independent expert review.
