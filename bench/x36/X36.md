# X36 — ἀναδίπλωσις ANADIPLOSIS

**Date:** 2026-10-21/22. **Branch:** `arena/f9c95c13-kompkernel`.
**What shipped:** one new codec, `anadiplosis`, registered at position 26 of
`src/lib/omega/registry.ts` immediately after `syncope`, byte-exact through the
registry `run` path. It takes `vix-daily-1990.csv` from 1195 to **594**, a
**−601 token (−50.3%)** cut, with **no lane regressing**.

---

## A. Executive summary

Every dictionary codec in this stack compresses the same resource: some span of
the text occurs more than once. All of them are indifferent to **where** the
second occurrence sits. That indifference is their strength, and it is also what
they pay for: every rule must be *defined* in a glossary before it can be *used*,
and the definition is charged against the saving.

ANADIPLOSIS compresses the case the dictionary is worst at — a span that repeats
**immediately**. Such a span needs no glossary entry at all. It needs a count.

```
dictionary:    §α=17.240000,¶  … α α α α         (1 definition + 4 uses)
anadiplosis:   ⟦4⇤17.240000,⟧                    (1 copy + 1 count)
```

This is run-length coding, but applied at the **span** level rather than the
character level, which is what lets it pay on text where no single character ever
repeats.

## C. Formal model

**1. Admissible objects.** A document `D` (a finite string), and a wire `W` such
that some stated procedure maps `W` back to `D` exactly.

**2. Information/access model.** The decoder is a frontier LLM receiving `W` in a
single chat input box. No system prompt, no skills file, no tools, no state
beyond `W`. It may perform character substitution, positional insertion, and
counted copying — operations that are exact under a stated rule. It may **not** be
asked to perform arithmetic beyond small counting, and it may **not** be asked to
guess.

**3. Resource counted.** `countTokens(W, o200k_base)` — real BPE tokens, not an
estimate.

**4. Success / failure, with quantifier order.** A codec succeeds on a lane iff
`∃` a wire `W` such that `decode(W) = D` byte-for-byte **and**
`tokens(W) < tokens(parentWire(D))`. It is *shipped* iff, additionally, `∀`
lanes in the measured set, `tokens(W) ≤ tokens(parentWire(D))` — i.e. no
regression anywhere is a precondition for shipping any gain anywhere.

**5. Parameter regime.** Documents 10²–10⁵ characters; English prose, source
code, logs, CSV/TSV, SQL dumps, markup. o200k_base pretokenizer:
`\p{L}+` (letters, unlimited), `\p{N}{1,3}` (digits, **capped at three**),
` ?[^\s\p{L}\p{N}]+` (punctuation runs), `\s+`.

**6. Adjacent problems that must NOT be substituted.**
- *Classical RLE* (character-level runs) — different: here the unit is a span of
  any length, and character-level runs are nearly absent from these corpora.
- *LZ77 back-references* — different: LZ needs an offset, which an LLM cannot
  reliably count; a count of *adjacent* copies needs no offset.
- *Entropy coding* — inaccessible: LLM inference is not byte-deterministic
  (arXiv 2505.06297, 2601.10678 PMATIC).
- *Semantic / lossy compression* — excluded by the fidelity requirement.

| # | approach | central idea | artifact | outcome |
|---|---|---|---|---|
| 1 | **Span-level run-length** | adjacent repeats need a count, not a definition | `bench/x36/grle.ts` | **SHIPPED** |

## F. The positive result in detail

### F.1 Measurement

`bench/x36/rle.ts` scans every lane for runs of identical adjacent fields:

```
vix-daily-1990.csv   ","  runs=126  chars=2520
every other lane           (none)
```

`bench/x36/grle.ts` generalises from *fields* to *any adjacent repeated span*
and measures end to end:

```
lane                     parent    GRLE    delta
vix-daily-1990.csv         1195     579    -616
npm-ls.txt                  940     925     -15
aapl-2014.csv              1452    1452       0
git-numstat.txt            1992    1992       0
find-listing.txt           1267    1267       0
openstack-loghub-26.log     898     898       0
dump.sql                    608     608       0
kb-article.txt              622     622       0
```

With the contract clause charged, the shipped codec delivers **vix 1195 → 594
(−601)** and npm-ls falls back to 0.

### F.2 The orthogonality arithmetic

Let `u` = tokens of the unit, `k` = number of adjacent copies, `OV` = framing
overhead (5).

| scheme | cost | saving |
|---|---|---|
| dictionary rule | `u + k` | `(k-1)·u − k` |
| run-length span | `u + OV` | `(k-1)·u − OV` |

Equal at `k = OV + 1`. For any unit worth naming (`u ≥ 2`), run-length wins
whenever the copy is **short-lived**. The dictionary pays a definition to buy
reuse; here there is no reuse to buy.

**Corroboration in the literature.** The local/global split is standard:
RLE targets *local* repetition, dictionary coding targets *global*
([learnlyai.co.uk](https://learnlyai.co.uk/en/high-school/a-level/ocr/computer-science/3-exchanging-data/run-length-encoding-and-dictionary-coding)).
Columnar-database engineering makes the same point from the other side —
dictionary encoding "can't do anything about runs of that same ID repeating
across many consecutive rows"
([CedarDB](https://cedardb.com/blog/encoding_vs_compression/)). Classical LZ77
length–distance pairs do subsume RLE
([Wikipedia](https://en.wikipedia.org/wiki/LZ77_and_LZ78)), but an LLM decoder
cannot count an offset, so here the two must be **separate instruments** — which
is the non-obvious part of this result.

### F.3 Wire form — and the failure that fixed it

The first implementation put the count **after** the unit: `⟦X⟧⇤k`. It
round-tripped on toy input and then died on real text with
`RangeError: Invalid string length`, because in a numeric corpus the digits of
`k` run into the digits that follow and the parser reads `12345` for `12`.

Shipped form — **count first, unit last**:

```
OPEN <count> MARK <unit> CLOSE        ⟦4⇤17.240000,⟧
```

The parser reads a bounded digit run to the first MARK, then everything to the
next CLOSE is the unit. No unit can contain a framing character, because the
encoder always slices from the **original** text (`applyAll`) rather than from a
string it has already rewritten.

### F.4 Selection — the threshold must be in tokens

The first rule accepted any span whose elision exceeded **6 characters**. That is
a character-space estimate of a token-space cost, and it erred exactly where it
matters:

| threshold | dump.sql | find-listing | npm-ls |
|---|---|---|---|
| in characters | **+73** | **+35** | **+24** |
| in tokens | **0** | **0** | −15 |

Accepted only when `(k−1)·tokens(unit) − OV ≥ 3` **and** `tokens(unit) ≥ 2`.
The second condition is load-bearing: **a unit costing one token can never pay for
its own framing**, however many times it repeats.

## G. Second-order adversary: the strongest attack on each candidate

**A(#1 span-RLE): "the dictionary already does this."** Refuted by arithmetic
(§F.2) *and* by observation: the parent has already run its full dictionary
search and still leaves four copies of the price field standing in the tape.
Detection test: `bench/x36/tape.ts` prints the tape; if the repeated span were
being handled, it would not be there.

**A(#3/#4 glyph re-layout): duplicate assignment.** The first annealer reported
−72 / −43 / −33 — and every one was an artefact. It chose pool slots **without an
injectivity constraint**, and CHIRON's `chironParseTape` rejects any wire where a
glyph character repeats (`used.has(glyph)`), so those wires were undecodable.
Enforcing injectivity drove the gain to **exactly 0** on all three lanes.
*This is the most important negative result of the turn: a 276-token "ceiling"
computed from run-merge statistics is unreachable, because the merge graph of the
pool is far too sparse (polyglot: 3 420 merging pairs among 802² = 643 204
candidates, 0.53%) to embed a real adjacency graph into.*

**A(#1): marker collision.** If a document contains `⟦`, `⟧` or `⇤`, the reader
cannot distinguish an emitted span from ordinary text. Guarded: the plan returns
`null` if any framing character occurs in the source.

**A(#1): runaway expansion.** A malformed count would make `unit.repeat(k)`
explode. Guarded: `k ≤ 100 000`, `k ≥ 2`, and `p·k ≤ |text|`; plus the round-trip
check runs **before** anything is emitted.

**A(all): regression.** Guarded by the measured gate — the transform ships only
if the full re-encoded message is strictly smaller.

### The generalisation boundary, stated without softening

**Zero of the ten prose-representative lanes have moved under any codec in this
stack, across four turns.** Measured, not asserted (`bench/x35/ttok.ts`): the
prose tape is 71–75% ordinary word tokens at ~5 characters/token, which **is** the
natural o200k rate for English. Every mechanism here attacks repetition, alphabet
pricing, or format; ordinary English has no exploitable surplus of any of the
three at that rate.

The ops contrast (`bench/x36/runs.ts`) is what makes those lanes winnable —
glyph runs are 32–63% of the tape and cost 1.36–1.79 tokens per run, i.e. they
are **not** merging:

| lane | tape tok | glyph runs | glyph chars | tok/run | merge ceiling |
|---|---|---|---|---|---|
| vix-daily-1990.csv | 989 | 350 | 850 | 1.79 | 276 (27.9%) |
| npm-ls.txt | 578 | 140 | 444 | 2.02 | 143 (24.7%) |
| git-numstat.txt | 1511 | 514 | 803 | 1.28 | 146 (9.7%) |
| kb-article.txt | 553 | 146 | 245 | 1.13 | 19 (3.4%) |

§G records why that ceiling is **unreachable** by glyph re-layout. It remains the
largest single measured headroom in the system and the most promising direction
for a future turn — but only via a mechanism that changes the *run structure*, not
the assignment.

## K. Negative space — result shapes that look like solutions but are not

1. **Duplicate-glyph wires** — tokenise better, decode to nothing. Detected by
   `chironParseTape` returning null; test: `anadiplosisRoundTrip`-style
   round-trip on every lane.
2. **Character-space gain thresholds** — accept spans that lose tokens (+73
   dump.sql). Test: measure in tokens.
3. **Un-delimited counts** — parse `12` as `12345`. Test: run on a numeric corpus.
4. **Units containing framing characters** — nested spans. Test: slice only from
   the original text.
5. **Field-level RLE** — a special case of span RLE; keeping it would narrow the
   codec for −43 tokens on one lane.
6. **Trailing-zero elision** — the dictionary already owns it.
7. **Padding elision** — under 10 surviving occurrences.
8. **Block/template structure** (X35) — provably redundant with the dictionary.
9. **Cross-script glyph search** (X35) — all 8 scripts tie.
10. **Min-cost segmentation** (X35) — greedy already optimal, 0/60 words improve.
11. **15× search budget** (X35) — identical output; mechanism-limited.
12. **Digit re-spelling** (X35) — digits are the *worst* alphabet at 1.49 c/tok.
13. **Post-grammar tape arbitrage** (X35) — shape collapse removes the payload.
14. **Arithmetic / base conversion** — LLM-infeasible; only positional and counted
    operations are admissible.
15. **Entropy coding** — LLM inference is not byte-deterministic.
