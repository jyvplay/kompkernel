# X159 — KLIMAX: hierarchical outline-label reconstruction

Experimental optional codec, not a default TAGSTACK change. KLIMAX means
“ladder”; it is not an acronym. Its mechanism is a bounded hierarchical
counter vector (Dewey-label differential coding), not a new theorem of
compression. Results must be read from final receipts, not inferred from raw
screens. Native-chat decoding is NOT_RUN.

## A–F: formal objects, access, costs, quantifiers and boundaries

Let D be UTF8-transport-stable strings of at most50000 UTF16 code units. Split
on literal LF; preserve every byte-equivalent source character, including CR,
form feeds, Unicode, page headers and final-LF presence. Recognize only line
prefixes after ASCII spaces and optional1–6 Markdown hashes plus one space.
A literal number is1–12 dot-separated positive decimal components, each1–6
digits with no leading zeros, followed by optional trailing period then
space/tab/end-of-line (CRLF included). Nonmatching lines remain literal and do
not update state. A preexisting @ at an eligible prefix causes planner refusal.

The state is initially an empty vector. Literal numbers replace the vector.
For an emitted @D:
- if D=len(state)+1, append1;
- otherwise require1<=D<=len(state), truncate to D components and increment
  the last component, refusing overflow past999999.
Emit the canonical dot-joined vector, preserving the original period and all
surrounding text. The encoder emits this operation only when it reproduces the
literal number exactly and that number has more than two characters. Otherwise
it transmits a literal reset. Depth is not inferred from indentation or font.

The encoder sees the complete source and tokenizer; the decoder receives only
the complete in-band key and parent message. No source, prior chat, skills.md,
external dictionary or training is a decoder input. `klimaxRead` takes a
message-only parent interpreter. `klimaxFromFrontier` checks its supplied
incumbent against source, then admits only a byte-exact strictly cheaper full
message. Baseline includes the operational optional chain through ISOSTATHMIA;
BEMATISMOS is separately screened over28 plans and its best raw plan receives
a parent trial on the HTTP outline. This is NOT an exhaustive tournament of all
399 source modules or all optional search configurations.

Price T is the installed o200k count of complete key + parent, including framing.
This is not bytes, characters, entropy bits, payload-only cost or total API bill.
Encoding CPU/wall, decoding work, source bytes and message price are separate
resources. Parent-search latency includes both baseline and transformed calls;
concurrent trial clocks are not an isolated speed comparison.

Software correctness proposition: for every admitted s and generated p,
undo(p.folded)=s. Induct on lines: unchanged lines preserve bytes and state;
literal resets set both states identically; a replaced label is admitted only
if the deterministic vector transition equals that literal; therefore both
states and emitted bytes remain identical. UTF8 stability converts string
identity to source-byte identity. This is a proof sketch plus executable tests,
not Lean verification.

Cost: one deterministic pass, O(n) transform/inverse, <=12 counters, O(n) output
storage. No greedy global search; the local emission rule uses character length,
not a claim of token optimality. One candidate parent encode per admitted plan,
plus measured baseline work. Parent runtime has no newly proved linear bound.

Success quantifiers: on a fixed declared source set and configuration, every
emitted message must independently invert to its source; at least one real
source must save >10 complete tokens versus the measured operational incumbent.
Native behavior needs a separately specified fresh model/version trial. Full
Pareto success additionally requires no runtime regression, with a significant
speed claim requiring >=10% aggregate CPU AND wall improvement and no tested
lane regression. Existence of a token win is not universal efficiency, native
correctness, or full Pareto dominance.

## G: adjacent problems excluded

Semantic summaries; JSON/XML data-model equality; byte compression into opaque
binary; retraining a tokenizer; vocabulary extension; hidden-source decoding;
codebook recall from training; numerical matrix-multiplication complexity;
symbol-length superstring approximation; faster isolated inner loops; reduced
search budgets; cache-warm vs cold comparison; synthetic examples as practical
holdouts; and exhaustive optimal compression are all different problems.

## H: outcome regions and evidence thresholds

H+: finite >10-token source-grounded gain with full pricing; stronger claims
require all additional native/runtime/holdout gates. H−: an observed wrong-byte
candidate, complete-price loss or protected runtime regression rejects that
candidate/claim, not the whole research goal. H-boundary: unsupported readers,
timeouts, source selection, missing native endpoint and untested optional arms.
Those are not passes. All-token-sequence strict shortening is impossible by
finite-alphabet counting (V^n > sum_{k<n}V^k, V>=2); this is NOT impossibility of
improving selected natural texts. No terminal-codec claim follows finite wins.

## Mechanism portfolio and novelty audit

Early alternatives were screened against actual source headers before selecting
KLIMAX. Mathematical font restoration is KALLIGRAPHOS/KALLOS, quoted-printable is
EPISTLE, paired document edits are DIORTHOSI, XML closers already live in TAGSTACK,
and fixed scalar progressions are METRON/APOGRAPHE. They were not renamed.
DENDRON encodes path trees via braces, not ordinal state transitions. BATHMOS
fits sorted ranks; ATHROISMOS integrates driven scalar recurrences;
ISOSTATHMIA uses hunk conservation. KLIMAX instead truncates/extends a variable
counter vector, carrying depth but deleting predictable multi-component labels.
This is a scoped implementation difference, not exhaustive semantic novelty.

noncanonical decimals, line-prefix collisions, overflow, malformed UTF16,
expansion limit, wrong parents and parent failure fallback. Generated sources
are correctness tests, never performance fixtures. `independent.py` separately
implements the vector inverse and reuses X157's Python parent parser; source
files, not encoder decoded fields, are the equality oracle.

Repair: the initial prose key omitted canonical-number bounds; it was expanded.
CRLF standalone-number handling was then aligned with line semantics. All
screen/unit/inverse gates were rebuilt and rerun, and a new attack chains
leading-zero/zero/oversized literal lines before CRLF-only outline numbers.
The first full candidate process started after these fixes. Baseline runs do
not use KLIMAX and are unaffected. No pre-repair candidate is trusted.
