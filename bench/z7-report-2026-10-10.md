## 1. Formal model (for the candidate tested)

- Admissible objects: UTF-8 text `T`. A codec returns `(wire, decoder contract)`; the one-chat message is their
  concatenation, and the reader sees only that message.
- Resource: o200k_base tokens of the whole one-chat message, contract included.
- Success: `∃ codec. (∀ T in lane: exact(T) ∧ cost(codec,T) ≤ cost(incumbent,T)) ∧ (∃ T: Δ > few tokens)`.
  Quantifier order: codec is fixed before the corpus; the universal half is enforced by a tournament over the
  incumbent (never-worse) and an exact decode gate.
- Must not be substituted: lossy schemes, tokenizer retraining, binary/base64 envelopes, model-internal methods
  (activation injection, arXiv 2607.08399), system-prompt dictionaries (arXiv 2604.13066), wire-only accounting.

## 2. Candidate A — KLIMAX (integer arithmetic runs, e.g. index columns and counters)

Idea: replace a maximal run of canonical non-negative integers with constant step `D` and a shared separator `S`
by a sentinel `⟪A:D:N⟫`. Probe: `bench/klimax/probe.ts` (text level, before contract; minimum run length 4).
Receipt: `bench/klimax/receipts/klimax-runs-probe.txt`.

- Files scanned: 210 (43 holdouts + 167 CSV corpus). Files with any run ≥4: 7.
- Files that got smaller: 3 (−22, −4, −2 tokens). Files that got larger: 4 (+14 to +144).
- Total: 79,887 → 80,074 tokens (+0.23%). Before the contract (~29 tokens), so the codec cannot pay for itself.
- Reading: the runs that exist are mostly coincidental numeric patterns inside data columns (dates, survey codes),
  not index columns. The "index column" hypothesis does not hold for this corpus.
- **Dead.** Do not retry in this form.

## 3. Candidate B — NUMLIST (consecutive "k. " / "k) " items replaced by a block marker)

Probe: `bench/klimax/numlist-probe.ts`. Receipt: `bench/klimax/receipts/numlist-probe.txt`.

- Result: 0 blocks of length ≥4 in the 43 holdouts. Numbered lines exist only in short runs (≤4 items; e.g.
  `license.txt`, `gh-prose.txt`, `llm-answer.md`). Probe output checked directly with `grep -rE "^[0-9]+[.)] "`.
- Reading: **not measurable on this corpus**. This is a coverage gap, not a negative result. A corpus with real
  numbered instructions would be needed to test it; no such file is in the holdout set.

## 5. New sources (grounding; not used to build a codec)

- arXiv 2604.13066 (Mar 2026), *Lossless Prompt Compression via Dictionary-Encoding and In-Context Learning*. The
  dictionary goes in the system prompt, which is outside our constraint. Reported exact match above 0.99 on
  template-based log decoding, but average Levenshtein similarity only above 0.91 on algorithmic compression. This
  is the honest bound for in-context decoding: not byte-exact in general. https://arxiv.org/abs/2604.13066
- arXiv 2609.12106 (Sep 2026), Hucke, *A Non-constant Lower Bound for Grammar-Based Compression with Greedy*:
  Ω(log n / log log n) lower bound on the approximation ratio of the global Greedy grammar compressor, for every
  execution with left-to-right occurrence replacement and any tie-breaking. The abstract says the bound is formally
  verified in Lean 4. Not re-checked here (no Lean toolchain). Relevance: CHIRON is a greedy macro grammar. The
  bound is worst-case on an adversarial family, so it does not show a real-corpus loss. Testing that is a next step.
  https://arxiv.org/abs/2609.12106
- arXiv 2602.13266 (Feb 2026), LoPace: Zstd and BPE binary packing for prompt storage. Binary output, so outside the
  readable constraint. https://arxiv.org/abs/2602.13266
- arXiv 2607.08399 (Jul 2026), activation aggregation for prompt compression. Requires model internals, so outside
  the constraint. https://arxiv.org/abs/2607.08399

## 6. Readability (no new evidence this turn)

- No model is reachable from this sandbox. Every readability claim in the repo rests on self-decode by the author
  model, n ≤ 3 per codec. This is downgraded: "decoded correctly by this model on hand-checked fixtures", not
  "verified for LLM readers". 2604.13066 is the reason to keep this downgrade: in-context decoding of algorithmic
  compression reached only ~0.91 similarity.
