## 1. One-chat reporting: fixed (structured channel)

**Problem.** `one-chat=N` was only in free-text notes. 41 of 136 keys never emit it. Notes were parsed with a regex. For the 16 keys that do emit it, the note sometimes carries it on only some files (e.g. `icarus`: 12 of 53 rows). So "16 admissible keys" was an artifact of which branch a wrapper took, not a property of the codec.

**Fix (code, committed in this turn).**
- `src/lib/omega/registry.ts`: `Entry.run` may return `oneChat?: number`; `CodecRun` gains `oneChatTokens: number | null`; `measure()` (now exported) sets `oneChatTokens = r.oneChat ?? (r.output === text ? inTokens : null)`. Identity output is the raw message, so its one-chat cost is the raw count. Anything else with no reported contract is `null` and inadmissible.
- All 50 entries that previously emitted `one-chat=${r.messageTokens}` now also pass `oneChat: r.messageTokens` (mechanical, verified: 50/50). The two wire-only `omega_xi` rows get `oneChatTokens: null`.
- Verified on two files: KANON one-chat 108 and 743, identical to the note values.
- `tsc --noEmit -p .` exit 0.

## 2. Shared-list re-measurement: harness built, run stopped, NO ranking produced

- Harness: `bench/z13/onechat-shared.ts` (calls the app's `measure()`, saves each output wire, one JSONL row per file). Driver: `bench/z13/run-shared.sh`. List: `bench/z11/eval-81.txt` (80 real files; same list as z11/z12).
- Keys: the 16 that emitted one-chat in z12 (`abacus amphora arithmos caesura chimera daedalus epistle icarus kanon lakonikos orthos procrustes prosopon stentor syntagma tabmin`).
- **Stopped, not finished.** Two keys (`abacus`, `amphora`) had started. Their rows are partial and were run under load, so they are **not used** and are not a ranking.
- **Blocker: the DAEDALUS family is not deterministic under load.** Evidence in code:
  - `daedalus.ts:192-226`: the second arm runs only if `Date.now() <= deadline`, where `budgetMs = min(20000, 1200 + 1.1·len)`.
  - `ariadne.ts:739, 749, 815-820, 901, 1149-1290`: search loops (`levels`, Lagrangian pricing, `greedyAdd`, `reparse`, `localSearch`) are gated by `Date.now() < deadline`. `sibyl.ts:282-335` and `ariadne.ts:1342-1403` use the same pattern.
  - `chiron.ts:1082-1085`: deterministic work units (KAIROS) exist only when `workUnits` is passed. The default CHIRON path (used by the `chimera`, `abacus`, `procrustes` wrappers, etc.) is wall-clock.
  - Repo evidence of the same effect: `bench/z11-report-2026-10-11.md` notes the same input giving 1664 in one run and 1613 in another (aapl).
- **Consequence.** Any ranking taken on a loaded machine is partly a measurement of CPU load. A fair shared-list ranking needs a deterministic mode (work units in ARIADNE/SIBYL/DAEDALUS, the existing KAIROS mechanism extended) or a sequential unloaded run. Neither is done. I did not publish a ranking.
- Timing: the 16 keys average 9–12 s per file (max ~100 s). A full shared run is about 2 h on this machine with two workers.

Also unverified: the faithfulness of the Block→TM2 translation (`RunsInPolyTime.certificate`, `Turing.TM2ComputableInPolyTime`), which is where a bit-level claim can hide. Next verifiable step: on a machine with Lean + the pinned Mathlib, run `lake build OAI.Computability.Superstring.Main` and `#print axioms OAI.Superstring.main` and check it lists only the three permitted axioms.

Literature context (from the web search, verified by reading the pages):
- The best published SCS approximation ratio is 2.466 [2](https://arxiv.org/html/2609.27921). The Greedy 2-approximation conjecture is still open [3](https://arxiv.org/abs/2407.20422).

## 6. Negative space (result shapes that look like wins and are not)

1. **Shorter contract by deleting "print only the result".** Saves ~5 tokens, but the decoder may echo its own reasoning. Needs a blind decode test, which I did not run. Rejected.
2. **Make the one-chat number from the registry note.** Notes are truncated and miss identity/wire-only cases. Fixed in §1.
3. **Shared-list ranking from the z12 sweep.** The one-chat keys cover different file subsets; the only common file is a 274-token file, where ratio = 1.000. Meaningless. Rejected.
4. **DAEDALUS "time budget" as a compression lever.** The budget only gates arms and search; it does not add compression. Making it deterministic changes reproducibility, not size.
5. **LTSC-style meta-token dictionary (arXiv 2506.00307).** Same mechanism class as CHIRON/DAEDALUS (dictionary substitution in the prompt). Its reported gains rely on fine-tuning the reader. Not applicable to a fixed chat reader. Not new here.
6. **Dictionary-encoded prompts (arXiv 2604.13066).** Already cited in the repo. Same class as the grammar arms.
