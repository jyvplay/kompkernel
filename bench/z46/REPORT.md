## A. Formal model (unchanged from Z45, restated)

A codec is a pair `(E, P)`; `E(text) → wire`, `P(wire) → prompt` (the one chat message the reader sees,
decoder contract inlined). Cost `M = tokens_o200k(P(E(text)))`. Admissible iff the reader can produce
`text` byte-exactly from `P(E(text))` alone, with no second message, system prompt or tool.
The frontier is DAEDALUS (`daedalusEncode`, default arms) composed with ANAGNORISIS where canon is
recognised. "Pareto-superior" means: on every file `M_new ≤ M_frontier` (guarded), and on some real
lane `M_new < M_frontier` by more than noise — DAEDALUS is deterministic under `OMEGA_DET=1`, so noise
is zero and any negative Δ is real.

## B. The position bound — why most of the 228 lanes in this repository tie DAEDALUS

The question "can we surpass DAEDALUS?" has a sharper form once one writes down what a dictionary
cannot do. DAEDALUS turns any REPEATED token sequence into one glyph per occurrence (plus one
definition). What it cannot do is go below **one wire token per position whose content is not a
copy of earlier material**. `bench/z46/floor.ts` measures that bound as the LZ77 phrase count of the
o200k token sequence (greedy longest earlier match, minimum match 2): literal phrases are single
tokens, copy phrases need at least one reference token.

| file | raw | LZ77 phrases | of which copies | DAEDALUS M | M / phrases |
|---|---:|---:|---:|---:|---:|
| gh-prose | 1934 | 1607 | 170 | 1782 | 1.11 |
| kb-article | 656 | 595 | 56 | 651 | 1.09 |
| llm-answer | 733 | 613 | 77 | 707 | 1.15 |
| readme | 843 | 571 | 81 | 688 | 1.20 |
| email-thread | 629 | 440 | 61 | 525 | 1.19 |
| license | 1166 | 838 | 158 | 968 | 1.16 |
| code-ts | 1422 | 803 | 263 | 1028 | 1.28 |
| gh-api.json | 2519 | 893 | 241 | 1153 | 1.29 |
| dpkg-l | 8975 | 3540 | 1430 | 4572 | 1.29 |
| ls-usr-bin | 17146 | 2821 | 1509 | 3746 | 1.33 |

(full table: `bench/z46/receipts/copy-floor.tsv`). On prose DAEDALUS's M is 1.09–1.20 × the phrase
count, and that factor contains the ~40-token contract and one definition per rule — i.e. the copy
mechanism is within a few percent of its own floor; LZ77 pointers (≥ 2 tokens per copy) would do
WORSE than the glyph dictionary on every prose file. This is why the dictionary has been the frontier
through ~200 lanes: layout regeneration (GRAMMA, indentation), quote prefixes (ECHO), closing tags,
list markers, alignment padding all remove tokens the dictionary already had at one per position —
they tie. The two ways below the bound are:

1. **import knowledge** — the position's content is not in the message at all (ANAGNORISIS, Z45);
2. **import a function** — the position's content is a known deterministic function of other
   positions, so it is sent zero times and recomputed.

Z46 ships (2). Everything in this repository that "computes" (EIDOS/AION/MNEMOSYNE/NYX deltas and
column programs, HELIX progressions) induces its function per message from template-aligned
families; the function here is a **published convention** the reader already knows, so there is no
family detection, no induced program, and the contract is one sentence.

## C. What is new: ENTHYMEME (ἐνθύμημα — the syllogism whose premise the listener supplies)

Two entailments with everyday mass were found, measured, and shipped; three were measured and
rejected (§D).

**Rule 1 — JVM stack frames.** `at pkg.Outer$Inner.method(Outer.java:123)`. The source file is not a
copy of anything in the line (`Outer.java` vs `pkg.Outer$Inner`), yet it is fixed: Java requires a
public top-level class to live in `<SimpleName>.java` and `StackTraceElement.toString()` prints that
file next to the class ([JDK 21 javadoc](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/StackTraceElement.html):
"`com.foo.loader/foo@9.0/com.foo.Main.run(Main.java:101)`"). Across 580 frames in ten real GitHub
issues the equality held in 580 (`bench/z46/receipts/trace-probe.log`). The wire writes `(:123)`;
the rule line reads

> `∴ Stack frames: "at C.m(:N)" = "at C.m(S.java:N)", S = C after its last ".", cut at the first "$".`

(34 tokens). Kotlin/Scala/Groovy frames, `Unknown Source`, `Native Method`, `<generated>` and any
frame whose file is not the class's are left literal; the encoder checks each frame.

**Rule 2 — Markdown heading links.** `[Getting Started](#getting-started)`. GitHub derives the
fragment from the heading text — lower-case, spaces to `-`, other whitespace/punctuation removed,
markup removed ([GitHub Docs, "Section links"](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax);
implementation `Flet/github-slugger` @ `3461c43`: `value.toLowerCase().replace(regex,'').replace(/ /g,'-')`
with `regex` = all punctuation/symbol/control/format/separator classes except `-`, `_` and space).
A table of contents therefore states every heading twice in two spellings the dictionary cannot
share. The wire writes `[Getting Started](#)`; the rule line reads

> `∴ Links: "[t](#)" = "[t](#s)", s = t lowercased, keeping only letters, digits, spaces, "-" and "_", then spaces → "-".`

(40 tokens). Duplicate-heading anchors (`#faq-1`), custom anchors and anything whose computed slug
differs from the written anchor stay literal.

**Composition.** text → rules (each verified round-trip on the raw text, declined if the elided form
already occurs) → DAEDALUS → wire = rule line + DAEDALUS wire; prompt = rule line + DAEDALUS prompt.
The reader expands the dictionary, then restores the elided fields. A rule fires only when its
predicted saving exceeds its sentence; the plain DAEDALUS arm is computed as a guard when the
predicted saving is below 60 tokens and the smaller message is emitted (this is a guard on one
composition, not a tournament over codecs; clear wins take the single-arm path).

## G. Native decodability — the check, as performed

`bench/z46/self-test.txt` is a real 26-frame Gradle trace (from cms-boot #3) under a one-line exception;
`bench/z46/self-test.prompt.txt` is its shipped prompt (M = 287 vs 667 raw). I decoded it in-context:
the DAEDALUS header defines, e.g., `қ = "        at org.gradle"`, `н = ")\r\n" + қ`,
`ь = ".api.internal.tasks.execution"`, `а = н + ь`, `ү = "Executer.execute"`, `е = ү + "(:"`,
`в = "Task" + е`; the body line `қь.ExecuteActionsTaskүActions(:110а.ExecuteActionsв77…` expands to
`        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter.executeActions(:110)` then
`        at org.gradle.api.internal.tasks.execution.ExecuteActionsTaskExecuter.execute(:77)` …; the
`∴` rule then gives `(ExecuteActionsTaskExecuter.java:110)`, and for
`EventFiringTaskExecuter$1.run(:51)` → S = `EventFiringTaskExecuter$1` cut at `$` →
`(EventFiringTaskExecuter.java:51)`, for `DefaultTaskPlanExecutor$TaskExecutorWorker$1.execute(:136)` →
`(DefaultTaskPlanExecutor.java:136)`. All three match the original file byte for byte. The slug rule
is a three-step string edit (lower-case, delete, replace) with no counting — the same class of
operation as the frame rule. Neither rule needs a catalogue, arithmetic, or width counting, which is
the property the Z45 review demanded of anything claimed natively decodable.

Second, mechanical check: `bench/enthymeme_decode.py` — a CPython reader written from the two rule
sentences (plus the existing `chiron_decode.py` for the DAEDALUS layer), not from `enthymeme.ts` —
reproduced the original bytes of all 20 emitted wires (10 traces, 6 READMEs, 4 shipped-lane files;
`receipts/xcheck-compare.txt`), including the 864 elided file names / anchors.

## I. Repair

- Two rule sentences were shortened from 46/47 to 34/40 tokens after counting (`bench/z46/clause-tok.ts`); the shorter frame sentence also removed the `"/"` clause, and `frameSourceName` was aligned to it so encoder and reader compute the same function.
- The frames estimate was recalibrated from the probe (`est = distinct-file tokens − distinct + repeats/2`), which predicts the measured Δ within ±25 tokens on 9 of 10 files; the exception (a trace that is itself repeated) is caught by the guard, not the estimate.
- Adversary cases drove two safety refusals: the rule declines when the payload already contains the elided form (`(:N)` frame or `](#)` link), and when the payload starts with the rule mark.

## J. Stopping

Stopped because (a) the copy-floor measurement shows the frontier is within ~10 % of the bound on
prose, so further in-message mechanisms cannot be large; (b) the two entailments with everyday mass
are shipped with receipts and the next candidates measured negative; (c) the remaining large lever
(config/scaffold canon) is catalogue-tier only and therefore not natively decodable. Future work
that would NOT be a new mechanism: Kotlin `.kt` frames, Android logcat prefixes, `-N` duplicate slugs
when the earlier heading is in view.

## K. The standing questions, answered from this turn's measurements

**Can we surpass DAEDALUS?** Not with copying: on prose it sits 9–20 % above the LZ77 phrase count,
and that margin is mostly its contract and rule definitions (§B). It can be surpassed only by
mechanisms that send a position zero times: knowledge (ANAGNORISIS, −82 % on recognised licences)
and functions (ENTHYMEME, −5…−10 % on whole trace/README documents, 15–30 % on the affected
regions). Both compose with it rather than replace it.

**What have we missed this whole time?** That the dictionary's floor is a *position* count, so the
~200 in-message lanes that regenerate layout, prefixes, padding or deltas were always going to tie
on real data — their savings were being counted before the dictionary had its turn. The misses that
remain are entailments: fields that look unique to a dictionary but are functions of their line.
Everyday pastes are full of them in two places (JVM traces, READMEs with tables of contents); the
others we looked for (PHP, .NET, same-URL links) are not entailed or not frequent, measured.

**Rosetta's "known form" broadened to random/hybrid prose?** Rosetta matched whole fixtures. The
honest broadening is the pair shipped in Z45/Z46: known *texts* (public canon, byte-exact modulo
layout) and known *functions* (public conventions). For random prose neither exists — there is no
form to know — and §B shows the copy floor is already met, so random prose stays at the dictionary
(15–20 %). For hybrid prose the structured literals (dates, IDs, versions) have known *shapes*, but a
shape is not a value: it cannot make the position disappear, only re-chunk it (SYNIZESIS, 0.6 % on
the prose holdout). The answer is therefore: broadenable exactly as far as canon and conventions
reach, and no further.
