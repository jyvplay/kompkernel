# X38 — OURA (οὐρά, "tail")

**Claim to be judged:** the constant-width hypothesis behind every numeric shape in this stack is
strictly stronger than the data requires. Relax it to *constant tail*, pay for the relaxation by
reading from the right, and a family of ordinary numbers that no shape in the stack can currently
see becomes compressible.

**Result:** the mechanism is built, gated and shipped. It is **byte-exact and non-regressing on
all seventeen lanes and it fires on none of them.** The constant-width hypothesis turns out to be
almost exactly as strong as the data permits. That negative result is the finding, and §E proves
it three separate ways.

### B1. Nesting the glossary — refuted

A straight-line program should let one rule's expansion reference another's, turning a long
glossary entry into a short one. `bench/x38/slp.ts` rewrites each entry using only entries that
precede it in the tape (so the result stays single-pass decodable), and re-tokenizes the exact
glossary:

```

find-listing.txt  glossLit=167  glossSLP=188  +21
kb-article.txt    glossLit= 56  glossSLP= 59   +3

npm-ls.txt        glossLit=310  glossSLP=328  +18
aapl-2014.csv     glossLit=174  glossSLP=191  +17
email-thread.txt  glossLit=123  glossSLP=151  +28
bibliography.txt  glossLit=115  glossSLP=132  +17
page.html         glossLit=196  glossSLP=209  +13
vix-daily-1990    glossLit= 89  glossSLP=101  +12
```

**Worse on ten of ten.** A glyph reference costs one token no matter what it names, and it also
breaks the merge between the replaced substring and its neighbours. `node_modules/` is three
tokens as literal text and one token as a glyph, but splicing a glyph in the middle of
`node_modules/@babel/core/lib/index.js` destroys the merges on both sides of the hole. This
independently corroborates SYNTOMOS's de-nesting arm, which was right for a reason nobody had
written down.

### B2. Pruning the rule set — refuted, and it is a local optimum

`bench/x38/prune.ts` reconstructs the wire as a straight-line program, computes each rule's full
expansion, and then greedily removes whichever rule most lowers the *measured* total, repeating
until no single removal helps. The recomputation is exact — it reproduces the shipped message
token for token before touching anything:

```
npm-ls.txt   baseline=901  recomputed=901  rules=82 -> 82  afterPrune=901  PRUNE_GAIN=0  removed=0
```

**The greedy rule set is already a local optimum under removal.** (The first version of this
probe reported a bogus −2479; it expanded every glyph in the body and was therefore measuring
"contract + glossary + original text". The recomputation check `recomputed == baseline` is now
the gate that catches that class of bug.)

### B3. Reordering the glossary — refuted in X37

`bench/x37/order.ts`, eight lanes, 857 s: ~0. Glyph script boundaries block every cross-entry
merge, so there is nothing for an ordering to harvest.

**Conclusion of §B: the glossary is big and it is already tight.** Three structurally distinct
attacks, all null.

## C. The mechanism OURA attacks

Every numeric shape in the stack — SYMPLOKE's four fixed ones (`date8`, `time6`, `dtT`, `dtSp`)
and the entire learned lattice — rests on one hypothesis: **the digit groups of a pattern have a
constant width vector.** `symplokeLearn` scans `\d+(sep\d+){k-1}` and rejects the shape the
moment two matches disagree on any width.

That rejection is load-bearing, not incidental. A collapse is recognised by the **length of its
digit run** — `digitRuns(out).filter(r => r.end - r.start === f.len)` — and a constant vector
makes the collapsed length a constant. So "a run of exactly eight digits is a date" is decidable
with no per-run marker at all.

The hypothesis is also false for a large and completely ordinary family of numbers. A semantic
version has three groups whose widths vary:

```
1.0.0      22.1.1      0.35.4      4.1.17
```

Two groups are one digit in some matches and not in others, every shape is rejected, and every
dot is paid for at full price. Same for fixed-precision decimals with a varying integer part
(`77.44539475`, `100.62342100`), times with fractional seconds, and any field where the trailing
precision is fixed by convention and only the head grows.

**What is constant in all of them is not the vector. It is the tail.**

### The construction

Relax the hypothesis from *constant vector* to *constant vector excluding the first group*, and
read from the right:

```
collapse:  1 . 0 . 0  ->  100
restore:   take the last 1 digit, then the last 1 digit before it,
           then everything that remains; join with '.'
           100 -> 1 | 0 | 0 -> 1.0.0
```

Exact and total: the suffix widths consume a fixed count from the right, so the head is whatever
survives, at any length. No carry, no base conversion, no arithmetic. The reader counts
characters off the right-hand end — the easiest direction to count in, because the suffix is
fixed.

### Three ways to pay for the relaxation

A constant-width collapse is identified by length. A tail-anchored one has a **variable**
collapsed length, so length alone no longer identifies it. OURA closes the gap three ways and
measures all three.

| mode | marker | cost/run | available when |
|---|---|---|---|
| `plain` | none, proved unambiguous | 0 | no digit run outside the spans reaches `minLen` |
| `lead` | the head's own separator survives | 0 | no *other* `<digits><sep><digits{sufSum}>` exists in the emitted text |
| `mark` | sentinel immediately before the run | 1 token | some sentinel is collision-free |

`lead` is the new one: keep the head **and its separator**, drop the rest, and the surviving
separator becomes the marker at zero cost. `1.0.0` → `1.00`.

### Guards for the layer below

OURA runs before SYMPLOKE's collapse, and a collapse here changes digit-run lengths there.

1. **Non-interference** — a candidate is only considered where the constant-width learner has
   already refused. If the head width is constant, SYMPLOKE owns the pattern and OURA keeps its
   hands off, so the two never claim the same span.
2. **Fixed-shape immunity** — no match may overlap `date8`, `time6`, `dtT`, `dtSp`, which are
   matched by literal regex and would otherwise be cut in half.
3. **Soundness before measurement** — `ouraUndo(rewritten) === text` must hold on the rewrite
   alone, before the expensive stack is ever run.

## E. Why it does not fire — three measured refutations

### E1. `mark` — the sentinel cancels the gain, and the dictionary was there first

A `k=2` shape removes one separator, so a one-token sentinel exactly cancels it. A `k=3` shape
removes two and nets one. npm-ls carries 45 three-group version strings, so `mark` should net
about 45 tokens.

It measures as **no improvement at all**. Two reasons, in order of size:

* Collapsing `1.0.0` to `~100` **destroys the redundancy the dictionary was already harvesting**
  from version-shaped text. The dictionary had got there first; OURA and the dictionary want the
  same characters and cannot both have them.
* The clause is not free. `bench/x38/cl3.ts` prices the wordings: the first-draft clause was
  **22 tokens**, the cheapest measured equivalent is **15** (`~N = N with . before its last 1,1
  digits. Drop ~.`). OURA now scores every wording against the exact contract it produces and
  takes the minimum — the same junction-pricing lesson EUTELEIA taught for the run-length clause
  — but 15 is still 15.

### E2. `plain` — blocked by the soundness proof on every lane that has a shape

`plain` is available only when no digit run outside the spans reaches `minLen`.

* **aapl-2014.csv**: the shape is `suf=[7]`, so `minLen=8`. The volume column contains
  `58671200` — eight digits. Blocked.
* **npm-ls.txt**: `minLen=3`; bare sizes like `4096` and `100` exist. Blocked.
* Every other lane with a shape, same story.

### E3. `lead` — blocked by ordinary two-decimal numbers, and the unit test proves it

`lead` pays nothing, so if it were sound it would win outright. It is not sound. The scan for
`<digits><sep><digits{sufSum}>` on the `lead`-rewritten npm-ls text finds **132** occurrences
against 45 real spans: **87 strays**. They are ordinary two-decimal numbers — `0.35`, `28.4` —
which are indistinguishable from a version tail.

A direct unit test (`/tmp/x38/lead.ts`) applies the `lead` rewrite and undo **without** the
guard:

```
npm-ls.txt   sep="." k=3 suf=[1,1] n=45   roundtrip=FAIL   matches=132   stray=87
pom.xml      sep="." k=3 suf=[1,1] n=5    roundtrip=FAIL   matches=13    stray=8
```

**The round trip genuinely fails**, which is exactly the failure `leadIsSound` exists to prevent.
Escaping the strays would cost 87 tokens to save 45.

### The conclusion

The constant-width hypothesis is not arbitrary. **Relaxing it costs a marker, and the marker is
what the saving was.** That is the result of this turn.

### F1. The alphanumeric swap, in detail

`bench/x38/swap.ts` measures a **bijective** relabelling of the alphanumerics — digit *i* ↔
letter *i* for ten chosen letters. Because it is an involution, no per-run marker is needed: the
reader applies the inverse permutation to the whole text, and the contract is one sentence
(`0123456789 = ETAOINSRHL.` measures **11 tokens**).

On raw text the gains are large where the document has no letters to damage:

```
aapl-2014.csv       lc-freq -345   vix-daily-1990  lc-freq -334
openstack-loghub    uc-freq -321   git-numstat     uc-freq -190
ls-full-iso.txt     uc-freq -107
```

and catastrophically positive (i.e. bad) on prose, where swapping `e` for `0` shreds every word.

Through the full stack it reverses:

```
openstack-loghub-26.log   stack=898  swapStack=1032   delta=+134
ls-full-iso.txt           stack=367  swapStack= 386   delta= +19
```

**Why:** the whole shape layer keys on the digit character class. `symplokeLearn` scans `\d+`,
the four fixed shapes are literal `\d{4}-\d{2}-\d{2}` and friends, and PYKNOSIS re-spells
`[0-9a-f]`. Relabel the digits and all three go blind. On openstack the shape and hex machinery
was worth more than 321 tokens, so the swap loses 455.

The general lesson, which is the most transferable thing in this document: **a pre-transform that
changes character classes is not free, because the layers above it are tuned to the classes they
were written against.** Any future pre-transform must either preserve the classes or be applied
where the machinery above it is class-agnostic.
